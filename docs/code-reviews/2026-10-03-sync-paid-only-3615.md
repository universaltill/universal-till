# Code review — paid-only cloud sync (ut-docs#3615, ADR-0148)

Date: 2026-10-03 / 2026-10-04 · Built by: Opus 5.5 · Reviewed by: Fable 5.1 (two passes)

## What shipped

A till that is not registered + claimed + on a paid plan makes no periodic cloud
check-in (ADR-0148, amending ADR-0117 §3/§5).

- `entitlement.SyncAllowed`: paid plan, active or trialing, no grace period.
- `cloudsync/sync_gate.go`: the sync loop skips its tick unless sync is allowed
  or an operator window is open. A window opens on a human action (Register
  now, claim, the new "Check for a paid plan" button, a manager's TSE retry)
  and allows check-ins for 2 minutes (15 for a claim code).
- `POST /api/enrol/check-plan` (manager-elevated, audited): opens a window and
  kicks one check-in.
- Settings registration card: a "cloud sync is off" notice and the check-plan
  button on an unpaid registered main till. The fleet list fetch is skipped
  while sync is off.
- 4 new keys in en/ar/fa/tr; help `claim.md` and `multitill.md` in all 5 locales.
- A replica receives the store's entitlement relayed from the main till over
  the LAN vouch (exempt from the gate); a newer confirmation wins.

## Findings

First pass (commit e7940f9a2), all fixed in ad29842bc, each test-first:

| # | Severity | Finding | Fix |
|---|---|---|---|
| 1 | blocker | `applyVouchRedeem` skipped the relayed entitlement when a replica redeemed its own credential, so its cache stayed empty and sync stayed gated forever | short-circuit removed; newer-confirmation-wins kept (`TestReplicaRedeemingOwnCredentialStillGetsRelayedEntitlement`) |
| 2 | major | `cloudsync.Start` set `kick=nil` after an error, so an operator's kick was dropped during backoff / lock-out | kick stays live; ends the wait only inside an operator window (`TestStartKickDuringBackoffChecksInWhileOperatorWindowOpen`) |
| 3 | minor | TSE background retry (`tseSystemActor`) opened an operator window | only a human actor opens one (`TestTSEKickoffOpensOperatorWindowOnlyForAnOperator`) |
| 4 | minor | check-plan on an unregistered / via-main till showed "Checking…" | refuses with `not_registered` / `registered_via_main`, no window, no audit (`TestEnrolCheckPlan_UnregisteredOrViaMainSaysNotRegistered`) |
| 5 | minor | Settings fetched the cloud fleet list on an unpaid till | wrapped in `{{ if not .cloudSyncOff }}` (extended `TestSettingsRegistrationCard_CloudSyncOffNotice`) |
| 6 | nit | tr/fa button wording | "Ücretli plan var mı diye kontrol et" / "بررسی وجود طرح پولی" |
| — | major (accepted, owner decision) | alerts digest, revocations feed and healthz still call out on an unpaid till | listed in ADR-0148 §6; tracked on ut-docs#3625 |

Second pass (ad29842bc): no blockers. Accepted:
- minor, pre-existing: the boot loop in `internal/enroll/enroll.go` retries device
  registration regardless of plan (bounded, stops on success) → added to #3625.
- minor, pre-existing: the UI's "registered" predicate (`CurrentStatus`) and the
  sync/check-plan predicate (`Effective(cfg)`) differ for an env-pinned till
  without a client id; the POST is elevation-gated and such a till already
  ticks today → follow-up card.
- nits: Register-now kicks on a via-main replica (harmless, no call);
  replica newer-wins compares two clocks (self-corrects within a tick).

## Verified beyond unit tests

- TDD re-verified by the reviewer for fixes 1–4: product code reverted → the
  named test fails with the claimed error → restored → passes.
- `go build`, `go vet`, `go test -race` on cloudsync, enroll, entitlement and
  pages (60m timeout): green. Full `go test ./...`: 79 packages ok (one `mobile`

  ~2 min; lapse to unpaid → sync stops after the next check-in; unregistered →
  error span, no network call.

  360×780, light and dark, en / fa (RTL) / tr / de, and the paid state in en.
  Not looked at: German as translated (pack PR follows the core merge), ar,

- Playwright: all `settings-*` specs + 7 neighbouring specs, 86 passed. No e2e
  drives check-plan (the default e2e till has no cloud endpoint), so this is
  covered by the handler tests and the driven run only.
