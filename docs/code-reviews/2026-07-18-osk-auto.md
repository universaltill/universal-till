# Code review — OSK visibility (field: "still don't see the keyboard") (2026-07-18)

Branch `fix/osk-auto-detection`. Diagnosis first: Farshid's till has
`display.osk = auto`, and on his mac (fine pointer) auto hides the keyboard
BY DESIGN — a machine with a physical keyboard shouldn't grow a virtual one.
The wiring (osk.js load, data-osk, InitOSKMode, settings endpoint) verified
correct via live smoke. So: partly expectation (Settings → Display →
On-screen keyboard → **On** forces it anywhere), partly a REAL robustness
gap fixed here:

- `auto` now detects touch via `pointer: coarse` OR `any-pointer: coarse`
  OR `maxTouchPoints > 0` OR `ontouchstart` — kiosk chromium with a mouse
  plugged in reports a FINE primary pointer despite the touchscreen, which
  would have silently disabled the OSK on the Pi.
- Belt-and-braces: if a real `touchstart` ever fires while disabled, the
  OSK enables from that moment (a touch proves a touchscreen).
- `focusin` respects the enabled state (previously the early-return
  prevented later enablement).

Test: `TestOSKModeReachesThePage` — data-osk renders auto by default and
"on" after the settings POST (204 accepted). Suites + guards green.

Field answer for the mac: set the keyboard to **On** in Display settings;
auto is for touch tills.
