# Review: nav rail → ADR-0088 UI slot (ut-docs#1912)

- **Card**: universaltill/ut-docs#1912 — "Sale-screen rail is not an
  ADR-0088 UI slot"
- **Complexity**: hard (built by a Fable subagent, independently reviewed
  by Opus in an isolated worktree — different model from the implementer)
- **PR**: universaltill/universal-till#TBD (opened right after this record)

## What shipped

`web/ui/partials/nav.html`'s `.nav-primary` block (the app-wide left icon
rail — Sell/Menu/Inventory/Orders, rendered on every page) converts from
hardcoded `<a>` tags into a third `internal/uislot` registry slot
(`RailSlot`), generalizing the exact mechanism already used for the Menu
launcher and the `/items` section list (ut-docs#1911). A `layout` plugin
can now reorder or relabel the rail; `plugins/layout-salon` demonstrates
it (a pure reorder — Orders ahead of Inventory — introducing no new
locale key).

**ADR-0088 gained Decision J** (`adr/0088-declarative-ui-slot-registry.md`,
`ut-docs` commit `35b958b`, header fix in `9b8b489`): `/` (Sell) and
`/menu` (Menu) are protected — the rail's only two entries with no
equivalent tile anywhere in `CoreMenu`, so hiding or relabelling either is
a structural dead end, not merely an inconvenience. `/inventory` and
`/orders` stay unprotected (both independently reachable elsewhere).

Hide/icon/group stay refused for the **whole** rail slot (not just the
protected pair) — same deferral as the Items slot: no Settings →
Hidden-destinations restore surface exists yet for a non-Menu slot, and
"accepted then silently ignored" is exactly the failure mode this
registry exists to prevent.

## An incident from this cycle, disclosed for the record

Mid-Tester-verification, an orchestrator mistake (`git checkout --
internal/uislot/slot.go`, intended to undo a temporary local edit)
discarded Dev's actual uncommitted changes to that one file, since the
file wasn't staged at that moment and `git checkout --` on an unstaged
file restores from `HEAD`, not "a moment ago." Recovered by hand: the
file's own test suite (`internal/uislot/slot_test.go`, untouched by the
mistake) is a complete, precise specification of the required API, so the
rail additions were rewritten against that spec, mirroring the
already-established Items-slot pattern in the same file. Re-verified
against the full test suite, the zero-alloc benchmark, and a full
`go build`/`go test ./...` afterward — all green, and the reconstructed
file's diff size matches the original shape. No other file was affected.
A second near-miss during review-fix triage (the same command, this time
on a *staged* copy, which `git checkout --` correctly restored from the
index) is why this note calls out the distinction explicitly: `git
checkout -- <path>` restores from the index when the path is staged, and
from `HEAD` when it isn't — worth remembering before reaching for it as a
quick "undo" on any file with real uncommitted work.
