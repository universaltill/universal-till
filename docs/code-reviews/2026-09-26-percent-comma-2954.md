# Review — percent inputs accept a decimal comma (ut-docs#2954)

Date: 2026-09-26 · Branch: `fix/2954-percent-comma` · Author lane: lane:cloud-24 (Opus 5.5) · Reviewer: independent Fable subagent

## What shipped

- `httpx.ParsePercentBP` — a percent with `.` or `,` as the decimal separator and at most two fraction digits, read straight into basis points with ParseMoneyMajor's integer grammar. No `strconv.ParseFloat`, so `1e3`, `NaN`, `Inf` and `0x10` are refused and 8.5% is exactly 850 bp.
- `httpx.PercentPatternLocal` / `PercentPatternLocalAttr` and the template func `{{ percentpatternlocal }}`: pattern `[0-9]+([.,][0-9]{1,2})?` plus `data-money-local="percent"`.
- Fields switched: promotions `value_percent` (×2), Settings payment-fee `percent`, Country settings `tax_rate_pct`, Tax codes `rate` and `takeawayRate`.
- Handlers switched: `parsePromotionForm` (still 0 < pct ≤ 100), `POST /api/settings/payments-fee` (empty still 0; a malformed percent is now refused with `✗ range` — it used to be stored as 0% because the ParseFloat error was ignored), `parsePercentAsBP` (country settings; empty still 0, ≤100% still enforced by the repo), `parsePercentToBP` (tax codes; still ≤100%, empty rate still refused).
- `app.js`: a `data-money-local="percent"` field takes its invalid message from `<body data-percent-invalid>` (always the "dot or a comma before the decimals" text), so a 0-decimal-currency shop doesn't tell the user a percent must be a whole number.
- Help topics (en/de/tr/fa/ar): promotions, tax codes, country settings; en payments (the only locale with the provider-fee bullet). Docs-shots manifest topic hashes + surface hash refreshed; no screenshot pixels change (the only template change is an attribute).
