# Review: F11 toggles the live window mode (ut-docs#3735)

- **Date:** 2026-11-11 · **Lane:** lane:cloud-54 · **Branch:** `feat/3735-f11-window-toggle`
- **Built by:** Sonnet (Dev phase, then two fix rounds) · **Reviewed by:** Opus 5.5, an independent subagent with fresh context

## What shipped

- `POST /api/settings/window-mode/toggle` (`internal/pages/window_toggle_api.go`) switches the live mode. normal or maximized goes to fullscreen, and fullscreen goes to normal.
  - **Kiosk:** a no-op that answers `reason: kiosk_locked`. Leaving kiosk stays behind the Exit-to-OS manager PIN.
  - **No shell:** with no attached exit-path shell it is a no-op that answers `reason: no_shell`.
  - **Not persisted:** the change is live only. `display.window_mode` is not written, so the configured mode applies again at the next launch, the same as Exit to OS (ADR-0064 Decision 2).
  - **Write path:** the write is `ShellChannel.CompareAndSetMode`, which reads and writes under the channel lock. A kiosk saved in Settings mid-toggle is therefore never overwritten.
  - **Audit:** each toggle writes a `window_mode_toggled` audit row.
- **Gate:** the caller needs the `settings` grant (no PIN elevation prompt from a keypress), a same-origin request, a loopback caller and an attached exit-path shell. Cashier and anonymous callers get 403. The demo build blocks the POST. The route is not auth-exempt.
- **Flag:** `<body data-window-toggle="1">` comes from `httpx.InitWindowToggle` (`internal/httpx/window_toggle.go`). It is rendered only under the same conditions and never on `/self-order*`.
- **Page script:** `web/public/window-toggle.js` intercepts only a plain F11 (no modifiers, no repeats, debounced) and only when the flag is present. In every other case the browser's own F11 is untouched.
  - **Message:** on `kiosk_locked` it shows a non-modal message in `#pos-alert` (new key `settings.display.f11_kiosk_locked` plus its metadata) and scrolls it into view (#5298 pattern).
- **Help:** item 11 of `web/help/en/display.md` describes F11. The docs-shots manifest is regenerated.

- **Reviewer check:** the reviewer disabled the kiosk guard, saw `TestWindowToggle_KioskIsNoOp` fail, restored the guard and saw it pass.

- **Browser:** the e2e spec `e2e/tests/f11-window-toggle-3735.spec.ts` passes 6/6 in Chromium. With no flag, F11 is not prevented and nothing is posted. Plain F11 posts once, and Shift/Ctrl+F11 do not. The kiosk message is not a `<dialog>`, and it is scrolled into view.
- **Screenshots:** the message at 1024x600 and 360px was checked. The status bar and nav rail stay reachable.
- **Gates:** gofmt, `go build ./...`, vet and golangci-lint are clean (0 issues). The pages, common, httpx and auth tests pass. The `ci.yml` build-job guards pass. shellcheck is not installed here, and no `scripts/ci` file changed.
