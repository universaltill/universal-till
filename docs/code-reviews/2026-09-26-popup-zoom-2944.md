- **Author lane:** `lane:cloud-54` (built on Opus 5.5)

  (`MODEL-ROUTING.md`, hard)

## What shipped

- `web/ui/layouts/base.html` (first script), the ONE popup motion:
  - **Opening.** The existing `HTMLDialogElement.prototype.showModal/show`
    wrapper (installed once) now does these steps in order:
    1. ends this dialog's own running shrink;
    2. `UT.finishZooms()`;
    3. runs the native method first and returns its value;
    4. unless `UT.motionOff()`, runs a FLIP zoom from `UT.takeOrigin()` to
       the dialog's box: uniform scale clamped .1–1 plus translation, from
       opacity .4, `--ut-zoom-small-ms`, `fill: 'none'`, `UT.trackZoom`.
       With no origin it grows from the bottom centre. The popup's own CSS
       transform (e.g. `.shrinkage-sheet`) is composed in.

    Everything after the native call is in try/catch.
  - **Closing.** A capture-phase `close` event listener (it covers
    `close()`, Escape, `form method=dialog` and `requestClose`) re-shows
    **the same element** with `data-ut-closing`, `inert` and `aria-hidden`
    at the box recorded while it was open (ResizeObserver plus remeasure).
    It then shrinks into the source, or the bottom centre, and restores
    the attributes. A timer backstop always cleans up. The native close is
    never delayed.
  - **Public API.** `UT.popupOpened(el)` / `UT.popupClosed(el)` for popups
    that are not a `<dialog>`; the bug-report panel is wired.
- `web/public/app.css`:
  - the `[data-ut-closing]` rule: fixed, logical inset and size,
    `pointer-events: none`, z-index above the rail and the OSK;
  - `display: none` backstops for Light and reduced motion;
  - `.ut-dialog-fx` and `ut-dialog-in` removed.
- `web/public/record-dialog.js`: its per-dialog open ease is removed.
- `web/ui/partials/modifier_picker.html`: the Add and Cancel close sites no
  longer empty the picker (review finding 1).
- Help: `web/help/{en,de,fa,ar,tr}/display.md` step 20 now describes the
  popup zoom; the docs-shots manifest is refreshed.
- Tests:
  - `internal/pages/popup_zoom_guard_test.go` (new) checks:
    - the wrapper is installed once;
    - `.animate(` appears only in the shared zooms, counted with comments
      stripped;
    - the wrapper order is finish → native → motion;
    - the close listener is capture phase and there is no `.close()`
      wrapper;
    - both entry points check `motionOff`;
    - the CSS rule and backstops exist;
    - no dialog is emptied at its close site;
    - passive zooms don't arm the re-dispatch;
    - `closeTarget` rules.
  - `transitions_test.go` and `effects_level_guard_test.go` updated.
  - `e2e/tests/popup-zoom-2944.spec.ts` (new, 9 tests) covers:
    - at Full: the popup grows from the tapped tile (centre within 1.5 px,
      scale = tile/popup);
    - closing by `close()`, by Escape, and by the picker's real Add and
      Cancel buttons shows `data-ut-closing` + inert with content, then
      cleans up;
    - reopening mid-shrink;
    - Balanced 200 ms;
    - Light: no animation and no re-show;
    - a mouse or touch tap during the opening zoom lands on the control;
    - a click during a closing shrink activates once;
    - the bug-report panel.
  - `in-panel-dialog-transitions-2338.spec.ts` was rewritten for the shared
    zoom.

## Findings

| # | Severity | Finding | Outcome |
|---|---|---|---|
| 1 | major | The modifier picker's Add/Cancel did `m.close(); m.innerHTML=''`. The `close` event is a queued task, so the shrink re-showed an **empty** card. Confirmed live on the main sell flow. | **Fixed**: removed the emptying at close (the #2525 opener gate and app.js's pre-GET empty already cover stale content; `sell-stale-tile-2525` passes). Added a `childElementCount` backstop in `popupClose`, a Go guard and an e2e case on the real buttons. |
| 2 | minor | `closeTarget` fell back to the stale tap-time rect when the source was connected but not rendered. | **Fixed**: uses the live rect only if the source is connected, rendered and on screen; otherwise the bottom centre. |
| 3 | minor | A tap during a *closing* shrink armed the §7 click re-dispatch, although the closing element takes no input. | **Fixed**: the closing shrink is tracked as passive; `finishZooms()` still finishes passive animations but reports only non-passive ones. Covered by an e2e case (one click, one request). |
| 4 | minor | The Go `.animate(` count also counted comments. | **Fixed**: `stripCodeComments` runs before counting, with its own test. |
| 5 | minor | The ResizeObserver tracks size, not position. | **Accepted**: every shipped popup is `position: fixed`, the box is remeasured on pointerdown/cancel/resize, and the draggable bug panel calls `popupClosed` before hiding. |
| 6 | minor | The self-order kiosk pages are standalone (no `base.html`) and get no popup motion; their partials use the same empty-at-close idiom. | **Deferred** to ut-docs#2972 (Backlog). |
| 7 | nit | An open dialog removed by a swap stays observed until the next pointerdown. | Accepted: bounded to one element, pruned on the next tap. |
| 8 | nit | The ADR says reopening "finish()es" the shrink; the code cancels it (visually identical). | Accepted; the queued-task note was added at `popupClose`. |

The reviewer verified live that native exception semantics are preserved:
`InvalidStateError` on a disconnected dialog or a double open, and
`TypeError` on a wrong receiver.

## After review — CI

- The first CI run on the PR failed `e2e`. That job runs the second
  Playwright suite, `tests/e2e`, which does not force reduced motion. Four
  tests in `tests/e2e/tests/bugreport_panel.spec.ts` measured or dragged
  the bug-report panel while it was still in its open zoom.
- Fix: a spec helper, `openPanel()`, now awaits the panel's animations,
  so the tests still pin its resting geometry. I reproduced the same 4
  failures locally before the fix; afterwards the full `tests/e2e` suite
  gives 21 passed and 4 skipped.
- Product note: a press made during the 300 ms open zoom finishes the zoom
  (§7), so a drag started at the panel's moving position doesn't grab it.
  That is the intended behaviour.

## Verdict

Safe to merge once CI is green.
