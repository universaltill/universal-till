## What shipped

The Menu launcher's per-tile emoji (`iconFor`, `internal/pages/menu_page.go`)
read differently per platform's colour-emoji font and, per the product
owner relaying the German pilot merchant comparing the till against SumUp's
app on the same tablet, "read as unfinished" — "like Windows 3.1"
(ut-docs#1830). This extends the drawn-icon system already introduced for
the nav rail (ut-docs#1423) and used once for a single tile (ut-docs#1720,
Bluetooth) to **every** core menu route:

- 15 new Lucide icon paths added to `railIcons`
  (`internal/httpx/icons.go`): palette, clock, book-open, chart-column,
  settings, map-pin, calculator, chef-hat, utensils-crossed, flag,
  monitor, clipboard-list, recycle, shopping-cart (plus the review-driven
  swap below).
- `iconSVGFor` (`internal/pages/menu_page.go`) now maps every core route
  reachable via `registerMenu`'s `add()` calls, including every
  manager-gated one. The old `iconFor` emoji map and `menuTile.Icon`
  field are deleted entirely, not just superseded.
- `web/ui/pages/menu.html`: tile rendering simplified to always use
  `.IconSVG`; the Pfand-refund tile (♻️) and the language-switcher label
  (🌐) converted to `{{ icon "recycle" }}` / `{{ icon "globe" }}`.
- `web/ui/pages/index.html`: the phone-width (`<=480px`) nav-shortcut row
  that duplicates `nav.html`'s rail (`.kiosk-actions`) converted its two
  emoji (🛒 New Sale, 📦 Inventory) the same way, with a new `.btn-ico`
  CSS class for an icon sitting inline with its own text (as opposed to
  `.menu-ico`'s fixed tile box).
- Tests updated (`internal/pages/menu_page_test.go`,
  `fiscal_device_page_test.go`) from emoji-glyph assertions to
  `data-icon="…"` assertions, plus a new denylist regression test.
- `make docs-shots`: `web/help/img/{en,fa,ar,tr}/menu.png` +
  `manifest.json` regenerated (only `menu.png` changed pixel-wise across
  all 26 topics × 4 locales — confirms the CSS/template changes don't
  leak into any other screenshotted page).

No new locale keys — this is a pure icon-rendering change, so
`lang-pack-drift`/the `ut-plugin-language-{de,es}` packs are unaffected.

## Findings and what was done about them

1. **`/tables` mapped to the wrong icon — Medium, fixed.** Lucide's
   `table` icon is a spreadsheet/data-grid glyph (grid of rows and
   columns); `/tables` is the dining-tables/floor-plan feature
   (`web/help/en/tables.md`: "every dining table with its name, area,
   seats and shape"). This is exactly the "technically drawn but reads
   wrong" failure ut-docs#1720 already fixed once for Bluetooth's 📶.
   **Fixed:** swapped to Lucide's `utensils-crossed` (crossed fork+knife),
   the icon this ecosystem's own competitor comparisons (SumUp, Toast)
   use for a restaurant tables/floor-plan surface. Not independently
   screenshot-visible (below the fixed 1024×600 capture fold on the menu
   grid, and `/tables`'s own topic screenshot is the floor-plan page
   itself, not the menu tile) — verified instead via the same
   render-and-inspect method as the route-coverage check above.
2. **Manual prose named the exact tile this diff changed — Medium,
   fixed.** `web/help/{en,de,ar,fa,tr}/bug-reporting.md` said "…via the
   🐞 Report an issue tile" — that tile's icon is precisely what this
   diff converted from emoji to SVG. **Fixed:** dropped the glyph
   reference in all 5 locale files, in the one line that actually
   describes the Menu tile (not the four other 🐞 references per locale
   describing the **nav rail**'s bug-report button, which was already
   converted to SVG back in ut-docs#1423/#346 and was already
   independently stale before this diff — out of scope here, see below).
3. **New test's name overpromised — Low, fixed.** `TestMenuPage_
   NoEmojiAnywhereOnThePage` is a fixed denylist of this page's own
   previously-used glyphs, not a full-page Unicode scan — the page also
   renders shared layout chrome (`web/ui/layouts/base.html`) with its own
   unrelated glyphs (📷 the bugreport screenshot button, ✦/⬆/✕ the
   self-update banner). **Fixed:** renamed to
   `TestMenuPage_NoRetiredTileEmoji`, tightened the doc comment to say so
   explicitly and point at the follow-up card below.
4. **Partial migration leaves some emoji on the same screen —
   Low, deliberately out of scope, filed.** `index.html`'s tender-screen
   quick-pay row still has 🛒/⚡, the AI-identify button still has 📷;
   `catalog_variants.html`'s image-upload label still has 📷;
   `bugreport_panel.html`'s screenshot button still has 📷. None of these
   are menu/nav markup — ut-docs#1845's own acceptance criteria scoped
   "no emoji left in menu/nav markup" specifically, and the requirement
   text explicitly said this card "does not depend on #1830 and should
   not wait for it," not that it must finish every emoji in the product
   in one pass. **Filed as ut-docs#1859**, with the exact file:line list
   and a warning that `e2e/tests/payment-overlay-duplicate-labels-1625.
   spec.ts` asserts on the 🛒 accessible name and will need updating
   whenever that follow-up lands. Confirmed the *current* diff does not
   break that spec (it runs at the desktop viewport, where
   `.phone-fallback-only` is hidden).
5. **Stale comments — Low, fixed.** `nav.html` still named the deleted
   `iconFor` map; `menu.html` still called the Pfand tile "the ♻️ tile
   above"; `index.html` described a "🛒/♻️" convention that no longer
   holds (♻️ is gone, 🛒 partially remains elsewhere in the same file —
   see finding 4). All three corrected to describe the current state.
6. **Inert CSS — Low, fixed.** `.btn-ico { vertical-align: -0.15em; }`
   never applied — every `.btn`/`a.btn` is already `display:inline-flex`,
   and a flex item ignores `vertical-align`. Removed; the flex `gap` on
   `.btn`/`.menu-lang-label` already supplies the spacing.
7. **Two pre-existing icon collisions, not a regression — Low,
   accepted, noted.** `/plugins` and the generic plugin-tile fallback
   both resolve to `puzzle` (visible side-by-side in the regenerated
   `menu.png` as "Plugins" next to "Help / FAQ"); `/` and `/fiscal-device`
   both resolve to `receipt`. Both mirror the *exact same* pairing the
   retired `iconFor` emoji map already had (🧩 was `/plugins`'s own
   glyph and visually close to no-icon anyway; 🧾 was already reused for
   both `/` and `/fiscal-device`) — not something this diff introduces.
   Left as-is; a deliberate follow-up to give `/plugins` its own distinct
   icon is real but separate scope.
8. **`/tills` carries an icon entry for a route with no tile — Low,
   pre-existing, noted.** `iconSVGFor["/tills"] = "monitor"` has no
   corresponding `add("/tills", …)` call anywhere in `registerMenu` (the
   page is reached via `sync_chip.html`/`settings.html`, not a menu
   tile) — carried over unchanged from the old `iconFor`, which had the
   same dead entry. Harmless (a map value read counts as "used" for
   `golangci-lint`'s `unused` check); left alone rather than risk
   removing something a near-future card might rely on.
9. **Lucide ISC-licence notice hygiene — Low, pre-existing, noted.**
   `internal/httpx/icons.go`'s own comment asserts "ISC licence, no
   attribution required in-UI" — true, but ISC does require the
   copyright/permission notice be retained in copies of the licensed
   work, and there is still no `internal/thirdparty/lucide/LICENSE`
   entry (the directory holds only `webview_go`/`mswebview2` notices
   today). Pre-existing since ut-docs#1423 first vendored Lucide paths,
   now covering 29 entries instead of 15. Not blocking; worth a small
   follow-up (`internal/thirdparty/lucide/LICENSE`) whenever someone's
   touching that area next — not filed as its own card given how small
   it is, noted here for whoever next edits `icons.go`.
