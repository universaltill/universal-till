# Duplicate-key check for web/locales/*.json (ut-docs#1872)

**Card:** universaltill/ut-docs#1872

## What shipped

`scripts/ci/guard-i18n.sh` gained a 9th check: every file matching
`web/locales/*.json` (en.json included) is read via a Python
`object_pairs_hook` closure that tracks a `seen` set over the raw key/value
pair list, so a top-level key defined twice in the same file is caught
before anything discards it — the existing checks 1/2/8, and this file's own
`keys()` helper, all parse with plain `json.load`, which silently keeps
only the LAST of a duplicated key. Real incident this responds to: two
lanes independently added the same five keys to a language pack's locale
file at different points in the file; git merged both non-conflicting
insertions cleanly, and every existing guard (this one included, pre-fix)
reported a clean pass against a file that actually had five keys defined
twice.

- `duplicate_keys(path)` + a `dup_hits` accumulation loop, added near the
  end of the embedded Python heredoc, before `if fail: sys.exit(1)` —
  follows the same accumulate-and-continue pattern as checks 1-8 rather
  than exiting early.
- Header comment (item 9) and the final success print string both
  extended to document/report it.
- New `scripts/ci/guard-i18n_dupkey_test.sh`: plants a disposable
  `web/locales/zz_guard_test.json` whose key set (after normal last-write-
  wins parsing) exactly matches en.json's — built from en.json's own first
  key duplicated in the raw text — so only check 9 can fire, not checks
  1/2/8. Registered as an explicit new step in `.github/workflows/ci.yml`'s
  `build` job (this repo's CI does not auto-discover `*_test.sh` files).

The companion fix in both `ut-plugin-language-{de,es}` (their own
`check-key-drift.sh` copies, ut-docs#312's known duplication) is in those
repos' own PRs, referenced from ut-docs#1872 directly — this PR is core-only.
