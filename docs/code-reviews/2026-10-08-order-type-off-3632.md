# Review: dine-in/takeaway "Off" mode (ut-docs#3632)

Date: 2026-10-08 · Branch: `feat/3632-order-type-off` · Lane: `lane:cloud-41`
Author model: Opus 5.5 · Reviewer: Fable (independent subagent, one round)

## What shipped

`sale.order_type_prompt` gains a fourth value, `off` ("this shop doesn't sell
food or drink to eat in": an off-licence, a barber, a retail shop). Before
this, the setting only chose *when* the cashier was asked (`top`,
`before_item`, `at_pay`), so every shop saw the dine-in/takeaway choice.

- **Setting:** `data.OrderTypePromptModeOff` is accepted by the settings POST
  (elevation summary and audit included), by the cloud door
  (`cloudsync_wire.go`, which fails closed on unknown values through the
  shared `validOrderTypePromptMode`), and by the LAN/startup path
  (`httpx.InitOrderTypePromptMode`, which no longer clamps `off` to `top`).
  `httpx.OrderTypeOff()` is the atomic reader.
- **Sale screen:** with Off there is no toggle above the basket and no
  intercept dialog. `app.js` short-circuits `showOrderTypePromptModal` too.
  `POST /api/pos/order-type` refuses takeaway with 409
  `{data:null,error:{code:"order_type_off"}}` (localized message).
- **Self-order kiosk:** under Off, `POST /api/self-order/order-type` clamps
  takeaway to `""`, the same shape as the table-bound clamp. The cart hides
  its toggle. This came from review finding 1.
- **Tax:** under Off, `pluginTaxRateAsker` sends `order_type: "none"` for
  `""` lines. `""` keeps meaning dine-in for every existing shop. The cache
  keys on the mapped value, so `""` and `"none"` never share an answer.
  `ut-plugin-tax-de` already treats any non-takeaway value as "no opinion".
  `ut-plugin-tax-uk` still applies its eat-in uplift to anything but
  takeaway, so it needs ut-docs#3902; until then an Off sale is taxed exactly
  like today's default dine-in sale, so there is no regression.
- **EOD:** the "by order type" section (Reports tab and printed Z) is hidden
  under Off when no row is takeaway.
- **Setup wizard:** shop type `retail` or `service` sets Off, but only when
  the key is unset. Café, hospitality, market stall and other stay as before.
- **i18n/help:** `settings.order_type_prompt.mode_off` and
  `pos.error.order_type_off` are translated in en/tr/fa/ar. The language
  packs de/es/pt get follow-up PRs in the same cycle. The `sell` help topic
  gets a bold-led "Off" paragraph in en/de/tr/fa/ar, with the help-drift
  baseline counts bumped and their reasons annotated. The README is updated.

## Findings

| # | Severity | Finding | Outcome |
|---|---|---|---|
| 1 | major | The self-order kiosk still showed the toggle and accepted takeaway under Off. | 2 | minor | EOD hiding reads the live mode, not the mode at report time. Switching to Off hides old dine-in-only "by order type" rows. | **Accepted:** display-only, and the archived JSON is intact. A report with any takeaway row still shows the section. |
| 3 | minor | A takeaway basket held or parked *before* the switch to Off, recalled after it, has no toggle to convert it. | **Accepted:** a switchover edge case. The sale keeps the takeaway treatment it was rung with. `POST /api/pos/order-type` with `""` still converts it. |
| 4 | nit | "Dine in" labels for `""` lines remain on the open-orders list, the kitchen ticket's mixed case and the printed Z when a takeaway row forces the section. | **Accepted:** these only appear when the data really is mixed. |
| 5 | nit | Help-drift baseline reasons were not annotated. | **Fixed.** |
| 6 | nit | The wizard's settings write is unaudited. | **Accepted:** consistent with every other wizard write. Annotated `settings-write:allow`. |

The reviewer checked and found no issue with: tax-ask cache keying, the

## Verification

- **TDD:** the reviewer re-verified it for `TestAskTaxRateBP_OrderTypeOffSendsNone`
  and `TestOrderTypeAPI_OffRefusesTakeaway` by neutralising each fix
  condition: both failed for the right reason, then passed once restored.
  The Dev step saw every other new test fail first.
- **Gate:** `gofmt`, `go build`, `go vet` and the full `go test ./...` pass.
  Every guard in `ci.yml`'s build job passes locally except
  `guard-deadcode-baseline` (the local Go is 1.26 and the module needs 1.27)
  and `guard-shellcheck-version` (no shellcheck installed); CI runs both.
- **e2e:** the new `order-type-off-3632.spec.ts` (2 tests) and the existing
  `order-type-prompt-placement-2282.spec.ts` (11 tests) pass against a real
  till.
- **Visual:** I looked at the sale screen and Settings → Dine-in/takeaway
  prompt under Off at 1024×600 and 360×800, in en and fa (RTL):
  - The basket has no toggle and nothing overlaps.
  - The RTL select fits.
  - At 360px the closed native select clips the long option, as the
    existing "At the top of the basket (default)" option already does; the
    opened picker shows it in full.

  Not looked at: dark theme, the printed Z on paper, the kiosk cart under
  Off (covered by the handler test only).
- **docs-shots:** regenerated. Only `web/help/img/manifest.json` changed;
  no PNG moved.

## Verdict

Safe to merge after the finding-1 fix, with the full gate green on the final
tree.
