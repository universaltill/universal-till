# Review: OSK numeric pad decimal key follows the till language (ut-docs#2971)

Date: 2026-10-19 · Branch `fix/2971-osk-decimal-key` · Lane `lane:cloud-41`
Author: Opus 5.5 · Independent reviewer: Fable (different model)

## What shipped

- `web/public/osk.js`: `render()` swaps the `.` key on the `num` and
  `numSigned` layers for `decimalKey()`. It returns `,` only when the
  focused field carries `data-money-local` (emitted by
  `httpx.MoneyPatternLocalAttr` / `PercentPatternLocalAttr`), is not
  `type="number"`, and `<body data-number-decimal>` is `,`. Every other
  numeric field keeps `.`, because its reader may be dot-only.
- `web/help/{en,de,tr,fa,ar}/display.md` step 5: one sentence on the
  decimal key. `web/help/img/manifest.json` was regenerated by
  `make docs-shots`, and the PNGs came out byte-identical.
- New e2e: `e2e/tests/osk-decimal-key-locale-2971.spec.ts`. On de, the
  pad types `,` into `#item-price` and the server stores 375. On en, it
  types `.`. A dot-only numeric field on de keeps `.`. All three tests use
  real OSK taps and read the stored price back from the server.

## TDD

With the `osk.js` change stashed, the de test fails: the `,` key is not
found. The en test and the dot-only test pass without the fix, which is
expected because they are regression guards. With the fix restored, all 3
pass. The neighbouring OSK and money specs also pass (24 tests):
`osk-central-guard`, `osk-caps-lock-latch-1835`,
`money-prefill-locale-2818` and `osk-signed-minus-key-1276`.
