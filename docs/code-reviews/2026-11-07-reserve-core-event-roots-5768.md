# Review: reserve the missing core event roots (ut-docs#5768)

**What shipped:** `coreEventRoots` in `internal/plugins/manifest_abi3.go` gains `agent`, `charge`, `inventory`, `report`, `shift` and `till`, which makes 38 roots. Core already publishes or asks events under the first five: `agent.action.result`, `charge.policy.ask`, and the `inventory.adjusted`, `report.generated` and `shift.opened/closed` eventModes keys. `till` is reserved ahead of #5758 (`till.drawer.no_sale`). Before this change a plugin with id `shift` could use `event_publish` to send `shift.opened`, because the event fell inside its own `<id>.` namespace. Now the id is refused at parse, at install and at load (`validatePluginID`), and the event is refused at publish and in schedules. The doc comment names the new guard and the ut-cloud mirror. A new `core_event_roots_test.go` (`TestCoreEventsHaveReservedRoots`) parses `internal/plugins` and `internal/pages` with go/ast. It resolves the event-name argument of every `Publish`/`PublishAuthorize`/`Ask`/`AskFrom` call (3 args) and every `PublishAuthorizeWithID`/`AskPlugin` call (4 args). The argument can be a literal, a package const, a function-local const, a `plugins.X` const or a const chain. The test also reads every `eventModes["…"]` key, and fails when a dotted name's root is not reserved. A self-check fails the test if the scan stops finding `sale.completed`, `shift.opened`, `charge.policy.ask`, `agent.action.result`, `fiscal.sign.ask` or `export.requested.ask`. Per-root cases were added to the parse, schedule, `validatePluginID` and `event_publish` tables. The ut-cloud mirror (`pkg/manifest`, `TestCoreEventRootsMirrorPOS`) ships in a companion PR. No ADR is needed: ADR-0121 §2 (2026-10-03 amendment) already sets the rule and leaves the list open with "…". No help, UI, i18n or migration change.

Sonnet built it. An independent Opus 5.5 subagent reviewed it in separate worktrees.

## Findings
1. **Low, fixed.** The four rows added to `TestEventPublishRefusesOutsideOwnNamespace` (`shift.opened`, `till.drawer.no_sale`, `agent.action.result`, `charge.policy.ask`) pass without the fix. The test plugin is `com.test.pub`, so the own-id prefix rule already denies them. The reviewer checked this: with the four roots removed, the test stays green, and the log says "outside the plugin's own namespace". They are still harmless regression rows. Elsewhere the fix is proven: the new schedule rows (`shift.tick`, `till.tick`) and `TestValidatePluginID` go red without it. A direct `checkPluginEventName("shift", "shift.opened") == errEventNameCoreRoot` table test would prove the publish path too. Fixed: the orchestrator added `TestCheckPluginEventName_NewCoreRoots` (plugin id = the root, so only the core-root check can refuse). Without `shift` in the map it fails with `checkPluginEventName("shift", "shift.opened") = <nil>, want errEventNameCoreRoot`; with it, it passes.
2. **Low, deferred.** The scanner reads only the top level of `internal/plugins` and `internal/pages`, and skips event names held in a `var` or built at runtime. Today that covers every core bus call site. The reviewer grepped `internal/` and `cmd/`: there are bus calls in 18 `internal/pages` files and `ipc.go`, and none anywhere else. The only call sites with dynamic names are plugin-owned (`e.TriggerEvent`, payment `<trigger>.authorize`, `plugin_job`/`plugin_view` `event` parameters fed from `ui.*` consts, and the button `eventType`, whose fallback is `plugin.button.pressed`). A core publish added in another package would go unseen, so a later hardening could walk the whole of `internal/`. `till` is already reserved, so #5758 is covered either way.
3. **Info.** Reserving the roots breaks no existing id. A grep of universal-till (bundled `plugins/**/plugin.json`, fixtures, e2e), ut-cloud and ut-docs found no plugin or manifest id rooted at `agent`, `charge`, `inventory`, `report`, `shift` or `till`. The only near hits were the ut-cloud category id `inventory` in `docs/api-reference.md` and the listing slug in `internal/catalog/service_test.go`, and neither goes through manifest validation. Settings keys like `till.name` and the i18n keys are not bus events. Root matching is on the whole segment, so `com.universaltill.shift-report`, `reporting.x`, `tills.x` and `agents.x` stay accepted, and tests cover those.
4. **Info.** Merge order: ut-cloud's `manifest-contract-guard` checks out this repo's default branch, so merge this PR first and the ut-cloud PR straight after.
