# Review: line edit compare-and-set, weighed discount, PIN hint (ut-docs#5417)

Branch `fix/5417-line-qty-cas`. Follow-ups from the #5411 review
(`2026-11-04-line-reduction-needs-pin-5411.md`).

## What shipped

- **TOCTOU (AC1–AC3).** `/api/pos/line` read the line from a `Basket()`
  copy, decided the `void_comp_waste` gate, wrote shrinkage + audit rows,
  then applied the qty unconditionally. A concurrent raise in that gap could
  turn the post into an ungated reduction (and the delta path added to the
  stale qty). Now the engine applies the change with a compare-and-set
  (`pos.Service.UpdateLineByKeyIfQty(key, fromQty, qty, discount)`,
  `pos.ErrLineChanged`); `UpdateLine`/`UpdateLineByKey` keep their behaviour.
  Shrinkage and audit rows are written only after the update applied. A
  refused update answers **409** with the current basket and a `role="alert"`
  note under the line (`Basket.LineChangedKey`, `.line-discount-error`
  styling), or above the totals when the line no longer exists; app.js's
  basket-body carve-out accepts 409 as well as 400.
- **Weighed phantom reduction (AC4–AC6).** The discount box sent the row's
  qty box (rendered `%.2f`) via `hx-include="closest tr"`, so a 0.125 kg
  line's discount edit arrived as qty 0.12: PIN prompt + shrinkage row. The
  discount box no longer includes the row; the handler keeps the current qty
  when none is posted. Qty box and steppers unchanged.
- **PIN hint wiped (AC7–AC9).** The prompt now sends
  `HX-Trigger-After-Settle: ut-basket-resync`, and the app.js resync carries
  the same `#shrinkage-hint` nodes across the `#basket` re-render while
  `#elevation-modal` is open (so Cancel/approve still clear it).
- New key `basket.line_changed` (English only, meta with `max_length` 110).
- Tests: `internal/pos/service_update_if_qty_test.go`,
  `internal/pages/pos_api_line_cas_test.go` (hook-forced concurrent raise,
  removed line, already-removed line, After-Settle header, weighed cases,
  deterministic race stress), `e2e/tests/prompt-line-reduction-hint-5417.spec.ts`.

## CI follow-up

`desktop-shell`'s whole-program deadcode guard flagged
`pos.Service.UpdateLine` as unreachable: the handler's code-addressed path
now goes through the key CAS, so nothing in production called it. Removed
it (adding it to the shrink-only `deadcode-baseline.txt` is not allowed);
its five test callers use a test-only `updateLineByCode` helper over
`UpdateLineByKey`. `go test ./internal/pos/` and the line/remove handler
tests re-run green.
