# Code review: ut-docs#1912 — sale-screen nav rail as an ADR-0088 UI slot

**Author:** Pouria Teimouri (`lane:cloud-41`), implemented via a Fable subagent (`complexity:hard`)
**Tester:** independent Sonnet subagent (session model) — real gate re-run, Playwright e2e actually executed, driven browser screenshots at kiosk/phone/RTL, one TDD-mutation check
**Reviewer:** independent Opus subagent, isolated scratch worktrees for the gate and for revert-then-restore verification (`complexity:hard` → Opus per model-routing, deliberately not Fable)

## What shipped

`web/ui/partials/nav.html`'s `.nav-primary` block — the four hardcoded
sale-screen rail links (Sell `/`, Menu `/menu`, Inventory `/inventory`,
Orders `/orders`) — is now resolved through `internal/uislot`'s ADR-0088
declarative UI-slot registry, the third slot after Menu and Items
(ut-docs#1911), so a `layout` plugin can reorder/relabel it the same way.

- `internal/uislot`: added `RailSlot`, `CoreRail` (4 entries), `ProtectedRailKeys`
  (`/`, `/menu` — ADR-0088 Decision J, merged to `ut-docs` main this cycle
  as `ut-docs#2049`), `IsProtectedRailKey`, `CoreRailEntry`,
  `ParseRailAmendments`, and a `railSpec` mirroring `itemsSpec`'s
  capability set (reorder + relabel only — no hide/icon/group, same
  Decision D restore-surface gap the Items slot has). `ParseAmendmentsJSON`
  dispatches `RailSlot`; its unsupported-slot error now names all three
  slots.
- `internal/httpx/rail.go` (new): the mechanism for reaching a shared
  partial rendered on every page from a package that cannot import
  `internal/pages/common` (import-cycle: `common` already imports
  `httpx`). A package-level `RailAmendmentsProvider func() []uislot.Amendment`
  var (default nil → zero-plugin rail), set once in `internal/pages.Init`
  to `dp.RailAmendmentsSnapshot` (immediately after `Deps` is constructed,
  before any route registration or `ReloadPlugins` call — verified no
  stale/nil-provider window exists). Bound into template funcs via
  `FuncsFor(locale)`/`baseFuncs`, reaching `Render`, `RenderWith`,
  `RenderContentFragment`, *and* `RenderError` (all four whole-page render
  paths — the ADR review caught that the original brief only named three).
- `internal/pages/common`: `RailAmendments`/`RailAmendmentsSnapshot`
  (nil-receiver-safe, since `RenderError` can render nav before any
  request-scoped state exists), `BuildRailAmendments`.
- `web/ui/partials/nav.html`: `.nav-primary` is now a `{{ range railEntries }}`
  over resolved entries; per-entry presentation (the `nav-rail-only` class
  hiding Inventory/Orders at ≤480px, `data-testid` attributes) is keyed by
  `Key`, not position — proven by a reviewer experiment that re-keyed it
  by position and watched the golden + reorder tests fail.
- `plugins/layout-salon`: a third layout entry (`"slot":"rail"`) reorders
  `/orders` ahead of `/inventory` (Order 250) — a pure reorder, no new
  translations needed. Version 0.2.0 → 0.3.0.
- `scripts/ci/guard-plugin-menu-read.sh` (+ its `_test.sh`): pattern
  widened to `RailAmendments\b` / `Build(Menu|Items|Rail)Amendments\(` —
  verified by the reviewer to catch an unguarded `deps.RailAmendments`
  read and to NOT false-positive on the `httpx.RailAmendmentsProvider =
  dp.RailAmendmentsSnapshot` wiring line (the specific reason for that
  variable's name).
- Tests: `internal/uislot/slot_test.go`, `internal/httpx/rail_test.go`
  (new), `internal/pages/nav_rail_test.go` (new, includes a real
  `PersistManifest`/`ReloadPlugins` end-to-end install of the salon
  plugin), `internal/httpx/icons_test.go` extended,
  `internal/plugins/layout_validation_test.go` extended,
  `internal/plugins/builtinlayouts/builtinlayouts_test.go` version bump.
- `web/help/en/menu.md`: documents the rail's reorder/relabel limits.
- `web/help/img/manifest.json` + regenerated screenshots (`make docs-shots`).

## Independent review — findings and disposition

The Opus reviewer ran the full gate itself (build/vet/lint/race/full
suite/14 guard scripts) rather than trusting Dev's or Tester's numbers,
and independently re-verified TDD claims via four separate
break-then-restore experiments (dropping a protected key, neutering the
protection check, deleting the zero-alloc fast path, and re-keying
presentation by position instead of by `Key`) — every one produced a
real, specific test failure with the exact error the fix exists to
prevent, then passed again on restore.

| # | Severity | Finding | Fix |
|---|---|---|---|
| 1 | Medium | `web/help/en/menu.md` promised a relabelled Inventory/Orders rail entry would be visibly renamed — but `/inventory` and `/orders` (the only two amendable rail keys; `/` and `/menu` are protected) are exactly the entries whose visible label is hidden at every viewport except the ≤480px phone fallback (rail labels are `.visually-hidden` at kiosk/tablet width, present only for assistive tech). The set of "keys a plugin may relabel" and the set of "keys whose label is ever painted" don't overlap in the normal kiosk/tablet case this help topic is written for. | Rewrote the help sentence to describe the rename as reaching screen readers everywhere and visible text only at phone width; dropped an inaccurate "on the left" (the rail sits on the *logical* start side — the right in `ar`/`fa`) and an inaccurate "stays where you expect" (reorder of `/`/`/menu` is explicitly allowed, so their position isn't fixed — only their presence and label are). Added a code comment on `railSpec` in `internal/uislot/slot.go` recording the same fact for the next person reading the capability declaration, not just the prose. |
| 2 | Medium | `reference/plugin-manifest.md` (this repo's sibling `ut-docs`) still named `menu` as "the first and so far only" layout slot — verified this was never actually corrected for the Items slot either (ut-docs#1911's own review record claimed an Items-slot section was added; no such section exists anywhere in the file), and was now additionally wrong for Rail: it listed `hide`/`group`/`icon` as universally available (all three are refused on both Items and Rail) and said "reorder/re-label/re-group/re-icon of a protected destination stays allowed" (false for Rail's `/` and `/menu` under Decision J). | Fixed in `ut-docs` directly (a `ut-docs` PR opened alongside this one, not part of this repo's diff): rewrote the section with a per-slot capability table (menu/items/rail) instead of a single-slot narrative, so the next slot addition has a table to extend rather than prose to rewrite. |

No blockers. Full findings list (including low/nit items the reviewer
explicitly chose not to act on, with reasoning) is in the review
subagent's own transcript; the two mediums above are the only items that
changed committed content.

## Deferred, explicitly (not silently dropped)

- **A findability/restore surface for the Rail slot** (same as Items) —
  `hide` stays refused until one exists. Worth a Backlog card if a real
  vertical needs to hide a rail entry rather than reorder/relabel it.
- **de/fa/ar/tr `web/help/menu.md`** don't carry the new rail-limits
  sentence yet — verified this is the same pre-existing lag the Items
  slot's own help update had (none of the four locales carry that
  sentence either), not a new shortcut specific to this card. Needs the
  self-hosted NAS translation model, unreachable from this cloud sandbox.
- **fa (Persian) RTL** was not independently screenshotted (ar covered the
  RTL check) — low risk given the rail's RTL behavior is driven entirely
  by existing logical CSS properties this diff didn't touch, but noted
  for completeness.

## Verdict

Safe to merge. Both independent-review findings were documentation
accuracy issues (a help topic overstating what a relabel visibly does;
a plugin-author-facing reference that was already stale before this card
and would have become actively wrong after it) — fixed in this same
cycle, not deferred, per this ecosystem's "behaviour changes update the
affected reference in the same session" rule. No code-level blocker or
medium finding survived independent review; the mechanism (import-cycle
seam, presentation/data separation, zero-allocation guarantee, slot
dispatch) was independently attacked from multiple angles and held.
