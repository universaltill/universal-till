## What shipped

- **Replica chip** (`internal/pages/link_status.go`, `web/ui/partials/main_till_status.html`):
  one truthful main-till light in the status bar on every page — *Main till linked* /
  *Main till: polling* / *Main till not reachable since HH:MM — selling offline*
  (+ *plugin updates wait for it*), with *Update waiting* / *Waiting for the main till
  to update* from the hello version vs `buildinfo.Version`. Derived from the link
  client's presence (`fleetlink.ClientStatus`: hello + a frame within 12 s) and the
  shared `PrimaryWatch`; polled every 5 s (was 30 s) into the `hx-preserve`d mount.
- **Browser light** (`base.html`): on a till with a main till the green "Online"
  (= a network interface is up) is hidden; it returns only as *No internet* when
  `navigator.onLine` is false. A polite live region announces a change of link state.
- **Main till Tills roster** (`internal/pages/tills_roster.go`, `tills_roster.html`,
  `Hub.Peers()`): per enrolled till — Linked / Not linked, role, version vs this till,
  update state, sales waiting to send, TLS pinned — re-rendered every 10 s through
  `GET /ui/tills/roster` (same `sync_management` gate as the page).
- Locales en/ar/fa/tr (+24 keys), help topic `multitill` in en/de/ar/fa/tr,
  `shortdatetime` helper, `.tag.ok` / `.sb-link` CSS.

## Findings

| # | Severity | Finding | Outcome |
|---|---|---|---|
| 1 | Medium | **Restart gap.** A replica restarted while its main till is down has no in-process loss (`LostAt` zero) and the pull loop's first tick is 30 s away, so the chip read *polling* for 30–90 s. `PrimaryWatch` already has the "already unreachable at launch" rule (one failure + last contact older than its window) but only the pull loop fed it. | **Fixed.** `ClientStatus.FailedAt` records a probe/dial that got no HTTP answer; `deriveLinkView` rule 5 reads unreachable since `sync.last_contact_at` when that is older than the exported `discovery.UnreachableWindow` (90 s) or absent. Tests: `TestDeriveLinkView` (3 cases), `TestClient_StatusRecordsAFailedAttemptAndForgetsItOnAnAnswer`. |
| 2 | Low | Roster showed ENROLLED as `2026-09-25 16:59:38` (SQLite `datetime('now')` column default, not RFC 3339) but LAST SEEN localised. | **Fixed** in the shared place: `httpx.ParseStoredTime` accepts both layouts; `datetime`, `shortdatetime`, `datetimeUTC` use it. Tests: `TestFuncsForExposesDateTime`, `TestTillsPage_PollsRosterUnlessFocusedAndFormatsBothDates`. |
| 3 | Low | After an outage, a main till that answers the probe as an older build (no link, `level < 1`) left `LostAt` set, so the chip stayed *not reachable* until the next successful pull (≤ 30 s) although the main till had answered. | **Fixed:** `attempt` clears the outage on that answer. Covered by the test in #1. |
| 4 | Low | `aria-live` announced *Main till linked* on every hard page load: the announcer's first sight of the mount is empty (the `load` poll hasn't answered), so the chip's arrival counted as a change. | **Fixed** (`base.html`): only a transition between two real states is announced; boosted navigations keep the chip via `hx-preserve`, so there the baseline is the real state. |
| 5 | Low (UX gate) | The roster swap replaced the Revoke buttons every 10 s, so a keyboard user who tabbed onto one lost focus at the next tick (ut-docs#826's lesson). | **Fixed:** `hx-trigger="every 10s [… !#tills-roster.contains(document.activeElement)]"` — same shape as `tables.html`'s `[!window.tablesEditing]`. Test in #2. |
| 6 | Info | **Polling cost.** Chip, per open page every 5 s: replica = 2–3 single-row settings reads (+ `CurrentPendingUpdates` only when unreachable); main/standalone = 1 read, empty body. Roster, per open Tills tab every 10 s: `ListTills` + 2 settings reads + a locked copy of the hub's maps, bounded by `MaxConns`/`MaxReports`. **No DB write on either poll.** Hidden tabs keep polling (htmx `every` has no visibility gate) — the app-wide pattern (`#sync-chip`, tables), not widened here. | Accepted. |
| 7 | Info | **HTMX.** The mount is `hx-preserve`d and its response is the chip itself, never an OOB swap of the mount (the standing rule holds); `#tills-roster` has no `hx-preserve`; both are `innerHTML` swaps — no page reload, no scroll change; 403/5xx leave the DOM as it was. | Accepted. |
| 8 | Info | **Leaks.** The roster exposes till name, role, version, update state (whitelisted), failure code (`[a-z0-9_-]`, ≤ 32), queue depth, TLS-pinned flag and the till UUID (already in the revoke URL). No bearer hashes, no URLs or IPs. Peer hello strings are clipped at the hub. Gate: `sync_management`, cashier gets 403 (tested). | Accepted. |
| 9 | Info | **No-internet honesty.** `navigator.onLine` false → *No internet* (true then); true → hidden on a replica, so nothing claims the internet is up. A main till still shows the old green *Online* (interface up) — pre-existing, outside this card. | Accepted; noted for a follow-up if the owner wants the main till's light changed too. |
| 10 | Info | `golangci-lint` typecheck `undefined: rand` at `fleetlink/client.go:418` — a line from the committed #2735 (`math/rand/v2`), lint binary built with go1.26 vs the go1.27 toolchain; `go build`/`go vet` pass. | Pre-existing, not this diff. |

## UX §7 gate

- Surfaces: replica status bar on every page incl. the sell screen (kiosk 1024×600 and 800×480 checked); main Tills page (desktop/kiosk). **Named and checked.**
- Touch still scrolls/drags: no pointer handlers added. No inputs added → no OSK concern; nothing steals focus (fix #5).
- Every string through `T`; en/ar/fa/tr complete; help in five locales. **de/es language packs need the 24 new keys** (brand-new keys → merge core first, land the pack PRs in the same cycle, per CLAUDE.md).
- RTL: logical properties only (`min-block-size`, `max-inline-size`); fa/ar screenshots correct.
- Non-colour meaning: every state is words first; tags read *Linked* / *Not linked*. Touch target: chip is a real link at the status bar's own item height (not enlarged beyond the bar's other items — pre-existing sizing). Focus ring: inherits `.sb-item`; not separately verified.
- 360 px: covered only by the existing ≤ 480 px ellipsis rule (`.sb-link` added to it); **not screenshotted.**
- Empty/error states: roster → `tills.none`; chip states self-explanatory and link to the Tills page, whose banner says what to do.

**Verdict: PASS** (360 px unscreenshotted; real-touch hardware not used — a replica on the Pi/tablet is worth a look after merge).
