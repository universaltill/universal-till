# Code review — kiosk PIN switches the device mode (ut-docs#3136)

Date: 2026-10-01 · Branch: `fix/3136-kiosk-pin-login` · Lane: `lane:cloud-54`
Author model: Opus 5.5 · Reviewer: Fable (independent subagent, own worktree)

## What shipped

- `POST /api/auth/login` (`internal/pages/auth_page.go`): a successful PIN
  login as the seeded `kiosk` user persists `display.mode=self_order`
  through the new shared `applyDisplayMode` helper (same write and live
  template flags as Settings → Display → Device profile), revokes the new
  token and any session the browser still carried, clears the cookie,
  audits `kiosk_mode_entered` and redirects to `/self-order` (where the
  Android app's existing URL-driven screen pinning engages). The kiosk user
  never holds a session.
- Any other user's login **through the kiosk's lock link** (`next=kiosk`)
  on a `self_order` till restores register mode (`display.mode=""`),
  audits `kiosk_mode_exited` and lands on `/` (the sale screen) instead of
  `/settings`. A plain `/login` from another browser leaves the kiosk
  running; back-office and register tills keep their mode.
- `POST /api/settings/display-mode` now uses `applyDisplayMode` (no
  behaviour change; `InitDisplayMode` receives the stored `""` for
  register, as boot already did).
- `selforder.exit` aria-label: "Exit kiosk mode (PIN required)" (en, tr,
  fa, ar) — the link no longer leads to settings.
- Manual: `web/help/{en,de,tr,fa,ar}/self-order.md` gained a paragraph on
  entering/leaving kiosk mode. ut-docs `architecture/pos-auth.md` updated.
