# Review: a lapsed till picks up its renewal by itself + "Check now" (ut-docs#4285)

**Bug:** a pilot store's plan lapsed. The owner renewed it in the cloud admin, but the till
never learned of it until it was updated to a new version, which fired ADR-0148's start-up
check-in. The cause is ADR-0148 §4: a lapsed till checks in only on an operator action
(a hidden Settings button) or on a start with a new version or date.

**Shipped** (ADR-0148 amendment 2026-10-14, ut-docs PR on branch `adr-0148-renewal-watch-4285`):
- **Renewal watch** (`internal/cloudsync/sync_gate.go`). A till whose cached block is `lapsed`,
  or that recorded `entitlement.last_paid_at`, checks in once an hour (±10 %). This runs for
  90 days from the last paid confirmation, or from the first lapse seen
  (`entitlement.lapsed_seen_at`). A 402 does not end the watch. A never-paid till is
  unchanged (silent). The markers are written in `cacheEntitlement`'s single SetMany and are
  per-till (`entitlement.` prefix).
- **Check now** (`POST /api/subscription/check-now`, `refreshEntitlementNow`, which #4286
  reuses). It is elevation-gated like `check-plan`. It opens the operator window, waits up to 8 s
  for a fresh confirmation (with a same-second guard), then shows one of: renewed
  ("Paid until …"), still lapsed, or offline. It is audited. On a renewal it sends
  `HX-Trigger: ut-subscription-changed`, which refreshes the status-bar chip and the
  registration card in place.
- **UI:** the button is on the lapsed banner and the Subscription card, for managers only. On a
  lapsed till it replaces "Check for a paid plan" (one action, not two). The lapsed banner copy
  no longer sends people to Settings → Till registration. Text is in en, tr, ar and fa. Help
  `claim.md` is updated in en, de, tr, ar and fa. Screenshots are regenerated.

**Tests:**
- `renewal_watch_test.go` (9 cases), plus `TestCacheEntitlement_RecordsPaidAndLapseMarkers` and
  `TestStartArmsRenewalWatch`.
- `subscription_check_test.go` (8 cases, including same-second, cashier, the button only for a
  manager, the HX-Trigger only on a renewal, and the card self-refresh living on a sibling).
- e2e `registration-card-paid-4285.spec.ts`.

**Tester:**
- Mutation-checked the tests: 9 of 10 mutations were caught, and the one vacuous assertion was
  fixed.
- Found and fixed a same-second false "offline" (test first).
- Driven runs against a stub cloud at 1024×600, light and dark, en and fa (RTL): 402 → "Still
  not renewed"; 200 → "Paid until"; the card and chip refresh without a reload; a cashier gets no
  button.
- **Not looked at:** German text on screen, phone widths, the replica in a real run, and
  offline in a real run (unit-tested).

**Independent review:** Fable (built by Opus 5.5).
- **HIGH:** `hx-select`/`hx-target="this"` on `#registration` were inherited by every htmx
  child, which blanked the card on paid tills and the banner's result. Reproduced with the
  bundled htmx. **Fixed:** the refresh moved to a hidden sibling. A Go assertion and an e2e spec
  were added, and the spec fails with the old attributes. Re-driven: all pass.
- **LOW:** each watch 402 parks the scheduler for the hour (`Retry-After`), so on a watched till
  issue-report and diagnostics uploads also run hourly. This is existing, tested behaviour from
  the 2026-10-05 amendment. Documented in the ADR; the fix is filed as **ut-docs#4304**.
- **LOW:** after PIN elevation, the re-rendered block drops the button for the elevated
  cashier. Harmless, accepted.
- **NOTE:** a cashier gets the elevation prompt, not a plain 403. That is the repo convention,
  the same as `check-plan`.
- The reviewer checked these and found them clean: CAS and gate order, the marker life cycle,
  replica behaviour, CSRF (SameSite=Lax as on every `POST /api`), the demo denial, the context-
  bounded wait, i18n, and the sale-path import guard.
- **TDD re-verified** in a worktree: with the source reverted, the tests fail to build; restored,
  they pass.

**Gate:** `go build ./...`, `go vet ./internal/...`, `go test ./...` (all ok), gofmt clean.
The i18n, showmodal, help-topics, help-drift, data-access and docs-shots guards are green.
golangci-lint (via `go run …@latest`) was clean at the Tester step.

**Language packs:** the new and changed `en.json` keys need the `ut-plugin-language-*` follow-up
PRs after merge (lang-pack-drift).

**Verdict:** safe to merge.
