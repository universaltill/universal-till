# Review: wasmbench on iOS (ut-docs#3918)

**Shipped.** The `tools/wasmbench` measurement moved into package
`tools/wasmbench/bench` (`Module`, `NewModule`, `Options`, `Run`, `Report`),
so the CLI and a new gomobile entry point (`mobilebench.RunJSON`) share it.
A throwaway XcodeGen app (`tools/wasmbench/ios`) runs it in-process on a
cabled iPhone/iPad; `ios/run.sh` builds, installs and launches it with
`devicectl` and writes `out/ios-<udid>.json`. iOS platform facts come from
sysctl (no exec in the iOS sandbox). It's a local debug tool: never shipped,
never TestFlight, no product UI, so no i18n or help topic applies.

**Result** (ut-docs `architecture/wasm-runtime.md`): tax-uk costs 11.9 /
12.9 ms (p50 / p95) per event on an iPhone 17 Pro Max interpreter, in-app.
The no-reactor verdict holds on iOS. The iPad was skipped by the owner;
follow-up ut-docs#3941.

**Reviewer:** independent Fable subagent in a separate worktree. It ran
build, vet (host and `GOOS=ios`), the tool tests, shellcheck and mutations.

Also found during testing: a `devicectl` launch refused because the phone
was locked ended `run.sh` silently under `set -e`. It now prints the log and
the reason.

**Verified beyond the unit tests:** two full iPhone runs (n=30, 1000 calls)
agreed. After the fixes, `run.sh` was run end to end on the iOS simulator
with `tax-uk=./tax-uk.wasm` as a relative path (rows named `tax-uk`). The
locked-phone failure path printed its reason. The CLI still runs on macOS
with both engines.

**Verdict:** safe to merge.
