# Review: customers E.164 phone normalisation, notes, caller lookup (ut-docs#3200)

Branch `feat/3200-customer-phone-e164`. Caller ID 1/8 (epic ut-docs#3080,
ADR-0131 §3–§4). Author: Opus 5.5 dev subagent (lane:cloud-24,
`complexity:medium`). Reviewer: Fable, fresh context, separate worktree
(reviewer ≠ author model).

## What shipped

- `internal/phonenumber` (pure, no SQL): a complete `(ISO, calling code,
  trunk prefix)` table of 245 ITU regions held as struct data, so
  `guard-core-neutral.sh` passes; `Normalise(raw, region)`, `Digits`,
  `TrailingKey`. No length or carrier metadata (ADR-0131 §3).
- Migration 069:
  - adds `customers.phone_e164` (indexed) and `customers.notes`;
  - adds `idx_sales_customer_id` (the last-5-sales query would otherwise
    scan all of `sales`);
  - adds a trigger that NULLs `phone_e164` when `phone` changes on its own.
- `POSRepo.BackfillCustomerPhoneE164`:
  - pages through the table by id in chunks;
  - each write is guarded on the phone it read, so it never overwrites a
    concurrent edit;
  - it is idempotent;
  - it recomputes every row when `store.country` differs from a per-till
    marker.
- At boot, a background goroutine on the app WaitGroup runs the back-fill
  on every till, never on a request path. A failure is only logged.
- `POSRepo.LookupCustomersByPhone`:
  - returns every matching non-erased customer (cap 10), with name, phone,
    address, notes, and the last 5 completed sales (date, `money.Money`
    total, line count);
  - rows the back-fill hasn't reached yet are normalised in Go, read-only.
- Replica retire-scrub also blanks `notes` and `phone_e164`.
- `docs/data-model.md` is updated.
- No UI and no locale keys. Customer create/edit and the notes field are
  ut-docs#1602.

## Findings

| # | Severity | Finding | Outcome |
|---|---|---|---|
| 1 | should-fix | An exact E.164 match suppressed the trailing-9 fallback, so a duplicate stored as an unnormalisable string ("020 7946 0018 (work)") was hidden, against ADR-0131 §4's "list every match". | **Fixed.** Exact matches are now unioned with trailing-9 matches among stored numbers that are not E.164. A stored E.164 number that only shares the last 9 digits still stays out. New subtest `exact match keeps unnormalisable duplicates` failed first (`[Alice]`, want `[Alice Work]`). |
| 2 | should-fix | `+44 (0)20 …` normalised to `+4402…`. | **Fixed.** A literal `(0)` is dropped in an international number. New GB and DE cases failed first. |
| 3 | nit | The retire-scrub test passes without the `phone_e164` scrub entry, because the scrub's `phone = NULL` already fires the 069 trigger. | Accepted. The entry is belt-and-braces; the `notes` entry is pinned. |
| 4 | nit | The back-fill and the country-change check run only at boot. | **Follow-up ut-docs#3992.** Lookup stays correct meanwhile. |
| 5 | nit | Short national numbers such as `555-0100` (US) pass the 8-digit floor. | Accepted. Both sides are treated alike, so matching is unaffected. |
| 6 | nit | Trailing-key asymmetry for stored numbers shorter than 9 digits. | Accepted (documented choice). |
| 7 | nit | Check TJ and UZ trunk prefixes (table: none). | Accepted. The table follows libphonenumber's current `national_prefix`. A wrong trunk affects both sides the same way, and the trailing-9 fallback covers it. |
| 8 | nit | The back-fill bumps `sync_admin_version` on the main till, so replicas re-pull once. | Accepted. One-off, and harmless. |
| 9 | nit | A formatting-only phone edit that writes back the same `phone_e164` gets NULL, which the migration comment did not say. | **Comment corrected** (comment-only; the checksum is unchanged). The behaviour is safe. |
