# Review — SKU-less item tiles read as "out of date" (ut-docs#3072)

**Date:** 2026-09-27 · **Branch:** `fix/3072-null-sku-tile` · **Built by:** Opus 5.5 · **Reviewed by:** Fable (independent subagent)

## What shipped
- `POSRepo.resolveItemByID` (`internal/data/pos_repo.go`) now reads `COALESCE(i.sku, '')`. An item with no SKU stores `sku = NULL`, and scanning that into `shortcutPriceRow.SKU string` failed. The `item:<id>` tier then reported not-found, and `/api/pos/scan` took the #2525 stale-tile branch: no line, the "quick button was out of date" toast, and a grid refresh that reset the category chip. It affected 125 of 231 items on a pilot catalog.
- A Scan error other than `sql.ErrNoRows` is now logged instead of being swallowed. This was the reviewer's suggestion.
- Tests:
  - `TestResolveShortcutLine_ItemIDCodePrefixResolvesNullSKU`. The existing #2294 test seeded `SKU ""`, not NULL, so it never hit this.
  - e2e `sell-null-sku-tile-3072.spec.ts` (all_filter_chips → chip → SKU-less tile → one line, no toast, chip stays).

## Findings
| # | Severity | Finding | Outcome |
|---|---|---|---|
| 1 | nit | `resolveItemByID` swallowed the Scan error, which hid this bug class | Fixed: logged unless ErrNoRows |
| 2 | nit | e2e `itemId` is describe-level state | Accepted (single test) |

The same-class hunt found no other reachable NULL→string scan on the sell path. Every other `i.sku` read either uses COALESCE or filters on `sku = ?` / non-empty. The synthesized `item:<id>` is blanked by `PriceResolverAdapter.resolve` before it reaches `sale_lines.sku_snapshot`, so it never shows on a receipt.

## Verified beyond automated tests
- Reproduced on a copy of the pilot's replica DB (sync disconnected) with v0.30.1: `POST /api/pos/scan code=item:<id> src=tile` gave the stale toast. With the fixed build, all three SKU-less Kuchen items added lines (total €14.70), with no trigger and no toast.
- TDD re-verified at both layers by the builder and again by the reviewer. The Go test and e2e fail without the COALESCE (e2e: 0 basket lines, chip back on All; screenshot looked at) and pass with it.
- `go build ./...`, `go vet ./...` and full `go test ./...` are green. `guard-data-access.sh` is green. Neighbouring e2e (`codeless-item-shortcut-1459`, `sell-screen-browsing-mode-2499`) passes 7/7.
- Not yet checked on the tablet: that needs a release; the device check is on the card.
