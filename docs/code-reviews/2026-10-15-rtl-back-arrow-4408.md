# Review: RTL text back arrows (ut-docs#4408)

- **Date**: 2026-10-15 · **Author**: Opus 5.5 (inline) · **Reviewer**: Sonnet 5.5 (independent, worktree)

## What shipped

- The 19 `← {{ T "…" }}` back links in `web/ui/pages/*.html` now wrap the
  glyph in `<span class="back-arrow" aria-hidden="true">←</span>`.
- `web/public/app.css` adds `.back-arrow` (inline-block) and
  `html[dir="rtl"] .back-arrow { transform: scaleX(-1) }`, next to the
  nav rail's Back mirror. The plugin store's page-local
  `.store-back-arrow` is folded into the shared class.
- `web/back_arrow_test.go` (`TestNoBareBackArrowGlyph`) fails CI on any
  bare `←` in a template outside a comment, so a new page can't
  reintroduce the bug.
- `e2e/tests/rtl-back-arrow-4408.spec.ts` reads the computed transform:
  `none` in en, `matrix(-1, 0, 0, 1, 0, 0)` in fa, on `/tills`, a
  journal detail page and `/settings` (phone width, deep-linked section,
  where its Back shows).
- docs-shots regenerated (the guard required it). The arrow-to-label gap
  in `.btn` back links is now the button's `gap` (.4rem) instead of a
  space, so some en screenshots changed by a few pixels.

- TDD: `TestNoBareBackArrowGlyph` fails on `main`'s templates (the reviewer
  reverted two templates; it named both). The e2e test fails with the RTL
  rule removed (`Received: "none"`) and passes with it.
- Looked at fa renders of the journal detail page and `/settings` Back
  (the arrow points right, at the start of the button) and at en
  tax-codes before and after (only the 3px gap moved). Did not look at
  ar or dark theme: the same CSS applies.
- `go build`, full `go test ./...` (minus the untouched `internal/plugins`),
  `golangci-lint` 0 issues, the i18n / inline-handler / help / showmodal /
  core-neutral / compliance / naming guards, and docs-shots regenerated.
  41 e2e tests pass across the specs that touch these back links plus
  settings-two-pane.
- The card's acceptance named `/invoices`. It redirects to `/settings`
  until seller details are set, so the e2e test uses `/tills`, which has
  the same markup; the Go guard covers `invoices.html` too.

**Verdict:** safe to merge.
