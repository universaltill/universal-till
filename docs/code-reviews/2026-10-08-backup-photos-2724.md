## What shipped

- `internal/db/backup_assets.go`: `SnapshotWithAssets` = `Snapshot` + a
  `ut_backup_assets(path, mod, data)` table inside the snapshot copy, filled
  from `paths.Data("public","assets",{items,categories,logo})` (files ≤ 10 MB,
  `.sync-tmp`/`.restore-tmp` skipped; table rebuilt on every call).
  `RestoreBackupAssets` runs on every boot after `ApplyPendingRestore`,
  before `db.Open`: writes each photo back (temp + rename, mtime kept),
  refuses unsafe paths and symlinked-directory escapes, then drops the table.
- Callers: daily backup (`internal/server`), `POST /api/backup/now`,
  `cmd/unitill-uninstall` (a photo failure aborts the uninstall there).
- `StageRestore` streams the file instead of reading it into memory.
- Help topic `backups` (en/de/tr/fa/ar); ut-docs `architecture/local-backup.md`.
- Not a migration: the table exists only in snapshot files; a live DB drops
  it on the first boot after a restore. Join snapshots stay DB-only.

## Findings (Fable)

| # | Severity | Finding | Outcome |

| 1 | major | One unwritable row kept the table, so every boot re-wrote all photos over newer uploads | Fixed: table dropped after one attempt; error returned for the log (the backup file stays in `backups/`). Test `WriteFailureStillDropsTable` |
