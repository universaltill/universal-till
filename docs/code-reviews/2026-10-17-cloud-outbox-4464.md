# Code review — cloud outbox: catalogue change upload, value-based conflict test, CatalogConflict log (universal-till side) (ut-docs#4464, ADR-0162 card 4)

**Date:** 2026-10-17 · **Author model:** Opus 5.5 · **Reviewer:** Fable (independent; first review, re-review, delta review)

## What shipped (across ut-cloud + universal-till)
- **universal-till:** `cloud_outbox` table (migration 083) and the push/seal/ack flow: a catalogue edit on a cloud-master till is queued, sealed into a batch, sent before every pull, and acknowledged per change; the cloud's current row in each answer is applied at once. A hidden base (`sku_kept`) is kept per row so the cloud can test by value.
- **ut-cloud:** `POST /v1/stores/catalog/changes` (contract `reference/contracts/cloud-catalog-changes.md` 1.0.0). Each change is tested against the cloud's master copy **by value, never by clock**; it is applied through `internal/catalogwrite` or kept as the cloud's row with the till's change logged as a `CatalogConflict`. `CatalogChangeReceipt` makes a replayed batch idempotent. Both new entities are covered by tenant scope, erasure, the Art. 20 export and retention, and classified in `residency.go`.
