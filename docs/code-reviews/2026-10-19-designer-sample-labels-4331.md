# Review: receipt designer sample ticket labels follow the shop locale (ut-docs#4331)

Date: 2026-10-19 · Branch `fix/4331-designer-sample-labels` · Lane `lane:cloud-41`
Author: Sonnet 5.5 · Independent reviewer: Opus 5.5, fresh context (different model)

## What shipped

- `internal/pages/receipt_designer.go`:
  - `sampleReceiptDoc` builds its labels from the keys and helpers a real receipt uses (`buildReceiptDoc`, ut-docs#4199):
    - `receipt.paper.receipt_no` (a printf format, as on real receipts);
    - `receiptMethodLabel(locale, "cash")` → `tender.cash`;
    - `receipt.change`, `basket.subtotal`, `basket.tax`, `receipt.paper.total`.
  - Item names, SKUs, quantities, the £ amounts and the date stay fixed demo content.
- The designer page preview, `POST /api/receipt-designer/preview` and `POST /api/receipt-designer/test` pass the shop locale (`httpx.DefaultLocale()`), not the request locale.
  - The test print's tracking-caption charset fallback uses the shop locale too, like `receiptTrackingPrint`.
  - The test print's UI messages (`test_ok` / `test_failed`) stay in the operator's locale.
- `web/help/{en,de,tr,fa,ar}/designer.md`: one sentence each. It says the preview's labels are in the shop's language, as on printed receipts, even when the till is used in another language.
- `web/help/img/manifest.json` was regenerated by `make docs-shots`. That refreshed the designer topic hashes and `surface_sha256`; every PNG came out byte-identical. The harness shop is en, so the labels render as before.

## BA / design notes

- The AC says the shop locale, not the operator's, because that is what real receipts print (`printLocale := httpx.DefaultLocale()` in `buildReceiptDoc`).
- An en shop's preview is byte-identical. Each en key value equals the old literal.
