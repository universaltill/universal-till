# Review: `event_publish` host function (ut-docs#3871, ADR-0121 build 7c)

- **Date:** 2026-10-08
- **Branch:** `feat/3871-event-publish` (+ ut-docs `docs/3871-event-publish`)
- **Author:** Opus 5.5 (dev subagent); **reviewer:** Fable (independent, different model)
- **Lane:** `lane:cloud-41`

## What shipped

`event_publish(type, payload)` on the `ut` host module (`internal/plugins/wasm_event_publish.go`):

- **Namespace:** the type must be `<manifest id>.<name>`, never a core root. `checkPluginEventName` is now shared with `schedules[].event` (`-2`).
- **Caps:** a type over 256 bytes is `-4` before it is read. The payload is JSON of at most 64 KiB (`-4`).
- **Rate:** a per-plugin token bucket, 20/s with burst 40, shared across instances (`-5`). Every call past the length check costs a token, including refused calls.
- **Hop count:** `Event.Hop`; core events are hop 0. A publish while handling a hop-3 event is dropped (`-5`) with a warning and an `event_publish_dropped` audit row that names plugin, type and depth, never the payload. The row is coalesced to one per plugin per second.
- **Pending cap:** at most 100 pending events per instance.
- **Async delivery:** accepted events are buffered on the instance's `hostState`. After the instance exits, however it ended, the call slot is released first and then the buffer goes to the new `EventBus.EnqueuePublished`. That method only enqueues onto subscriber channels (`events:receive` check, the same audit rows, the same channel-full throttle) and never calls a Blocking handler.
- **Ordinary work:** a published event (hop > 0) never takes the reserved sale-path slot (`isSalePathCall`) and never gets the payment, export or import deadline floors (`timeoutForEvent`).
- **Refactor:** `publish`'s non-blocking branch moved verbatim into `enqueueWithDB`. Core events are byte-identical: `hop` is omitted at 0.
- **Docs:** `architecture/wasm-runtime.md` (ut-docs) has the new host-function row and an "Event publish" paragraph.

## Findings

| # | Severity | Finding | Outcome |
|---|---|---|---|
| 1 | major | The event *type* length was unbounded. A 3 MiB type was accepted and queued, so up to 100 of them could exhaust host memory, and each was copied into audit rows and logs. | **Fixed:** a 256-byte cap is checked before `readGuest`. `TestEventPublishTypeLengthCap` fails on pre-fix code (257 bytes → 0). |
| 2 | major | The hop-limit drop wrote an audit row and a warning on every call (20/s ≈ 1.7 M rows/day from one looping plugin), against the `channelFullWarnInterval` precedent. | **Fixed:** coalesced to 1/s per plugin, and the row says later drops are coalesced into it. `TestEventPublishDropAuditCoalesced` fails pre-fix (5 rows, want 1). |
| 3 | minor | A denied-namespace publish logged before the rate check, so a tight loop logged without bound. | **Fixed:** the rate is charged right after the length check. `TestEventPublishDeniedCostsAToken` fails pre-fix. |
| 4 | minor | The flush (audit inserts under `eb.mu.RLock`) ran while the publisher still held its call slot (LIFO defers). | **Fixed:** the flush defer releases the slot first; `release` is idempotent. |
| 5 | minor | Accepted publishes write `event_published` + per-subscriber dispatch rows at the full sanctioned 20/s. This is the existing per-event audit design applied to a plugin caller. | **Deferred:** Backlog card ut-docs#3887 (audit coalescing for plugin-published events). |
| 6 | nit | `flushPublished` silently discarded events when `db == nil` (unreachable in production). | **Fixed:** it now logs a warning. |
| 7 | nit | The docs branch carried an unrelated ADR-0140 commit. | **Fixed:** rebased onto `main`, where ADR-0140 has since merged. |

Reviewed and found sound:
- **Lock discipline:** `EnqueuePublished` holds the RLock across sends, the same as `publish`, so there is no send on a closed channel. No `eb.mu` re-entry.
- **Concurrency on `hs.published`:** host functions run on the instantiating goroutine, so `hs.published` is never touched concurrently.
- **Rate-limiter math.**
- **Hop semantics:** a cross-plugin chain still stops at depth 3.
- **Behaviour for core events:** unchanged.
- **Namespace:** the parent-namespace case (`a` publishing `a.b.x`) is out of scope. The ADR-0121 2026-10-03 listing-id amendment (ut-docs#3604) assigns that to the marketplace.
