# /admin out-of-band tree suppression: unify across six destinations, fail open (ut-docs#2178)

- **Branch:** `fix/2178-admin-tree-oob-fail-open`
- **Card:** universaltill/ut-docs#2178 (follow-up filed out of ut-docs#2167's own review, findings 5–7)
- **Reviewed:** 2026-09-12, independent Opus subagent in an isolated worktree
- **Predecessor record:** `docs/code-reviews/2026-09-12-country-settings-in-panel-scope-filter-2167.md`

## What shipped

`/admin` is a two-pane htmx shell: a tree-row click swaps content into `#admin-panel`, and each of six destination handlers (`locations`, `registers`, `translations`, `fiscal_register`, `fiscal_device`, `country_settings`) appends an out-of-band copy of the admin tree so the "current" highlight follows the click.

ut-docs#2167 gave `/country-settings` an in-page htmx control (scope chips) that targets its own subtree rather than `#admin-panel`, and suppressed the OOB tree for it via `isAdminPanelSwap(r)` — an `HX-Target == "admin-panel"` check, wired into **one** of the six call sites. This card replaces that mechanism:

- **`internal/pages/admin_page.go`** — `isAdminPanelSwap` removed. New `adminInlineSwapHeader = "X-UT-Admin-Inline-Swap"` and `isAdminInlineSwap(r)` (presence check on that custom header). `writeAdminTreeOOB` now short-circuits on `isAdminEmbed(r) || isAdminInlineSwap(r)` **at its own top**, so the decision is made once for all six destinations instead of per call site.
- **`internal/pages/country_settings_page.go`** — its call site is now unconditional, matching the other five.
- **`web/ui/pages/country_settings.html`** — the two scope chips send `hx-headers='{"X-UT-Admin-Inline-Swap":"1"}'`. A new `#country-settings-status` (`.visually-hidden`, `aria-live="polite"`, `aria-atomic="true"`) sits **outside** `#country-settings-view` so it survives that div's own `hx-swap="outerHTML"` replacement; a small inline `<script>` copies the now-pressed chip's own label into it on `htmx:afterSwap`.
- **`web/ui/partials/category_filter_popover.html` + `web/public/category-filter.js`** — the same live-region treatment for `/catalog` and `/inventory`'s category filter, which is a different, purely client-side mechanism (no htmx). `paintTriggerState` already computes a localized active/idle label for the trigger's own `aria-label`; it now mirrors that label into `[data-category-filter-status]`.
- **Tests** — the country-settings guard test rewritten to three cases (suppressed / tree-row click / **fail-open with no `HX-Target` at all**), a new `TestLocationsPage_InlineSwapSuppressesOOBAdminTreeToo` proving the shared rule generalizes to a second destination, a markup-presence test for the popover's status div, and Playwright assertions on the live-region text in both e2e specs.

The direction change is the point. `HX-Target` fails **closed**: htmx omits that header entirely when the swap target has no `id`, so a future tree row or in-page control using an id-less target would silently lose the tree with no error anywhere. A positive opt-out header fails **open** — a caller that forgets it gets a tree that htmx harmlessly discards, never a highlight that quietly stops updating.

**No i18n keys added or removed** — verified, not taken on faith: `git diff origin/main..HEAD -- web/locales/` is empty and the diff introduces no new `{{ T … }}` key anywhere. Both live regions reuse already-translated chip/trigger text. So this card owes **no `ut-plugin-language-{de,es}` follow-up**.

## What the independent review found

One blocker, found by the orchestrator's own e2e run and re-applied here; two real defects found by this review. All three fixed on this branch.

1. **The country-settings live region announced one toggle behind.** (Blocker, found by the orchestrator running the updated Playwright spec; fix re-applied independently in this worktree.) The `htmx:afterSwap` listener read the chips out of `ev.detail.target`. The swap is `hx-swap="outerHTML"`, so by the time `afterSwap` fires htmx has *replaced* that element and `detail.target` still references the **detached, pre-swap node** — its `id` still matches, so the guard passes, but its chips carry the pre-click `aria-pressed` state. Expected "Show all countries", got "Show only my country", every time. **Fixed:** `detail.target` is now used only as the "was it us?" predicate and the live node is re-queried by `id`. This is also the shape the repo's two existing precedents already use — `catalog.html`'s `#catalog-table` handler and `tables.html`'s `#floorplan-wrap` handler both id-check `detail.target` and then look their real nodes up fresh — so the corrected version is the conventional one, not a special case.

2. **The category-filter live region announced on every page load.** (Found by this review.) `CategoryFilter.bind()` calls `fire()` unconditionally at the end of binding, to seed the initial list — so `onChange` runs once at bind time, and therefore so did the new `paintTriggerState` → status write, on every `/catalog` and `/inventory` load and on every htmx swap that re-renders the control. Writing an `aria-live` region on load is the classic way to make a screen reader announce a state the user never chose: a screen-reader user would hear "Filter by category" unprompted on every visit, which inverts the card's own AC ("a spoken confirmation when a filter **changes** what is listed"). **Fixed:** the status write moved into a new `paintStatus()` that arms the region on its first call and leaves it empty, writing only from the second call on. The trigger's own `aria-label`/`title` are unaffected — those are not live regions and must keep being painted at bind time.

3. **Repeated identical writes could make a live region speak repeatedly.** (Found by this review.) The inline `<script>` ships *inside* the swapped "content" fragment, so every return trip to `/country-settings` through the admin tree registers **another** copy of the `document.body` listener. The diff's own comment claimed this was fine because "setting the same textContent again on a stray extra call is harmless". For an ordinary element that is true; for an `aria-live` region it is not — assigning `textContent` replaces the text node even when the string is identical, and that mutation alone is enough to re-announce. After N visits, one chip click could speak N times. **Fixed:** both live-region writes (country-settings and `paintStatus`) now compare before assigning, making the extra calls true no-ops regardless of how many listeners have accumulated. The comment was rewritten to say what actually makes it safe. Note this was only ever *redundant*, never *wrong* — with finding 1 fixed, every accumulated listener computes the same correct label.

4. **A Playwright assertion that could pass against a do-nothing implementation.** (Found by this review.) The new catalog assertion read `.toHaveText((await trigger.getAttribute('data-label-active')) ?? '')`. The `?? ''` fallback means that if the attribute ever went missing the test would assert `'' === ''` — and the live region is *also* empty until the first real change, so it would pass against an implementation that never writes the region at all. **Fixed:** the label is captured, asserted truthy, then compared.

Accepted as-is, with reasoning:

- **No data-leak or privilege vector in the positive-marker design.** Checked directly rather than assumed. The header can only ever cause the server to send **less**: `writeAdminTreeOOB`'s early return omits the whole fragment. It cannot widen what the tree contains, because the contents come from `visibleAdminEntries(d, r)` → `vis.visible(e.VisibleIf)` (`internal/pages/menu_page.go:234`), a per-request visibility predicate driven by the authenticated user, not by any client-supplied header. A malicious or naive client that sets the header on a real tree-row click loses its own highlight refresh — self-inflicted and cosmetic; one that omits it on an in-page swap gets a tree it was already entitled to, which htmx discards. Both failure directions are cosmetic, and the fail-open direction is the harmless one by construction.
- **`X-UT-Admin-Inline-Swap` collides with nothing.** Grepped repo-wide: the existing `X-UT-` family is `X-UT-Response`, `X-UT-Page-Title`, `X-UT-Control-Token` and `X-UT-Admin-Embed`. The new name is unused elsewhere and follows the established prefix convention the ut-docs#2167 review explicitly recommended.
- **Residual `isAdminPanelSwap` mentions** remain only in prose — this branch's own comments describing what was replaced, the e2e spec header, and the historical ut-docs#2167 review record. No code references the removed symbol; `golangci-lint`'s `unused` would have caught a stray definition.
- **The `.visually-hidden` "no rendered pixel" claim holds**, verified rather than assumed: the class is a real rule (`web/public/app.css:1680` — `position:absolute; width:1px; height:1px; margin:-1px; padding:0; overflow:hidden; clip-path:inset(50%); white-space:nowrap; border:0`), so both new divs are out of flow and cannot shift any sibling's layout; both new elements carry it; and the docs-shots harness (`e2e/tests-docs/docs-shots.spec.ts`) only ever does `page.goto()`, which never sets `HX-Request`, so `httpx.IsFragmentSwap` is false and `writeAdminTreeOOB` is not reached on any screenshotted path at all.
- **No file writes and no filesystem paths anywhere in this diff**, so the two recurring bug classes this pipeline watches for — a write handler missing `os.MkdirAll`, and a cwd-relative path where `paths.Data(...)` belongs — are not applicable. Confirmed by reading the diff, not by assumption.
- **No SQL crept in**; `guard-data-access.sh` green and the diff touches neither `internal/data` nor `internal/db`.
- **RTL** needs nothing new: `.visually-hidden` declares no directional property, and no `left`/`right` was added.

Filed as a follow-up, not fixed here:

5. **`Vary` does not mention the new header.** `httpx.IsFragmentSwap` sets `Vary: HX-Request` only, so `/country-settings` now has two possible fragment bodies (with/without the OOB tree) distinguished by a request header absent from `Vary`. In practice this is inert — the success path sets no `Cache-Control`, `Last-Modified` or `ETag`, so the response is not heuristically cacheable, and this is a LAN offline-first app with no intermediary cache — and it is **pre-existing in kind**: the old `HX-Target` check had exactly the same structural gap. Worst case is a stale or missing highlight, never wrong data. Fixing it properly means widening `Vary` where the header is set (before the body is written; `writeAdminTreeOOB` takes an `io.Writer` and cannot set headers), which is a wider change than a review pass should make.

## Verified beyond automated tests

- **Real mutation testing of the new guard, not just a re-run of the given tests.** `writeAdminTreeOOB` was reverted in place to `if isAdminEmbed(r) { return }` and the two headline tests re-run: `TestCountrySettings_FragmentOmitsAdminTreeOnlyWhenInlineSwapMarked` **FAIL** and `TestLocationsPage_InlineSwapSuppressesOOBAdminTreeToo` **FAIL**. Both exercise the new guard for real — neither is a false pass. The file was then restored and both pass again. The `/locations` test is the one that matters most here: it is a *different* destination with no in-page control of its own, so it proves the rule is genuinely shared rather than country-settings-specific by inspection.
- **The fail-open case is a real assertion, not a restatement.** The third sub-case sends `HX-Request` with **no** `HX-Target` at all — precisely the shape htmx produces for an id-less target, which is the invisible bug this card exists to remove — and requires the tree to still be sent. Under the old `isAdminPanelSwap` this case returned no tree; it is the one assertion the previous mechanism could not have passed.
- **The `X-UT-Admin-Inline-Swap` name and the `isAdminPanelSwap` removal** were grepped for across Go, HTML, JS, TS and shell, not just the changed files.
- **`web/help/img/manifest.json` was diffed field-by-field**: exactly one line changes, `surface_sha256`. Nothing else in the file moved.

## Not checked

- **The two Playwright specs were not run in this worktree.** This sandbox has no Playwright browser cache and no system Chromium, and is network-restricted, so `e2e/scripts/resolve-chromium.sh` has nothing to resolve. The orchestrator ran both specs on the same content and it was that run which caught finding 1. **Findings 2, 3 and 4 are therefore reasoned and code-level, not browser-confirmed** — they should be re-verified by an e2e run before merge, in particular that the catalog spec still passes with `paintStatus`'s arming behaviour (traced by hand: `bind()` → `fire()` → first paint arms and leaves the region empty; the spec's first assertion comes only after a real chip click, which is the second paint and does write).
- **No screen reader was driven.** The announcement behaviour is argued from the DOM-mutation semantics of `aria-live`, which is the right model but is not the same as hearing NVDA/VoiceOver/Orca say it. The load-time announcement in finding 2 is a well-established antipattern rather than something measured here.
- **Not run on the real pilot tablet**, and no visual check was performed — deliberately, since the diff adds no visible element.
- **The full `go test ./...`** was not run; the gate below covers `./internal/pages/...` and `./internal/httpx/...`, the only packages this diff touches.

## Manual / help-topic decision

**No `web/help/` update is needed, and this is a deliberate decision rather than an omission.** The standing rule (ut-docs#324) is that anything a shop owner *sees or does* which a change adds, removes or alters ships with its manual topic in the same branch. This change adds no control, removes none, alters no step, and changes no rendered pixel: both new elements are `.visually-hidden`, and the server-side change swaps one internal suppression mechanism for another with identical user-visible behaviour on all six destinations. What changes is only what assistive technology *announces* about controls the manual already documents — there is no new step to write down, and the existing topics' descriptions of the scope chips and the category filter remain accurate word for word. `guard-help-topics.sh` (route coverage, no new page route added) and `guard-help-drift.sh` both pass unchanged.

## Verdict

**Safe to merge, conditional on an e2e re-run.** The core mechanism is sound and is a genuine improvement on what it replaces: the guard now lives in the one place all six destinations funnel through, the failure direction is provably the harmless one, the header can only ever narrow what the server sends and cannot widen it past the per-request visibility filter, and the fail-open property is pinned by a test the previous mechanism could not have passed. Mutation testing confirms both headline tests are real.

The accessibility half of the card was the weaker half and is where all three defects were: it shipped announcing the wrong label on one surface, announcing unprompted on load on the other, and with a test that could not tell a working implementation from an inert one. All are fixed. Because this sandbox cannot run Playwright, the two fixes that were *not* the orchestrator's own browser-confirmed finding should be re-verified by an e2e run before the merge — that is the one gap between this verdict and an unconditional one.
