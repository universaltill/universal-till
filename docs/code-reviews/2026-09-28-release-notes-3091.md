# Review — in-app release notes (ut-docs#3091)

Date: 2026-09-28 · Lane: cloud-24 · Author: Opus 5.5 (dev subagent) · Reviewer: Fable (independent) · Tester: Opus 5.5 subagent

## What shipped

- `web/release-notes/<locale>/vX.Y.Z.md` (en base + de/ar/fa/tr), embedded as
  `web.ReleaseNotesFS`; `internal/releasenotes` loads, semver-sorts, falls back
  to English per note, renders with goldmark (raw HTML omitted). Seed note:
  v0.30.6.
- Settings → **About** card (`#settings-about`, sidebar row after Software
  update): installed version, first start on this till, and What's new (the
  running version plus up to four older notes; never a newer one).
- `app.version` / `app.version_first_run_at` recorded at boot; a fresh install
  seeds `release_notes.seen_version`. All three are per-till settings
  (`PerTillSettingPrefixes`) — every till runs its own binary.
- Status-bar chip "Updated to vX — see what's new": `settings` permission only,
  never on the self-order kiosk, never blocks selling. The link POSTs
  `/api/release-notes/seen?open=1` then `HX-Redirect`s to About; × dismisses.
- `scripts/ci/guard-release-notes.sh` (+ `_test.sh`, in ci.yml): `release.yml`
  `prepare` refuses a tag without `web/release-notes/en/<tag>.md`, on both the
  tag-push and dispatch paths (before the tag is created). The goreleaser job
  passes it as `--release-header`; the generated list sits under
  "Technical changes". `RELEASING.md` documents writing the note first; the
  ut-docs devops skill gains the same rule (ut-docs PR, same card).
- Manual: "What's new in each version" in `web/help/*/updates.md`;
  screenshots regenerated (`make docs-shots`, 124/124).
- New locale keys (en/ar/fa/tr): `settings.about.{title,installed_version,
  first_run,whats_new,english_only,no_notes}`,
  `status.release_notes_{updated,dismiss}` — de/es packs follow in the same cycle.
