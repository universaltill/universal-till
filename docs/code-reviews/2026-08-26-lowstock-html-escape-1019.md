# Code review: GetLowStock success-path HTML escaping (ut-docs#1019)

## What shipped

`GetLowStock`'s HTML/htmx success path (`internal/pages/inventory_api.go`)
built its `<table>` response with `fmt.Sprintf`, interpolating
`item.Name`, `item.SKU` and `item.LocationName` with no escaping. These
values come from persisted catalog/location data (set via catalog admin
or an import), not an immediate request-echo — stored-XSS-shaped rather
than reflected: a catalog item or location name containing markup would
render unescaped into an authenticated operator's low-stock table.

This is the same missing-escape class ut-docs#1000 already fixed for this
file's *error*-response branches (via the shared `errorHTML()` helper);
this ticket covers the distinct success-path call site #1000 deliberately
left out of scope.

**Fix:** wrap all three string fields in `html.EscapeString(...)` at the
interpolation point. The handler's local accumulator variable, previously
named `html` (shadowing the imported `html` package within that function
scope), was renamed to `tableHTML` so `html.EscapeString` unambiguously
resolves to the stdlib package. Numeric fields (`CurrentQty` `%.2f`,
`ReorderLevel` `%d`) are untouched — correctly, since they're not
attacker-controlled strings.

## Test added
