# Review — no-sale drawer opens on the EOD/Z report (ut-docs#5753)

**Date:** 2026-11-07 · **Branch:** `feat/5753-eod-no-sale`
**Author model:** Sonnet (dev subagent) · **Reviewer model:** Opus 5.5 (independent subagent, separate detached worktree for every revert-and-rerun)

## What shipped

- `data.EODReport` gains `NoSaleCount` and `NoSaleOperators` (`no_sale_count`,
  `no_sale_operators`, both `omitempty`, so older archives and zero days
  are unchanged).
- Four readers in `internal/data/no_sale_repo.go` over `no_sale_events`
  (#2558):
  - `NoSaleCountForDateRange` uses `local_date BETWEEN`.
  - `NoSaleCountForInstantWindow` uses the half-open `instantWindow` on
    `created_at`, with a zero `from` meaning unbounded.
  - `NoSaleOperatorsForDay` / `NoSaleOperatorsForInstantWindow` group per
    actor. The name falls back the same way as `OperatorSalesForDay`:
    display name, then username, then raw id, then `""`. Rows are ordered
    by count desc, then name, then id.
- They are wired into `dateRangeSummary` (per-cashier on a single day only,
  like Operators) and `dateRangeSummaryInstant`. Same window as
  `ClearedBasketCount` (#1122), and every till's opens are counted (replica
  opens once they are journaled, #3562). Each read is best-effort: an error
  leaves the field empty and never fails the close.
- Printed Z (`buildEODDoc`): a **NO SALE (DRAWER OPENS)** footer section
  with the total, then one `footerRow` per cashier ("Unattributed" for no
  actor). It is omitted at zero and never touches `doc.Totals`.
- Reports → Day-end (EOD) archived detail (`reports_page.go`,
  `reports_tab_eod.html`): a "No sale (drawer opens)" table behind the
  same `eod_report` gate as Operators. A no-sale-only archive still opens
  the detail row.
- 5 `en.json` keys with `en.meta.json` metadata, and a help paragraph in
  `web/help/en/reports.md`.

## Findings

| # | Severity | Finding | Outcome |
|---|---|---|---|
| 1 | should-fix | The "a no-sale failure never fails the close" contract had no test. A later edit could turn the best-effort read into `return rep, err` and silently block the EOD close. | **Fixed:** `TestEndOfDay_NoSaleFailureNeverFailsClose` renames the table away and asserts both the date and the instant paths still produce the report. |
| 2 | should-fix | `TestNoSale_LocalDayBoundary` passes on a UTC host even when `local_date` is replaced by `date(created_at)`. CI is UTC, so it was vacuous there (Tester's M7). | **Fixed:** added `TestNoSale_DateWindowUsesLocalDateNotUTCDate`. It seeds an open whose `local_date` is ahead of its UTC date (a shop east of UTC), so it fails under `TZ=UTC` too. The old test is kept. |
| 3 | must-fix (UX M1) | The help named a tab that doesn't exist ("Reports → End of day"). | **Fixed:** "…in that day's detail on the **Day-end (EOD)** tab of Reports." |
| 4 | should-fix (UX S1) | A several-day archive showed an Operator \| Opens header over a lone Total row. | **Fixed:** `<thead>` is now inside `{{ if .NoSaleOperators }}`, with `TestReportsPage_EODRowNoSaleRangeHasNoOperatorHeader`. |
| 5 | should-fix (UX S2) | The help bolded a **No sale** button that core doesn't ship yet. `git log origin/main` has no #3560 or "no sale" commit, and no `web/ui` control exists. | **Fixed:** reworded to "opened without a sale (a "no sale")". Bold the label once #3560 lands. |
| 6 | minor | Suppose a replica's open is stamped before the main till's close but journaled after it. On the close-to-close (instant) path it then falls into a window that has already closed, so it appears on no Z report. Replica sales and every other journaled stream have the same pre-existing limitation (ADR-0066 windows on `created_at`). | **Accepted, out of scope:** pre-existing and systemic, not introduced here. Deferred, see below. |
| 7 | nit | The count and the per-cashier rows are two reads outside a transaction. An open written between them would make the per-cashier sum one higher than the total. Operators and the totals have the same pattern. | **Accepted:** the window is milliseconds, the field is informational, and no money is involved. |
| 8 | nit | On screen the table sits after "By operator", while on paper it comes after CLEARED BEFORE PAYMENT and before the cash count. | **Accepted:** each placement is sensible for its medium (UX). |
| 9 | nit | The instant predicate `datetime(created_at)` is not sargable. | **Accepted:** the table is small, and `cleared_baskets` and sales use the same predicate. |

Checked and found clean:
- Raw SQL appears only in `internal/data`.
- Counts are `int` and no money is involved.
- No hardcoded user-facing strings; every new key has meta.
- CSS is logical only (`text-align:end`).
- No fixed test date within the 60-day window (`2026-10-14` and `2026-01-01` are in the past, and the guard looks forward).
- No new file writes and no cwd-relative paths. Neither of the two recurring bugs applies.
- No double counting: an open sitting exactly on the boundary goes to the next close (`TestGenerateEOD_NoSaleWindowsAbut`, `TestNoSale_InstantWindowHalfOpen`).
- Archive JSON without the fields renders unchanged (`TestReportsPage_EODRowOmitsNoSaleWhenAbsent`).
- No real shop or person names in the test data.

## Deferred

- The till's own on-screen live report line for no-sales (the #3560 lane) is
  out of scope here. The help can bold the **No sale** label once that button ships.
- Opens and sales a replica journals after the main till's close, but stamped
  before it, never reach a Z on the instant path (finding 6, pre-existing for
  every journaled stream). This needs a Backlog card if one doesn't already exist.
- The screen and the paper print the sections in a different order (finding 8),
  left as is.
- No 58 mm (32-column) print mode exists. This was already true before this
  change, and the change adds nothing new to it.
