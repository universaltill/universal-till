# Code review: till → cloud config report (ut-docs#2472)

**Change:** `internal/pages/cloudsync_wire.go`. The heartbeat's `DeviceExtra` also carries `categories`, `modifier_groups`, `kitchen_stations` (id + name only), `currency` and `currency_decimals`. This is the read side of ADR-0095 Decision 2, so the cloud manager can show and later edit the shop's menu configuration. Companion: ut-cloud `docs/code-reviews/2026-09-23-config-report-2472.md`.

**Built by:** Fable (dev subagent). **Reviewed by:** Opus (independent subagent, detached worktree, mutation checks). **Tested:** a live end-to-end run with a real till syncing to a local ut-cloud.

## Findings and outcome
| # | Severity | Finding | Outcome |
|---|---|---|---|
| 1 | should-fix | A read error sent `[]`; the cloud stores an empty list as "none", so one busy read wiped the portal's copy | **Fixed.** Report funcs return nil on error; `configReportGate` then omits all three keys ("keep what you have"). `TestRemoteConfigReport_ReadErrorOmitsKeys`, mutation-verified (fails with the old `[]`). |
| 2 | should-fix | A large menu could push the sync body over ut-cloud's new 4 MiB cap → every sync refused → the till also loses its directives | **Fixed.** Till-side count caps match the cloud (1000/500/100/500/200); a 1 MiB byte budget omits the lists with a warning; lists are sent only when their SHA-256 changes, or every 30 min so a cloud that lost its copy recovers. `TestRemoteConfigReport_OverBudgetOmits`, `TestRemoteConfigReport_SentOnlyWhenChanged`. |
| 3 | should-fix | Price deltas mis-scaled on the cloud for PKR (CLDR 0 vs till 2) and IRT (not ISO) | **Fixed.** The till sends `currency_decimals` from `httpx.CurrencyByCode` (the till's own table). Prices stay integer minor units; display divides by 10^decimals (the original money decision). `TestRemoteConfigReport_CarriesCurrency`. |
| — | nit | Raw SQL (`UPDATE categories SET parent_id`) in a `_test.go` | Accepted: 6 existing precedents in this file; tests are exempt from `guard-data-access.sh`. |

The reviewer confirmed that no printer address or destination leaves the till (mutation M2), the per-group items cap + `items_total` (M11), and currency present (M12).
