# Review: shellcheck version guard drops 0.9.0 (ut-docs#5208)

**Date:** 2026-10-31 · **Lane:** `lane:cloud-41` · **Card:** ut-docs#5208 (follow-up to ut-docs#5207)

## What shipped
- `scripts/ci/guard-shellcheck-version.sh`: `ACCEPTED_VERSIONS=("0.11.0")`. 0.9.0 (Ubuntu 24
  image) was accepted only while ubuntu-latest's 24→26 migration was mixed.
- `scripts/ci/guard-shellcheck-version_test.sh`: 0.9.0 is now an `expect_fail` case; the
  exact-match near-miss cases moved to the accepted version (`0.11.0-rc1`, `10.11.0`) so they
  still prove a prefix/substring compare would be caught.

## Evidence the migration is complete
Every readable `ci` `build` job from 2026-10-30 23:59Z to 2026-10-31 04:31Z (11 of 11; a 12th
had no downloadable log) ran image `ubuntu-26.04` 20261025.179.1 with shellcheck 0.11.0. None ran 0.9.0.

## TDD
The new test run against `origin/main`'s guard fails on exactly one case ("expected guard to reject
the dropped Ubuntu 24 version (0.9.0)"). Against the new guard all 9 cases pass. Re-run by the
orchestrator, not only by Dev.

## Independent review (different model from the author)
No blocker or major findings. Checked: `shellcheck scripts/ci/*.sh` 0 issues (0.11.0),
`guard-ci-tests-sandboxed.sh` OK (the test writes only to a `mktemp -d` and `/tmp`), no other
reference to accepting 0.9.0 anywhere, and no workflow runs this guard on a pinned Ubuntu 24
runner (only `ci.yml` `build`, `ubuntu-latest`).
- Nit, accepted: messages still say "one of" with a single version. They stay correct if a version is added later.
- Nit, accepted: the `0.10.0` case is now partly redundant. It is harmless, and its label was updated.

## Risk
If GitHub ever moves `ubuntu-latest` back to 24.04, `build` goes red. That is the guard's
intended loud failure.

**Verdict:** safe to merge.
