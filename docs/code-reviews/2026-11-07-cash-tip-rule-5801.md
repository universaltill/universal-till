## What shipped

- The rule: expected drawer cash **includes** cash tips, while "cash sales" **never** includes them. On every view, `Opening + CashSales + TipsHeldOut + Adjustments == Expected`. No `expected_cash` value changes.
- `internal/data/shift_cash_repo.go` (new) adds `ShiftCash` (`money.Money` fields) and `POSRepo.ShiftCashBreakdown(ctx, shiftID, opening)`. This is the shift-scoped primitive, and X report #5796 will reuse it.
- `internal/data/pos_repo.go`:
  - The private `shiftCashWindow` helper now holds the FROM/WHERE and args shared by `SumCashPaymentsForShift` and the new `SumCashTipsForShift`. The two sums therefore cannot use different windows.
  - `ComputeExpectedCash` now wraps `ShiftCashBreakdown(...).Expected`.
  - The `CashReconciliation` doc comment points to the rule.
- Doc comments only: `internal/pos/shifts.go` `ComputeExpectedCash`, and `internal/data/sales_aggregate_repo.go` `SalesAggregatePayment.ExpectedCash`. The second now says the value is cash takings minus cash tips, not drawer cash. The wire name is unchanged.
- Tests:
  - `shift_cash_repo_test.go` (new) covers the BA AC2 fixture, the no-tip case and the window parity.
  - `TestCashTipRule_ShiftBreakdownMatchesEOD` checks the shift breakdown against the EOD `CashReconciliation`.
- ut-docs:
  - `architecture/end-of-day-report.md` gains a "Cash tips (ut-docs#5801)" section.
  - In `reference/design-5780-x-report.md`, the Cash block now uses the primitive and has a Tips held out line. The "deferred" note is gone, the line reuses the existing key `reports.zpaper.cash.tips_held_out`, and AC1 now includes a cash tip and asserts the identity.

Checked and found clean:
- **Money.** `ShiftCash` uses `money.Money`. Conversion happens only at the scan boundary (`money.FromMinor`) and on return (`.Minor()`).
- **NULL handling.** An open shift has `closed_at` NULL, so `Valid` is false and the window has no upper bound, as before. An empty shift id is an error, as before. An unknown shift is a `query shift` error, as before.
- **Repository pattern.** All SQL is in `internal/data`.
- **Fixtures.** The new tests use dates in `2026-01-01`, outside the 60-day window. The EOD test uses `cashReconAnchor`.
- **Test data.** No real shop or person names appear.
- **The two recurring bugs.** There are no file writes and no cwd-relative paths, so neither applies.
