## Findings
1. HIGH, fixed (cloud): outbound push could gross up a non-taxable price. Inbound kept 10.00, but the link baseline recorded the channel's own tax basis, so when channel and store bases differ the outbound build converted 1000 to 1200, pushed it, and the next pull compounded it. Fix: `effectiveChannelTaxIncluded` records the store basis in the baseline for NonTaxable rows (both the first save and the change comparison), so outbound sees equal bases and never converts. Test added.
2. MEDIUM, fixed (cloud): gallery PUT If-Match was checked outside the transaction. Now re-checked inside it, and a unique-constraint clash from a concurrent writer maps to 412 version_mismatch instead of 500.
3. LOW-MEDIUM, fixed (cloud): a run whose only news was failed image fetches was marked quiet (hidden by default, pruned after 3 days). `quiet` now also requires FailedCount == 0.
4. LOW, fixed (my.), Tester defect: RTL run-table sentence scrambled; count cell now `dir="auto"`.
5. MEDIUM, open (cloud, flags default off): a channel gallery change overwrites the owner's non-primary gallery/alt edits (baseline compares only the primary sha). Needs a gallery digest in the baseline; must land before CATALOG_GALLERY_ENABLED + CHANNEL_INBOUND_IMAGES_ENABLED go on.
6. MEDIUM, open (cloud, flags off): a permanently failing image is refetched every pull and, via `return` at the budget check, can starve later items (50-fetch budget). Needs a bounded retry record and per-item `continue`.
7. MEDIUM, open (cloud): `status=review` runs filter scans in Go over at most 10x100 rows and sets no cursor when the scan budget ends, so older review runs can be unreachable; also `quiet_hidden_count` ignores the status filter. Fine at current volume (Tester: 8 ms at 3000 rows); move to a SQL column when retention grows.
8. LOW, open: retry-directive is not atomic (double click can queue twice); `convert.go` `ImageIndex > 0` should be `>= 0`; gallery PUT can return 402 after the rows committed (single-image handler has the same order); status GET runs a write (DismissStaleFailures) and ignores its error; limit>50 clamps silently while the error text says 1 to 50.
9. PROCESS, open: no end-to-end run of my. <-> cloud <-> till or plugin <-> cloud (Tester); Shopify dev-store proof not re-done. Run once on staging with the flags on before enabling.

## Verdict
Approve for merge with flags at their defaults (CATALOG_GALLERY_ENABLED off, CHANNEL_INBOUND_IMAGES_ENABLED off, gift-card off, on_demand plans empty). Findings 5 and 6 are blockers for switching the gallery/inbound flags on; findings 7 to 9 are Backlog.
