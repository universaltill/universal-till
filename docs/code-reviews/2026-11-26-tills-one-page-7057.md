# Review: one Tills & devices page (ut-docs#7057)

Reviewer: Opus 5.5 subagent (independent of the Sonnet 5.5 author), read-only on the worktree, plus the author's own re-run of gates.
Pre-flight: build, vet, gofmt, guards (i18n, i18n-meta, rtl-logical-css, help-topics, compliance-claims, no-showmodal, no-native-confirm, mail-addresses) green; docs-shots regenerated with `make docs-shots` inside the Linux image (guard-docs-shots green).

## What shipped
Five-tab page on /tills, reconciled list (internal/tills), bulk/one-tap stale removal, flag + replace for a pair request whose name is already enrolled, help topic, CSS, e2e. ADR-0216 (Proposed) in ut-docs.

## Findings
1. CRITICAL, fixed: the merge joined the account list on `device_id`, but the account's device id is the marketplace identity ("till-<uuid>") and the local till id arrives as `till_id`. Every till would have shown as local-only and the bulk Remove would have deleted them all. Fix: `enroll.Device.TillID`, join on it, account role words (primary/replica) normalised, and a cloud row with no till_id makes the list ambiguous so nothing is marked stale. Regression tests in internal/tills/reconcile_test.go.
2. HIGH, fixed: bulk Remove ignored how recently a till was seen and recomputed the list at submit. Now it only offers, and only removes, tills that are stale AND unseen past 24 h AND whose ids were posted from the confirm text. Test covers unconfirmed, recently seen and confirmed.
3. HIGH, fixed in the final round (see Final round):  the replace-on-same-name decision uses the name the device types at /api/sync/enroll, not the name the manager approved. Mitigations added: live window 2 min -> 15 min, the last-seen check is repeated inside the UPDATE (ErrTillStillLive -> 422 name_taken), and the replaced till keeps its own role (a satellite keeps its TLS-only rule; no pin drop by a role swap). OPEN: binding the approved name into the enrolment token needs an architect decision (tokens carry no name today). A valid token is still needed, so this is not an unauthenticated takeover.
4. MEDIUM, fixed: the joined till's own row used the main till's name; now the device's own name.
5. LOW, fixed: the Change key refusal element (`tills-network-key-error`) did not exist (pre-existing at HEAD); added.

## Final round (combined Tester + combined Reviewer over the whole diff, after merging main with #3428)
Reviewer (Opus 5.5, changes requested) and Tester findings, all fixed unless listed under Deferred:
- IMPORTANT, fixed: a replace kept the enrolled till's role, so a satellite name could be replaced over plain HTTP and the bearer returned in clear (ADR-0114 section 7). The enrol handler now refuses a satellite name over plain HTTP before the token is spent. Test added.
- IMPORTANT, fixed: replace was decided by the name typed at enrol. It now needs a manager-approved pair request for exactly that name (`PairingRepo.NameForToken`); a typed pairing code, or a token approved for another name, never replaces a till. The unseen window is 24 h (was 15 min). Tests added.
- MEDIUM, fixed (Tester): a till that had never connected counted as unseen for ever, so a tablet enrolled minutes ago could be bulk-removed; ReplaceEnrolment also reset last_seen to NULL. Never-seen now counts from `enrolled_at` (SQLite datetime layout parsed), replace stamps last_seen. Tests added.
- IMPORTANT, fixed: help text (name-in-use and re-join wording, "Settings -> Tills" paths, network key location, account comparison only when the account reports till ids).
- NIT, fixed: the invisible 44px hit area is scoped to the Tills page; the tab panel has a stable aria-label.
- e2e added: approving a pair request from an enrolled name replaces that till (same till id, new bearer, one row). The #3428 scan specs now open the join form on the Add a till tab.
