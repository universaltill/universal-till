# Review — slot-gated /menu tiles (ut-docs#3982)

**Date:** 2026-10-09 · **Author:** Sonnet (dev subagent) · **Reviewer:** Opus 5.5 (fresh context, independent worktree)

## What shipped

#3973 gates a content-slot plugin page entry's route by its slot's host
screen, but `/menu` still drew a tile for every page entry — a cashier saw
a `reports.panels` entry's tile that answered 403, and a
`setup.wizard.steps` entry's tile answered 403 for everyone.

- `data.ListMenuEntries` reads `config_json`'s `content_slot` into
  `MenuEntryRow.Slot` (same parse as `ListPageEntries`; malformed = none).
- `plugins.MenuPlugin.Slot` → `common.MenuItem.Slot` (`BuildMenu`).
- `menuSlotEntries` gives a slot entry the core-derived
  `VisibleIf = "plugin_slot:<slot>"`; `menuVisibility.visible` resolves it
  through `pluginSlotGates` (init-assigned indirection — a direct
  reference is an init cycle via `admin.pages` → `visibleAdminEntries`).
  Unknown/ungated slot → no tile (fail closed). Plugins can't author
  `VisibleIf` (amendments have no such field).
- Docs: `docs/plugin_guidelines.md`; ut-docs `reference/plugin-views.md`.

never writes `VisibleIf`; no new shared state.
