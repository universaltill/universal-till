# Code review — iOS: focusing a field zooms the till in; pages pinch-zoom (ut-docs#3350)

Date: 2026-10-01 · Branch: `fix/3350-ios-input-zoom` · Lane: `lane:cloud-54`
Author: Opus 5.5 · Reviewer: Fable (independent subagent, fresh context)

## What shipped

- **iOS app shell** (`ios/UniversalTill/TillWebView.swift`): a `WKUserScript`
  (document end, main frame only) sets the viewport to
  `width=device-width, initial-scale=1, maximum-scale=1, user-scalable=no`.
  WKWebView honours those limits (`ignoresViewportScaleLimits` stays at its
  default `false`), so the app neither pinch-zooms nor zooms in when a field
  takes focus, in any orientation. Safari users keep pinch (only the app
  shell sets this).
- **Web, phone tier** (`web/public/app.css`, ≤480px): typed-into fields are
  at least 16px — the threshold under which iOS WebKit zooms on focus — so
  Safari and the home-screen web app don't zoom in portrait either. The
  selector uses `:where()` to stay at element specificity, so class rules
  that size a field larger (the setup wizard's 1.05rem) still win; the
  basket's `.qty-input`/`.disc-input` (class-sized below 16px) are named.
- **Guards**: `e2e/tests/phone-input-no-zoom-3350.spec.ts` (24 routes + the
  basket line at 390px; each route must answer 2xx and render ≥1 field so it
  can't pass vacuously) and `scripts/ci/ios-webview-zoom_test.sh` (wiring
  test for the Swift lock, self-tested against 5 broken fixtures; wired into
  `ci.yml`'s build job; `ios-ci.yml` compiles the Swift on this PR).
- `ios/README.md` note; docs-shots surface hash refreshed (screenshots are
  taken at 1024×600, where the ≤480px rule changes no pixel).

## Findings

| # | Severity | Finding | Outcome |
|---|---|---|---|
| 1 | should-fix | The first selector `input:not(...)×4` had specificity (0,4,1), so it shrank fields a class rule sized larger — every setup-wizard text input dropped 17.85px → 16px at 390px, mismatching its selects. | Fixed: `input:where(:not(...))` (0,0,1), plus `input.qty-input, input.disc-input` so the basket fields still reach 16px. Basket case added to the spec. |
| 2 | should-fix | Spec passed vacuously for a route that 404s or renders no field. | Fixed: asserts `resp.ok()` and ≥1 measured field. This exposed four routes (`/`, `/import`, `/my-reports`, `/orders`) with no visible field at 390px — removed; `/` is covered by the basket case. |
| 3 | nit | The ≤480px rule is portrait-only; Safari in landscape can still focus-zoom. | Accepted: comments now say "in portrait". The app shell (the reported surface) is orientation-independent. |
| 4 | nit | Wiring test greps were single-line brittle and the `ignoresViewportScaleLimits = true` regex too narrow. | Fixed: separate greps per argument; any non-comment use of `ignoresViewportScaleLimits` fails (awk, not a `grep -q` pipe — pipefail guard). Extra fixture for `.atDocumentStart`. |

Reviewer judged the Swift approach sound for iOS 16–26 (focus zoom is
clamped to the viewport's maximum scale; HTMX swaps never touch `<head>`;
standalone pages are full loads so the script re-runs) and advised against a
native pinch-recognizer belt (WebKit resets it).

## Verified beyond automated tests

- TDD: with `web/public/app.css` reverted to `origin/main`, the spec fails 13
  of 25 (e.g. `/catalog/tax-codes` `input[rate] 13.9px`, basket
  `input[qty] 14.4px`, `input[discount] 13.6px`); with the fix, 25/25 pass.
  Reproduced independently by the reviewer in a separate worktree.
- `ios-webview-zoom_test.sh` fails on the pre-change Swift and on every
  broken fixture.
- All phone/basket/login specs on a fresh build: 187 passed.
- Screenshots at 360px of `/users`, `/` and `/tills` looked at: fields
  render at 16px, no sideways scroll.
- CI build-job guards run locally: all pass except `guard-shellcheck-version`
  (local shellcheck 0.11 vs pinned 0.9) and `guard-deadcode-baseline`
  (skips the GTK desktop root without its headers) — both environmental,
  no file in this diff involved.

**Not verified:** on a real iPhone — no device in a cloud lane. The Swift is
compiled and smoke-launched by `ios-ci.yml`; the on-device check (focus the
Change-PIN field, pinch) is left for the owner's next TestFlight build.
`/pin` itself needs a logged-in session (303 on the auth-off e2e till); it is
plain `label > input` markup, covered by the same rule.
