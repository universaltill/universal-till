# Review — sign the .dmg itself (ut-docs#2870)

**Why:** v0.25.0 (run 36221557677) was the first release with notarization:
Apple **accepted** submission `c2b1c51a-e452-4ba0-9c4e-e7e7648f7134` (~28 min)
and stapling succeeded, but the job's own final check
`spctl --assess --type open --context context:primary-signature -v "$DMG"`
rejected the image — `source=no usable signature`. Only the `.app` inside was
signed; Gatekeeper assesses a disk image by the image's own signature. With
#2917 the rest of the release published and no un-assessed `.dmg` was
attached.

**Change:** `packaging/macos/make-dmg.sh` code-signs the `.dmg` with the
Developer ID (`codesign --force --timestamp --sign "$MACOS_SIGN_IDENTITY"`,
then `codesign --verify --strict`) right after `hdiutil create` and before
notarization — Apple's documented flow (create → sign → notarize → staple →
assess). No hardened runtime (not applicable to a disk image). Static test
`TestMakeDmgSignsTheDiskImageBeforeNotarizing` pins the order (failed first).
Author: Opus 5.5. Reviewer: Sonnet.

**Reviewer:** OK — matches Apple's flow; `make-dmg.sh` runs in the same
`macos-app` shell after the signing keychain is unlocked, on the search list
and partition-listed for codesign, so the identity resolves exactly as in
`build-app.sh`; stapling after signing needs no re-sign. Nit: the test pins
text order, not execution — accepted (narrow change).

**Verification:** `go test ./packaging/`. Real proof = the next release's
`macos-app` passing `spctl` and attaching the `.dmg` (then close #2870).

**Verdict:** safe to merge.
