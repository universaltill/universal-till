# Review: till-styled confirm for hx-confirm (ut-docs#5524)

**Change.** Every `hx-confirm` on a till surface now asks in the till's own in-page dialog `#ut-confirm` instead of the WebView's native "The page at http://127.0.0.1 says:" box. The same goes for the jiggle-mode remove question in `app.js` and the inline-actions `data-submit="confirm"` step (tables release).
- New `web/public/till-confirm.js`. It exposes `UT.confirm(q,{tone,ok,opener})`, which returns a Promise, and registers one `htmx:confirm` listener that calls `issueRequest(true)` after Confirm.
- The dialog shell sits in `base.html`. It is `.show()` over `#ut-scrim`, never `showModal`, and the script is added to `HeadAssets`.
- New key `common.confirm` with its meta.
- Three tills sites carry `data-confirm-tone="neutral"` (role change, update now, network key). Every other site is danger: red Confirm, focus on Cancel.
- The 22 e2e specs that used native dialogs now go through `answerTillConfirm` / `noNativeDialogs`.
- `app.js` `stayInEdit()` now counts `#ut-confirm` as inside edit mode, so a tap on Confirm no longer ends jiggle mode.

**Pipeline.** BA, Architect (Opus 5.5) and UX ran before code. Dev was Sonnet 5.5 and TDD-first: the three Go tests and the new spec were red before the implementation. Tester and Reviewer (Opus 5.5) were each a separate agent.

## Findings
| # | Sev | Finding | Outcome |
|---|---|---|---|
| M1 | medium | `till-confirm.js` close handler: the queued `close` event of an answered question cancelled a question opened from its `.then`. | **Fixed**: `if (!dlg.open) settle(false)`. New spec "a question chained after an answer stays open" is red without the fix and green with it (re-verified by the orchestrator). |
| L1 | low | The opener was taken from `document.activeElement` even when focus was outside the request's element (a search box). Cancel then refocused the wrong field and the poll guard watched it. | **Fixed**: `activeElement` is used only when `elt` contains it; otherwise submitter, then `elt`. |
| L2 | low | inline-actions `utConfirmed` could outlive a `requestSubmit` that failed validation, skipping the next question. | **Fixed**: cleared in `try/finally`. |
| L3 | low | The poll guard cancels in the bubble phase, after inline-actions' capture hook set busy state. It has no effect on the roster today. | Accepted; noted for #6116. |
| I1 | info | `data-confirm-ok` is implemented but unused. | Accepted, for #6117. |
| T1 | — | Tester: at ≤480px Lock is in the closed nav drawer, and `#ut-scrim` covers the drawer toggle, so Lock can't be reached while *any* scrim popup is open. This predates the change; the native confirm blocked everything anyway. | Deferred → ut-docs#6118. |
