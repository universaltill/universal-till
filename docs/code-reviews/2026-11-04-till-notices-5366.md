### `more` and the cap: defined behaviour

The cloud lists at most 20 live items per device, critical first, newest
first (ADR-0176 §4), and sets `more: true` when it held some back. The wire
contract has no cursor, so the till cannot fetch the rest; what it can do it
now does: it never lets the cap cost a critical (it sorts the way the cloud
should have before truncating), and it logs the overrun with counts only.
Keeping the live set per device under 20 is the sender side's job (the
admin UI's recipient preview, slice 2).

## Verified beyond the automated tests

- **Mutation, inline (revert → run → restore, one turn each):** eight
  mutations, every one failed on exactly the claimed assertion: `controlFree`
  always true; the 30-day start rule removed; the partner-critical refusal
  removed (Dev's claim); `SortForCap` removed; `reported_at` stamped with the
  response time; the item byte cap removed; `CAST AS BLOB` reverted; the
  `notices.view` gate forced open (Dev's cashier-403 claim).
- **Rendering:** `RenderBody` escapes first, pulls links out through a NUL
  token (NUL is stripped from the body before tokenising), escapes link text
  and URL exactly once, re-checks the URL with `safeHTTPS`; emphasis regexes
  run on escaped text only; titles, sender names, labels and `aria-label`
  go through `html/template`'s contextual escaping; a stored `link_json` only
  becomes an `<a>` through `ParseLink` → `checkLink` at render time; `route`
  targets are an allow-list; `https` opens with `rel="noopener noreferrer"`.
- **Gates:** `/notices`, `/notices/{id}/row|read|dismiss|ack` → 404 with the
  flag off, 403 without `notices.view`; the ack also needs `IsManager()`;
  bell/toast answer empty without the permission; the strip is the one
  read-only exception and filters `sender_kind = 'platform'` in SQL as well
  as refusing a partner critical in `Validate`. The three poll routes were
  added to `backgroundPollPaths`/`shellGetPaths`, not to the auth-exempt
  list. Demo mode denies every route. `/notices` is reserved from plugin
  pages.
- **Flag-off invisibility and erasure:** no `notices` object, no GET
  parameter, no bell, 404 inbox; turning the switch off deletes every row
  and forgets `notices.rev`/`notices.lang`.
- **Memory bounds:** 100 rows / 256 KiB (bytes now), eviction rank read →
  expired → unread non-critical → unread critical, oldest first within a
  rank, matches ADR §3; in memory only the `have` hash, rev and one item.
- **Offline-first / never block:** no handler touches the basket or tender;
  the sell path never reads `cloud_notices`; no `showModal`, no overlay,
  no `role="alert"`; the toast poll is cancelled while `#payment-overlay`
  is open and the toast is only marked shown when rendered; the strip is
  in flow and stays. The mid-sale e2e completes a tender with the strip up.
- **Sync:** `have` = sha256 of sorted `id:rev`; `unchanged` keeps the store;
  a language change resets `have`/`rev`; the GET carries `notices=<rev>`
  only with the flag on; a 304 with a pending ack still POSTs; below
  64 MiB `MemAvailable` the pull is skipped and `have` kept; a malformed
  block never fails the tick; a failed `Mirror` leaves the cursor so the
  next pull retries.
- **Migration 096:** new table + `INSERT OR IGNORE` permission rows only,
  `IF NOT EXISTS`, checksum pinned in `shipped_migrations_test.go`; safe on
  an installed till. `cloud_notices` and `notices.*` are excluded from the
  admin bundle (per-device data).
- **i18n:** every new key in `en.json` with meta (English only, ADR-0160 §2); `guard-i18n`,
  `guard-help-topics`, `guard-rtl-logical-css`, `guard-no-showmodal`,
  `guard-data-access`, the e2e guards and shellcheck pass locally;
  `gofmt`, `go vet`, `golangci-lint` (0 issues).
- **UX fidelity:** bell in `.nav-right` above Help/Sync with a 56 px hit
  area; "9+" cap; square badge with a triangle on an unread critical;
  phone burger badge with a count-aware label; one `.pos-notice` surface
  with `.important`/`.critical`; info never pops up; 10 s pausable toast at
  the top of the products pane; strip on every page until acknowledged;
  cashier strip two lines, no button, no link; rows ≥ 64 px that expand in
  place; glyph shape + word + 6 px bar; server-rendered sender chip with a
  dashed partner treatment; Acknowledge instead of Dismiss on critical;
  empty state with no CTA; reduced-motion rule. Deviations: no Past tab
  (finding 15), `aria-live="polite"` without `role="status"` (equivalent).
