## What shipped

The item editor's tab strip is now Details · Variants · **Modifiers** · Item
image · Labels · Keypad. The Modifiers panel (`#item-form-panel-modifiers`)
hosts `#item-modifiers-list` inline: the item's own groups with detach
(#2330, attach-only), the attach-existing multi-select, the
category-inherited groups with skip/use-again (#2284) and the
"Go to Modifiers" way out (#2379). The nested `#modifier-groups-modal`
dialog, the Variants-panel summary line and the "Manage Modifiers" button
are gone, with their CSS. `renderModifierMutationResult` now answers the
item fragment for any `Hx-Target` other than `modifiers-list`, since the
Variants fragment no longer shows modifier state. `/modifiers` item chips
deep-link to `/catalog?item=<id>&tab=modifiers`; `showItemFormTab` parks the
wanted tab on `data-open-tab` for Alpine's `init()` in case Alpine has not
booted when the deep link fires. The list loads on item open and again on
every tab select (so a category change saved on Details is reflected), into
the stable `#item-modifiers-host` by innerHTML — two loads can be in flight
(open + deep link) and an outerHTML swap onto a target the first response
already replaced would throw `swapError`; same-item loads are collapsed.
Help topics (en/ar/fa/tr/de, catalog + categories) and the README describe
the tab; the tab label reuses `catalog.modifiers.title`, so no new locale
key and no pack follow-up.

## Findings

1. **Minor, deferred — two dead locale keys.** `catalog.modifiers.manage`
   ("Manage Modifiers") and `catalog.modifiers.inherited_summary`
   ("%s (from category)") have no remaining reference in `web/ui`,
   `internal` or `web/public`; they survive in en/ar/fa/tr and in the de/es
   packs. Harmless at runtime (`guard-i18n` only checks the template → locale
   direction). Not removed here: dropping core keys while the packs still
   carry them is pack-drift territory and belongs in the next
   `ut-plugin-language-{de,es}` sweep, not in a template-only card.
2. **Gate, open — `guard-docs-shots` fails**, as expected for a change to
   `catalog.html`'s rendered tab strip and to seven help topics (`fa/ar/tr
   catalog`, `en/fa/ar/tr categories` listed stale). `make docs-shots` was
   deliberately not run in this review (shared e2e ports; must run last and
   alone on the merged tree). The card's own AC also demands a close-out
   screenshot of the tab bar — the new e2e spec writes
   `2211-modifiers-tab-1280x800.png` / `-1024x600.png` when
   `UT_2211_SHOT_DIR` is set; the lane attaches one of those.
3. **Nit, left as is —** `modifiers.html` emits `href="/catalog?item=…&tab=modifiers"`
   with a bare `&`. Valid HTML5 (`&tab` is not a legacy named reference, so
   no parser ambiguity) and pinned verbatim by
   `TestModifiersPage_AssignedItemLinksBackToCatalogItem`; `&amp;` would be
   tidier but changing it buys nothing.

Checked and clean: no `hx-preserve` anywhere in the touched templates; every
mutation form inside the list still targets `#item-modifiers-list` with
outerHTML and the response is rooted at that id (verified by the
attach/opt-out/opt-in handler tests); create-mode shows the "save first"
hint and `loadItemModifiers` no-ops on an empty `#item-id`; the post-create
path never sets `#item-id` (the dialog auto-closes), so no stale-list window;
dialog close blanks the host and the in-flight guard so item A's groups can't
appear under item B; the keyboard walk relies on DOM order of `[role=tab]`,
which the Go test pins; RTL is handled by the existing
`getComputedStyle($el).direction` branch and the e2e asserts the mirrored
geometry; no money, no SQL, no migration touched. The deleted 1989 spec is
superseded by the new spec's 1024×600 case, which re-proves the same
reachability for the attach button. Translations: the tab is named with each
locale's existing `catalog.modifiers.title` term (ar الإضافات, fa افزودنی‌ها,
tr Modifikasyonlar, de Extras) in every help edit, consistent with the rail.
