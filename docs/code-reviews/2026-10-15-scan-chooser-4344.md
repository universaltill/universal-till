# Scan chooser: a code that is two things asks (ut-docs#4344)

**Status: reviewed. Safe to merge.** Started by the pipeline owner's local session (2026-10-14/15 WIP, branch `feat/4344-scan-chooser`). Finished by `lane:cloud-41` on branch `feat/4344-scan-chooser-c41` (2026-10-16): the WIP was rebased onto `main` with its authorship kept.

## What shipped
- `/api/pos/scan` looks a code up as every kind (`internal/pages/scan_resolve.go`): item (exact), voucher, customer (`CUST*`/`LOY*` codes only), promo and receipt.
  - One answer acts exactly as before.
  - Two or more set `Basket.ScanChoices`, which renders a chooser at the top of `#basket`. It is not a dialog and never takes focus. Nothing is added until the cashier picks a row. The pick re-posts with `kind=` and the scan's own `src`.
  - Tiles, suggestion chips, the identify pick and `gv=1` always mean the item.
- `POSRepo.ScanCodeKinds` does the voucher, promo and receipt checks in one query. The promo predicate is shared with `FindActivePromo`, so the chooser can never offer a promo the apply path would refuse.
- The main till's voucher proxy is asked only when nothing local answered, and only once per scan (see F1/F2).
- Keys `pos.scan_choice.*` are in en/tr/fa/ar. Packs de/es/pt get follow-up PRs in the same cycle.
- Help: `sell.md` in en/de/tr/fa/ar.
- CSS:
  - `.scan-choices` joins the phone collapsed-basket whitelist.
  - Rows are ≥48 px.
  - Logical properties only.

## Review
Independent review by a different model from the author (Opus 5.5). Fable was refused (out of usage credits), so the review ran on Sonnet, per MODEL-ROUTING.md's fallback. **No blockers.**

| # | Severity | Finding | Outcome |
|---|---|---|---|
| F1 | major (offline-first) | A `GS-` code that was a local item still waited on the main-till voucher proxy. | **Fixed** in cycle (found by the finishing lane before review). Proxy asked only when no local answer exists. Test: `TestScanAmbiguous_LocalAnswerSkipsPrimaryVoucherProxy`. |
| F2 | major (latency) | An unknown `GS-` code asked the main till twice: in the resolve step, then again in the voucher branch. With the 2 s budget each, a dead main till cost up to 4 s. | **Fixed**: `askedPrimary`. Test: `TestScanAmbiguous_UnknownGSCodeAsksPrimaryOnce`. |
| R1 | major (process) | This record still said "WIP / not reviewed", and the packs were outstanding. | **Fixed**: this record. Pack PRs de/es/pt are opened in the same cycle. |
| R2 | minor | Typed text that partly matches an item name, but is exactly a promo/receipt/voucher (e.g. typed `SAVE` with an item "Saver pack" and promo `SAVE`), now applies the promo. Before, the item-name search won. | **Accepted, intended.** An exact answer beats a name search (#4342 made the same call for device scans). The old order was the "silent first match" bug. Typed text that matches no exact kind still name-searches. |
| R3 | minor | A `GS-` code that is a local item and also a voucher known only to the main till now adds the item. Before, the main till was asked first and the voucher won. | **Accepted, per the card** (BA req. 1: a scan never waits on the network once something local answered, ADR-0003). |
| R4 | minor | The chooser's re-post dropped `src`, so after a camera/scanner read the item pick could reach the name tier. | **Fixed**: `Basket.ScanChoiceSrc` is re-posted. Test: `TestScanAmbiguous_ChooserKeepsDeviceSource`. |
| R5 | minor (input validation) | `kind=customer` skipped the `looksLikeCustomerCode` gate, so a curl'd phone number with `kind=customer` attached a customer by phone. | **Fixed**: the gate applies to `kind=customer` too. Test: `TestScanAmbiguous_KindCustomerKeepsCustomerCodeGate`. |
| R6 | nit | A typed name *miss* now pays `ResolveExact` + `ScanCodeKinds` before the name search. | Accepted: two indexed point reads on a path already dominated by template render (~2 ms/op). Not worth a second code path. |
| R7 | nit | The scan-cache placeholder can show a bare "Item: milk" row when a typed-name cache key collides with a voucher/promo named the same. | Accepted: needs a voucher/promo whose code is literally a cached typed word. The row still adds the right item. |
| R8 | nit | A `ScanCodeKinds` error fails open, and can ask the proxy for a voucher that exists locally. | Accepted: fail-open is the offline-first choice; harmless. |
