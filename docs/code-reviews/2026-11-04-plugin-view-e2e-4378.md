## Change
Test-only. Until now the plugin-view components (ADR-0121) were covered by Go tests on a fake
bus and by `plugin-chat-focus-4379.spec.ts`, which hand-writes the chat markup. This adds a
real compiled WASM guest that answers `ui.view.ask` / `ui.action.ask` with v1 documents for a
chat, a wizard (with a `qr`) and a long-job page, plus its two job events. The seeder installs
it on an extra-seeded worker till (`startWorkerTill(..., { extraSeeds })`, port band
worker + 100), the way `e2e/seed_identify_plugin` does. The spec measures the real
`servePluginView`, `plugin_job.go` poll, templates, `app.js` and `app.css` at 1024x600 and
360x800, in en and fa, plus one de pass.

`confirm` is out of scope (needs an auth-on till and a signed-in manager), split to #5466.

Pre-flight: review record — updated (this file); till user-visible behaviour / `web/help/` /
docs-shots — n/a (no product change); `en.json` keys / meta / language packs — n/a (the
`e2eviews.*` keys are the test plugin's own bundle under `e2e/seed_plugin_views/locales`, not
core i18n, and `guard-i18n.sh` passes); `README.md` / `e2e/README.md` — n/a (neither lists
seeders); reference / ADR / plugin host functions / manifest mirrors — n/a (no SDK, host

hardening card (below).

Checked and found fine:
- **Seeder SQL:** every NOT NULL column of `plugin_catalog`, `plugins`, `plugin_permissions`,
  `plugin_hooks` and `plugin_entries` is set or has a default (checked against 001 / 018 /
  089). `menu_group` is set to `'main'` (free-form; a NULL bricks boot, see deferred). `INSERT
  OR IGNORE` on fixed ids makes a re-run idempotent; each till gets a fresh data dir anyway.
  Raw SQL in `e2e/` is the test-support exception in CLAUDE.md; `guard-data-access.sh` passes.
- **Trust path:** no production code changes. Like the identify / api-importer / file-importer
  seeders it writes DB rows and `plugins/<id>/<version>/plugin.wasm` directly, bypassing the
  Ed25519-verified install path, only on a throwaway e2e till. No new production trust path.
- **Neutrality and test data:** `com.example.e2e-views`, "Sample View Plugin", no shop or
  personal names, no mail addresses; `guard-core-neutral.sh` and `guard-mail-addresses.sh` pass.
- **CI parity:** `e2e.yml` runs `npx playwright test` with `CI=1` and the German pack overlay;
  `worker-till.ts` runs the seeder with `go run` from the repo root and the seeder runs `go
  build` with `GOOS=wasip1 GOARCH=wasm`, exactly as locally and as the identify precedent.
  `retries: 2` in CI re-runs the serial group with a fresh till. The guest is under `testdata/`,
  so `go build ./...`, `go vet ./...` and golangci-lint skip it; it is vetted with the wasip1
  target below.
- **Port band:** extra-seeded tills sit on worker port + 100 and refuse to reuse a busy port;
  two of them (2 workers) ran side by side here.
- **Assertions:** geometry is measured after `waitForStableLayout`; RTL mirroring, the
  one-and-only `aria-current="step"`, the plugin's own `JobProgress` text (not core's default),
  history surviving `_turns`, and focus return are all real checks (the Tester's three
  break-its plus mine below).

## Deferred
- **#5466** — `confirm` component e2e (auth-on till, signed-in manager).
- **`PluginRepo.ListMenuEntries` NULL hardening** (Tester §5): `menu_group` / `route` / `label`
  are scanned into Go `string`s without `COALESCE`, so one NULL page row fails
  `loadMenuEntries` and the till does not boot. No production writer can store NULL
  (`ReplacePluginEntries` binds `string`s; migrations only copy), so it is reachable only through
  raw inserts or a hand-edited / restored DB. **It deserves a card, low priority:** the failure
  mode is a till that will not start, which is out of proportion to one bad row on an
  offline-first device, and the fix is small (`COALESCE(..., '')` or skip-and-log per row, with a
  test that inserts a NULL row). Not a bug in this branch.
- Not from this branch (Tester §6): the `move_5127` tests' hard-coded `moveExp` expired on
  2026-11-03 and turn `go test` red on main (fix PR universal-till#2343).
