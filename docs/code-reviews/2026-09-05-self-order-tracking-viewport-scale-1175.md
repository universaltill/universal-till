# 2026-09-05 — Self-order/order-tracking viewport-scaling fix (ut-docs#1175)

## What shipped

Follow-up to ut-docs#1126. Three standalone documents — `web/ui/pages/self_order.html`,
`web/ui/pages/self_order_shop.html`, `web/ui/pages/order_tracking.html` — still
hardcoded the OLD, pre-ut-docs#161 fixed-px viewport-scaling mechanism on their
`<html>` tag (`style="font-size: {{ uiscalepx }}px"`) instead of the
viewport-responsive `--ui-scale` + `app.css` fluid clamp that
`web/ui/layouts/base.html`/`login.html`/`setup.html` already use. Swapped all
three to `style="--ui-scale: {{ uiscale }}"` — a one-line change per file, no
new CSS (the global fluid clamp already exists).

`order_tracking.html` is a special case worth recording explicitly: it renders
on a **customer's own personal phone** after scanning the self-order
confirmation QR (`internal/pages/order_tracking.go`, auth-exempt, gated only by
an unguessable tracking token), not on shop kiosk hardware — there is no fixed
target device the way there is for the two kiosk screens. Its regression test
therefore uses a phone-class viewport (375×667) plus a larger one (1920×1200)
rather than the kiosk sizes, to prove the same responsiveness property without
assuming a specific device.

New regression coverage: `e2e/tests/self-order-tracking-viewport-scale-1175.spec.ts`,
mirroring `e2e/tests/login.spec.ts`'s existing #1126 tests — one test per page,
each driving both viewports and asserting the two root-font-size readings
actually **differ** from each other (not just "!= 16" independently, which
would still pass against a fix that hardcoded some other wrong constant).
`self_order.html`/`self_order_shop.html` also assert a real interactive
element (`.selforder-start`, the shop header's back link) meets the 44px
touch-target minimum at both viewports, without needing any catalog/basket
fixture. `order_tracking.html` is tested via a bogus tracking token, which
hits the handler's NotFound branch — same full document/`<html>` tag as a
real tracking link, with no sale/receipt fixture needed.

`web/help/img/**` screenshots + `web/help/img/manifest.json` were regenerated
via `make docs-shots`, since `web/help/en/customer-order-tracking.md` claims
`/o/{token}` and its screenshot changed visibly (the status/heading region) at
all four locales. `web/help/en/self-order.md` (which covers `/self-order` and
`/self-order/shop`) carries no `routes:` front matter — it's on the
route-coverage denylist as a customer-facing kiosk screen with no operator "?"
link — so it isn't part of the 25 screenshotted topics and owed no shot.
