## What shipped

- `display.effects_level` = auto | full | balanced | light, per till (the
  `display.` prefix is already in `PerTillSettingPrefixes`), plus
  `display.effects_detected` / `_reason` / `_fingerprint`.
  `ApplyReplicaIdentity` deletes every `display.effects_*` row
  (`substr`, not `LIKE`, because `_` is a wildcard), so a joined replica
  detects for itself.
- `internal/fxlevel`: host detection from CPU cores, `/proc/meminfo` RAM
  (Linux/Android only; unknown RAM is never a signal) and the Raspberry Pi
  device-tree model (`pihealth.PiModel`). Light if Pi, ≤ 2 cores or ≤ 2 GiB
  known RAM, else Full. Re-detects only when the fingerprint changes or the
  stored detection is invalid; never overwrites an explicit level.
- `httpx.InitEffectsLevel` + `fxlevel` template func + `|fx=` in
  `ShellSignature`, republished by `publishCachedSettings` (boot and sync
  re-derive) and by the POST handler.
- `<html class="fx-…">` on base.html and the standalone pages, `UT.fxLevel`,
  `UT.motionOff()` (reduced motion OR light) used by pageswap, pagereveal,
  `htmx:beforeTransition`, the swap/panel ease, the tile FLIP and the record
  dialog ease. The inline `@view-transition` opt-in is omitted under Light.
- `html.fx-light` / `html.fx-balanced` CSS blocks. Light keeps the two
  spinners and restores six box-shadow selection indicators explicitly.
- Settings → Display: Auto/Full/Balanced/Light selector,
  `POST /api/settings/effects-level` (same auth as ui-scale; 400/204), and
  the detection shown in words. 14 new keys in en/ar/fa/tr; help step 20 in
  en/de/ar/fa/tr `display.md`.
- e2e `effects-level-2859.spec.ts` (emulates `reducedMotion: 'no-preference'`
  first); `worker-till.ts` and docs-shots pin the level to Full so motion
  specs and the manual don't depend on the runner's core count.

## Verified

- Reviewer re-verified three TDD claims by reverting each fix: the replica
  delete (`TestApplyReplicaIdentityClearsInheritedEffectsLevel` fails with 4
  rows surviving), the `{{ if ne fxlevel "light" }}` wrapper
  (`TestBaseHTMLOmitsViewTransitionOptInUnderLight` fails), and the
  `publishCachedSettings` call (`TestCachedSettingsGlobals_AllPublishedByOneHelper`
  and `TestPublishCachedSettings_PublishesEffectsLevel` fail); all pass
  restored.
- Reviewer: no `transitionend`/`animationend` hang under Light; focus rings
  are `outline` (untouched); `UT.motionOff` is defined before every user;
  handler auth parity with ui-scale; kiosk isolation intact; offline-only
  detection with two local file reads.
- Tester driven run (headless Chromium, this sandbox's 4-core/16 GB host →
  Full): Display card at 1024×600 and 360px in en/de/fa; sale screen,
  Settings and Items in Light vs Full, default and dark theme; selected
  category tab, checked colour tile and keyboard focus visible under Light;
  a level change forces one full load and survives reload; dialogs open and
  close under Light; no console errors. e2e: effects-level-2859,
  page-transitions-2223, in-panel-dialog-transitions-2338 (19/19), plus
  the 2496 motion specs and four settings specs (Dev).
- Gates: gofmt, build, vet, `go test ./...`, golangci-lint (0), every CI
  build guard (shellcheck not installed in this sandbox; no shell script
  changed).
