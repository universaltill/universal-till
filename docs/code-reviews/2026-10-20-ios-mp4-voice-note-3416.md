# Review: bug-report voice notes on iOS before 26 (MP4) (ut-docs#3416)

Date: 2026-10-20 · Branch `fix/3416-ios-mp4-voice-note` · Lane `lane:cloud-41`
Author: Opus 5.5 · Independent reviewer: Fable 5.1, fresh context (different model)
Pairs with ut-cloud `fix/3416-ios-mp4-voice-note` (record `docs/code-reviews/2026-10-20-ios-mp4-voice-note-3416.md` there).

## What shipped

- `internal/issuereport/bundle.go`: new `AudioFileName(b)`. It checks the bytes, not the client name. An "ftyp" box at offset 4 means MP4, saved as `audio.m4a`; anything else is saved as `audio.webm`, as before. `Pending()` finds either file, and `audio.webm` wins if both exist.
- `internal/cloudsync/issue_reports.go`: the upload uses the bundle's real file name instead of a fixed `audio.webm`.
- `web/ui/partials/bugreport_panel.html`:
  - `audio/mp4` is the last entry in `VOICE_TYPES`, so a device with WebM or Ogg records exactly as before.
  - The upload is named `audio.m4a` when the stored recording's type is `audio/mp4`.
  - MP4 draft chunks (ut-docs#2342) are kept just like WebM ones (review finding 1).
- `web/help/{en,de,fa,tr,ar}/bug-reporting.md`: removed the sentence "older iOS can't record voice notes", which is no longer true.
- `web/help/img/manifest.json`: regenerated by `make docs-shots`. Topic hashes and `surface_sha256` changed; every PNG is byte-identical.
- `e2e/tests/bugreport-voice-mime-3354.spec.ts` now has three tests:
  - A recorder with no usable audio type: the voice button stays disabled.
  - An MP4-only recorder: the button is live.
  - A driven MP4 recording with a fake MP4 `MediaRecorder` survives a reload mid-recording and posts `filename="audio.m4a"` with `Content-Type: audio/mp4`.

## Findings (Fable 5.1)

| # | Severity | Finding | Outcome |
|---|---|---|---|
| 1 | medium | The first cut skipped draft chunks for MP4, because fragmented-MP4 chunks might not join. The upload joins the same chunks, though, so the skip saved nothing. It also lost the note on a reload mid-recording, while the help says the note is kept. | **Fixed**: MP4 chunks are persisted like WebM. The new e2e test reloads mid-recording; it fails with the skip and passes without it. |
| 2 | low | Rollout order: a fixed till against an older ut-cloud stores MP4 bytes as `audio.webm`. | Accepted. Merge or deploy ut-cloud first; nothing breaks either way. |
| 3 | low | The panel's file name is cosmetic, since both servers check the bytes. | Accepted (as designed). |

Checked with no issue:
- No hard-coded `audio.webm` is left outside fallbacks and comments.
- No new file writes (`MkdirAll` and `paths.Data` don't apply).
- No new user-facing strings.
- An attacker-chosen file name can't reach a path.
