# Review: invoice page print CSS (ut-docs#6167)

**Change.** Printing `/invoice/{no}` used to put the whole app shell on paper: the rail, the status bar, the notice strip and the Print / ← Receipt buttons. The browser also added its own header and footer (page title, URL, date). Now only the document prints. This covers all three variants, because one template serves the invoice, the tax invoice and the credit note.

- **`web/ui/pages/invoice.html`:**
  - The page content is wrapped in `.invoice-doc`.
  - The button row gets the class `.invoice-actions`.
  - One page-local `<style>` is added:
    - `@page { margin: 0 }`, so the browser has no margin box to print its header and footer in.
    - Under `@media print`, the voucher-slip isolation pattern (ut-docs#6152): `body *:not(:has(.invoice-doc)):not(.invoice-doc):not(.invoice-doc *)` hidden, and the ancestors flattened to static blocks.
    - `.invoice-doc` gets its own 15mm inset in logical properties (`padding-inline` / `padding-block`), with `box-decoration-break: clone` so the inset repeats on every page.
    - Black on white whatever the theme; the card's shadow and radius are removed; rows get `break-inside: avoid`.
- **`web/help/en/invoices.md`:** one sentence in step 3 of "Viewing, reprinting and exporting". English only (ADR-0160).
- **`e2e/tests/invoice-print-6167.spec.ts`** (Chromium, 794×1123 ≈ A4):
  - Screen view: chrome visible; Print calls `window.print` once.
  - CSSOM: the page has an `@page` rule with margin 0.
  - Print media, in `en` and `fa`: chrome hidden; title, sheet and customer visible; inset ≥ 15mm on all four sides; x ≤ 1, width ≥ 793, no horizontal overflow; black text on white.
  - After a boosted ← Receipt navigation, no `@page` rule is left.
  - Attaches PNG screenshots and an A4 PDF.
- **`e2e/tests/invoice-print-phone-6167.spec.ts`** (360px): has "phone" in its name, so it also joins the `webkit-phone` lane. It checks the CSSOM rule, the hidden chrome, the inset and no overflow.
- No Go change. No new i18n key. No ADR: it follows the #6155 / #6152 pattern. ut-docs: no change.

**Pipeline.** BA, Architect and UX wrote the combined design. Dev and Tester ran on Sonnet. The Reviewer is a separate agent on Opus 5.5.

## Findings
| # | Sev | Finding | Outcome |
|---|---|---|---|
| F1 | minor | **Orphaned sub-rows on multi-page invoices.** The Reviewer printed a real 50-line invoice (87 table rows, 5 A4 pages, Chromium 153 `page.pdf`). The "Unit price (excl. VAT) …" sub-row of the last line on page 2 (Bananas) printed alone at the top of page 3, separated from its line. Cause: `break-inside: avoid` keeps each `<tr>` whole, but nothing keeps a line and its `tr.muted` sub-row together. | **Fixed.** Added `.invoice-sheet tr:has(+ tr.muted) { break-after: avoid; }` inside the print block. Re-rendered: the line and its sub-row now move to page 3 together, and every page is still 5 / 5. The desktop spec now asserts computed `breakAfter === 'avoid'` on such a row. That assertion fails without the CSS line (Received "auto") and passes with it. |
| F2 | info | The `:has()` rules share one `@media print` block with the other rules; the voucher slip gives each rule its own block. CSS drops only the style rule whose selector is invalid, not the whole block, so an engine without `:has()` still gets the inset, `@page` and colours. It would print the chrome, which is the old behaviour. All engines the till targets have `:has()`: Chromium ≥105 (Pi OS Bookworm ships 12x+) and WebKit ≥15.4 (iOS WKWebView). | Accepted. |
| F3 | info | **`@page` spill to other pages.** The `<style>` sits inside `#ut-page`, which a boosted navigation replaces with outerHTML. History restore cannot bring a stale copy back: `historyCacheSize: 0` with `refreshOnHistoryMiss` does a full reload. The spec proves the boosted case: `pageRules` is `[]` after ← Receipt. The Tester showed the journal's print PDF is byte-identical to the same page loaded directly. | No issue. |
| F4 | info | **Does the hide selector hide the invoice?** No. `.invoice-doc` and all its descendants are excluded, and the ancestors (`body > #ut-page > main`) match `:has(.invoice-doc)`. The h1 prints because it is inside `.invoice-doc`, while `.invoice-actions` is hidden on its own. Both specs assert this. | No issue. |
| F5 | info | **Page inset on page 2 and later.** It depends on `box-decoration-break: clone` for block fragments. Chromium 153 honours it: the Reviewer's PDF shows the top and side inset on pages 2–5. Older Chromium builds and WebKit may not, so the inset would show only at the start and end of the whole document. | Accepted. Pi Chromium is current. Real-printer check deferred (below). |
| F6 | info | **Spec stability.** The specs seed through the API on the per-worker till (9091 + parallelIndex), so they do not race other specs. `afterEach` clears the seller and resets the POS. They use no fixed dates. `zeroMargin` accepts `0` / `0px` and fails closed on any other value. | No issue. |

## Verification
- **TDD, re-verified by the Reviewer** in the review worktree:
  - Reverted `invoice.html` to `HEAD~1` and ran both new specs: both **fail**. The phone spec fails on `@page rules > 0` (Received 0); the desktop spec fails on `.invoice-actions .btn` count (Received 0).
  - Restored the file (index unstaged, `git diff HEAD` empty) and ran both again: both **pass**.
- **Suite after the F1 fix (Chromium, default project):** `invoice-print-6167`, `invoice-print-phone-6167`, `invoice-phone-4393` and `invoices-phone-4402` gave **4 passed**. The #4393 and #4402 specs confirm the screen layout is unchanged.
- **Build and Go tests:** `go build ./...` passed. `go test ./internal/pages/...` passed.
- **Guards:** rtl-logical-css, i18n, help-topics, fixed-dates (no date in 2026-11-13..2027-01-12), no-showmodal, no-native-confirm, compliance-claims and wip-commits all passed.
- **Multi-page check (Reviewer):** 50 demo items, 5-page A4 PDF, rasterized and looked at:
  - title and seller block on page 1;
  - the table header repeats on every page;
  - page 5 holds the last line, the end-aligned VAT/totals table and the barcode;
  - the inset shows on every page.
- **Tester's visual attestation (looked at the rasterized A4 PDFs):**
  - Tax invoice, en light: no rail, status bar, notices or buttons. Even inset, nothing clipped, amounts end-aligned.
  - Tax invoice, fa: RTL mirrored, inset symmetric.
  - Credit note, en dark theme: white page, black text, "Credit note" title and the "credits INV-…" line printed.
  - Credit note, fa light: mirrored correctly.
  - Screen at 1024×600 and 360px: before and after screenshots are byte-identical.
  - Journal after leaving the invoice: prints with normal margins.
- **Tester mutation checks:** each change made the specs fail.
  - Hide rule dropped: both fail.
  - Inset 5mm: both fail.
  - `@page` 10mm: both fail.
  - Colour rule dropped: the desktop spec fails.

Pre-flight: web/help updated (`invoices.md` step 3; screen unchanged, so no docs-shots regeneration); reference n/a (no reference page covers invoice printing); en.json n/a (no new key); README n/a; ADR n/a (follows the #6155/#6152 page-local print pattern); ut-docs n/a; follow-ups: none beyond the deferred checks below.

**Verdict:** approve with the F1 fix applied (uncommitted in the review worktree: `web/ui/pages/invoice.html` +2 lines, `e2e/tests/invoice-print-6167.spec.ts` +2 lines).

- **Page 2+ inset on engines without block `box-decoration-break: clone`** (older Chromium, WebKit): not checked.
