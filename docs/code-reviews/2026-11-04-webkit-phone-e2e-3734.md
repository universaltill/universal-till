# Review: WebKit phone-spec lane for the UI E2E suite (ut-docs#3734)

Branch `ci/3734-webkit-phone-e2e`, base `origin/main` (5ae7ae3). Author: Dev
(Sonnet); independent review: Opus 5.5.

## What shipped

- `e2e/playwright.webkit.config.ts`: a separate Playwright config with one
  project, `webkit-phone`. It spreads the main config (timeout, expect,
  retries, workers, globalSetup, testDir), then overrides `webServer: []`
  (per-worker tills only, no static tills), `outputDir`
  (`test-results-webkit`), `reporter` (`playwright-report-webkit`) and
  `projects`. The project matches every spec with `phone` in its file name,
  ignores `EXCLUSIVE_SPECS` (which drops the three auth-only `phone-drawer-*`
  specs), and runs `browserName: 'webkit'` with `e2eWorkerServer: true` and
  no `launchOptions` (the preinstalled-Chromium path never reaches WebKit).
- `e2e/playwright.config.ts`: the `*_ONLY_SPECS` regexes and `WorkerOptions`
  are exported, and the `default` project's `testIgnore` is the new
  `EXCLUSIVE_SPECS` array, in the same order as before. There is no
  behaviour change: the Tester found the `--list` output byte-identical to
  main.
- `.github/workflows/e2e.yml`: a new `webkit-phone` job runs in parallel to
  `playwright`, with no `needs:` and no `continue-on-error`. It installs
  WebKit only, has its own browser cache, and uploads the
  `playwright-report-webkit` artifact on failure. It skips itself with an
  in-job `git diff` and has no workflow-level `paths:` filter, so the
  Chromium job is unaffected.
- `package.json` gains `test:webkit`. The `.gitignore`, `e2e/README.md` and
  `CLAUDE.md` (path-scoped jobs list) are updated.

AC1, restated for the separate-config design:
`npx playwright test -c playwright.webkit.config.ts --list` lists 237 tests in
19 files, all `[webkit-phone]`. With the main config,
`--project=webkit-phone` is "not found".

Pre-flight: CI-only change, no till user-visible behaviour, so `web/help/`
and docs-shots are n/a. No `en.json` key, so i18n meta and lang packs are n/a.
No plan, platform or ADR change. `e2e/README.md` and `CLAUDE.md` are updated.
This review record is updated. Follow-up cards: none needed.

## Findings

1. MINOR, **fixed** (Tester G1). The PR filter matched only `^(web|e2e)/`, so
   a PR that edits only `.github/workflows/e2e.yml` (for example the install
   step or the cache key) skipped the WebKit job, and the edit was first
   exercised on main. The filter is now
   `^(web|e2e)/|^\.github/workflows/e2e\.yml$`. The step name, the skip
   message, the header comment, `README.md` and `CLAUDE.md` now say so. I
   checked the regex by hand: `e2e.yml` runs; `ci.yml`, `e2e.yml.bak` and
   `docs/x.md` skip. `e2e/playwright.webkit.config.ts` was already covered by
   `e2e/`.
2. MINOR, **fixed**. A cache prefix collided with the Chromium job. The new
   key was `<os>-playwright-webkit-<hash>`, and the Chromium job's
   `restore-keys: <os>-playwright-` prefix-matches it. On a lockfile change
   (an exact-key miss), the Chromium job could restore the WebKit-only cache
   if that was the most recently saved one. It would then download Chromium
   anyway and save a cache holding both browsers under its own key. Nothing
   breaks, but the code comment "never collides" was false. The key is now
   `<os>-pw-webkit-<hash>`, with the restore-key `<os>-pw-webkit-`, so the two
   caches are disjoint in both directions. The Chromium key is left as it is,
   so its warm cache is not invalidated.
3. NOTE, **accepted**. The `Fetch diff base` step also runs on push. Its
   result is unused there, because push always runs the lane, and a zero
   `before` SHA fails harmlessly under `|| true`. It is kept so that the
   filter step has one shape.
4. NOTE, **accepted**. Locally, running the WebKit lane and the Chromium
   `default` project at the same time collides on the worker ports
   (9091 + parallelIndex). In CI the two jobs run on separate runners. Run
   them one after the other on a dev machine.
5. Checked, no finding:
   - `...base` override semantics. `projects`, `webServer`, `reporter` and
     `outputDir` are replaced, and the base has no top-level `use`, so no
     Chromium `launchOptions` can leak through it.
   - The worker-server fixture keys only on the `e2eWorkerServer` option and
     `parallelIndex`, never on the project name, so it boots per-worker tills
     under WebKit unchanged.
   - `globalSetup` only builds the binary.
   - None of the 19 specs needs the German overlay (`germanPackExpected` is
     env-keyed, and the WebKit job does not set it), and none uses
     `browserName` or CDP.
   - The artifact names are distinct (`playwright-report` and
     `playwright-report-webkit`).
   - A skipped job concludes green: every later step is gated on
     `match == 'true'`, and the artifact upload runs only on `failure()`.
   - A base that cannot be fetched or resolved leads to a run, never a skip
     (sentinel path).

## Tester summary

The Tester's verdict was PASS on everything that can be checked locally.
- **Listings.** The `default` and full listings are byte-identical to
  origin/main (1423/282 and 1536/314). The WebKit lane is 237/19 and matches
  the BA's file list. Each of the 19 files sets a phone viewport.
- **Skip logic.** The exact YAML `run:` blocks were executed against
  fabricated PR and push states in a throwaway bare clone, in 12 cases:
  - docs-only skips;
  - `web/` and `e2e/` changes run;
  - nested or root `web`/`e2e` names skip, because the regex is anchored;
  - push always runs;
  - an unfetchable, empty or zero base runs.

  Base drift only ever adds files to the diff, so a false skip is impossible.
- **Chromium job.** `jobs.playwright` is unchanged. The new job has no
  `needs:` and no `continue-on-error`.
- **Guards.** 57 of 58 passed, and the 58th (shellcheck-version) passed once
  shellcheck was installed. actionlint is clean.
- **Gaps.** G1 is fixed here. G2 (a Go-only render change skips on the PR and
  is caught on main) is accepted by design (BA R4).
