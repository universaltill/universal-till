# Code review — "Update now" for a joined till over the main-till link (ut-docs#2945, LAN half)

- **Date:** 2026-10-08
- **Branch:** `feat/2945-update-now-lan`
- **Lane:** `lane:cloud-54`
- **Built by:** Opus 5.5 dev subagent.
- **Reviewed by:** an independent Fable subagent, a different model from the author.
- **Scope:** the LAN half only. The my. relay is split to ut-docs#3923, which also depends on #2682.

## What shipped

- **`fleet` frame (ADR-0114 §2/§5).** Main → joined till. The payload is `{target, now}`; policy comes with #2739.
  - The hub keeps it as a pending flag per peer, like `cloud_checkin`: the latest target wins, nothing queues, and it is O(1) per slow peer (§8).
  - `Hub.RequestUpdate` refuses a till that has no live link, has no hello yet, or is silent past the heartbeat timeout. It returns `ErrNotLinked`.
- **Joined till.**
  - It accepts a `fleet` frame only as "update now", and only to exactly the version the main till's own hello names (§7: frames can do little).
  - A press overrides only the "automatic updates off" guard and the "already tried / no effect" guards.
  - Everything else still applies: the till must be a joined till, both versions must be releases (never a dev build), the target must be strictly newer (no downgrade, never past the main till), `UT_UPDATE_CHECK` must be on, the install must be able to replace itself, and the install goes through `ApplyVersionWhenIdle`, so never mid-sale.
  - One attempt per press. A press for a target the main till has since moved past is dropped.
  - The scheduler goroutine stays the only applier: a press kicks it, and the link loop is never blocked.
- **Real `report.update_state`.** It was a hard-coded `idle`. It now reports `downloading`, `waiting-safe-moment` (also while a downloaded update waits for an open sale), `failed:<code>`, and `failed:unsupported` for an install that can't replace itself. These are ADR-0114 §2's states only, so no ADR change is needed.
- **Main till's Tills page.**
  - A manager-gated **Update now** button (`sync_management`) appears on a linked joined till that is behind, and also after a failure, where it works as a retry.
  - `failed:unsupported` reads "Needs the installer on that till" and shows no button.
  - `POST /api/tills/{id}/update-now` works on the main till only and is denied in demo mode. Refusals (not linked, dev build) are localized and shown right under the button. A request writes an `update_requested` audit row.
- **i18n and help.** 5 new keys in en/ar/fa/tr. The help topic `multitill` step 9 is updated in en/de/tr/fa/ar, and docs-shots were regenerated.

## Findings

| # | Severity | Finding | Outcome |
|---|---|---|---|
| 1 | minor | The refusal text landed at the bottom of the card, outside `#tills-roster`, and was never cleared, because the `save-error` carrier had no colon. | **Fixed.** The button is now in its own `<form>` carrying `fail save-error:tills-update-now-error`. The line sits right under the button, inside the roster, so the next press or the 10 s refresh clears it. The test assertion is updated. |
| 2 | minor | A new report state `manual` was not in ADR-0114 §2's list. | **Fixed.** The till now reports `failed:unsupported` (a §2 state), and the roster maps it to the installer note. An unknown state is still dropped (test case added). |
| 3 | minor | The row showed "Downloading" while a downloaded update waited for an open sale. | **Fixed.** `applying` with a sale open now reports `waiting-safe-moment` (test case added). |
| 4 | minor | The help said "Windows or Android" can't self-update, but a Windows installer install can. | **Fixed** in all 5 locales: "a portable Windows zip, Android, or an install it isn't allowed to change". |
| 5 | nit | A stale forced target was kept forever after the main till moved on. | **Fixed.** `followInputsOf` drops it. |
| 6 | nit | Tiny lost-press window between reading and clearing the forced flag. | **Accepted.** At worst a second press during the first attempt is spent; pressing again after a failure retries. |
| 7 | nit | `RequestUpdate` ignored heartbeat liveness. | **Fixed.** A peer silent past `PeerTimeout` returns `ErrNotLinked`. No dedicated test: the reaper closes such a link within `PeerTimeout/6`, so the window can't be held open in a test without a clock seam. |
| 8 | nit | A `fleet` frame read in the same burst as a re-link's hello can be checked against the previous link's version and ignored. | **Accepted.** It needs a press within milliseconds of a re-link, the ignore is logged, and pressing again works. |
| 9 | note | Until TLS pinning (#2736), a LAN MITM could forge a `fleet` frame to override `update.auto_enabled=false`. | **Accepted, recorded here.** The forged frame can still only point at a checksum-verified genuine release newer than the till and equal to the hello version, so this adds no new install vector. A MITM can already forge the hello today. |

  - Removing the Forced bypass of "off" fails `TestFollowDecision_Forced` and `TestFollowTick_UpdateNowInstallsOnceWithUpdatesOff`.
  - Both pass again once the code is restored.
- **Rendered roster** (button, installer note, failed + retry, up-to-date row) screenshotted and looked at:
  - Looked at: 1024×600 in English and Persian (RTL). Buttons line up, nothing is clipped, and the Persian strings are real translations.
  - At 360 px in a bare harness without the app's phone table wrapper, the existing 7-column table overflows. That predates this change and was not re-checked inside the real app shell.
  - Not looked at: the dark theme, and a real two-till link driven end to end in a browser. No Playwright spec sets up two linked tills; the Go test `TestTillUpdateNow_ReachesTheLinkedReplica` covers the path over a real in-process link.
- **Gate:** gofmt clean; `go build ./...`; `go test ./...`; `-race` on `internal/fleetlink` and on `internal/pages` (full run before the fixes, targeted after); all `ci.yml` build-job guards.
  - golangci-lint could not run locally (its binary was built with Go 1.25, older than the module's Go 1.27.1). CI runs it.

## Verdict

Safe to merge. None of the findings touch the sale flow, offline-first behaviour or the install path's safety.
