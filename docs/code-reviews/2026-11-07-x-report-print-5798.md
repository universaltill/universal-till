## Review findings
- M1 Medium — free text reached the printer with control bytes. An adjustment reason (any cashier with adjustment rights types it; the handler only checks non-empty) plus register/cashier names went onto paper raw, and the `utf8` charset passes C0 bytes through, so `ESC p …` in a reason would kick the drawer from an X report and a `\n` would forge a line (e.g. a fake "Expected £0.00"). This card is the first to print the reason. **Fixed:** `xPaperText` maps every control rune to a space for reason, register and cashier names; `TestBuildXReportDoc_FreeTextHasNoControlBytes` (red before: `control byte 0xa on paper in "Register … Front\nTill"`, green after).
- L1 Low — the audit write used the request context: a browser that leaves after the printer accepted the job cancels `r.Context()` and the row is lost although the paper is out. **Fixed:** `context.WithoutCancel(ctx)` for the audit insert only (no test: needs a mid-handler disconnect; one-line, mirrors the comment's own intent).
- L2 Low — "Refunds (0) -£0.00" prints a minus on zero — accepted: same convention as `buildEODDoc` (`"-" + money(RefundTotal)`); X and Z papers stay consistent.
- L3 Low — "Adjustments and payouts" (>20 cols) falls back from `eodRow` to `footerRow`, so that one row is not column-aligned — accepted: same `eodRow` behaviour as the Z paper; amounts are never clipped.
- L4 Low — help says the failure message appears "next to the button"; it sits on its own line directly under the button row — accepted (wording close enough; changing it re-hashes the topic for no behaviour gain).
- L5 Low — a JSON client cannot pass a PIN (PostForm only), so a non-permitted JSON caller always gets 403 — accepted: same as card 2's view endpoint and the design.
- L6 Low — the 404-before-PIN reveals whether a shift id is open to an unpermitted session — accepted per design (`/shifts` already shows the current shift; ids are UUIDs).
- No `showModal`, logical CSS only, money via `money.Money` throughout (JPY 0-decimal test present), no file writes, no cwd-relative paths, no raw SQL outside `internal/data` (test-only SQL is fixture setup).
