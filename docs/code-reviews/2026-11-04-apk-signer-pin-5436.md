# Review — Android in-app update pins the APK signing certificate (ut-docs#5436, ADR-0179)

- **Date:** 2026-11-04 · **Lane:** `lane:cloud-24` · **Card:** universaltill/ut-docs#5436
- **Built by:** Sonnet (Dev + one fix round) · **Reviewed by:** Opus (independent) · **Tested by:** separate Tester agent (Opus)
- **Design:** ut-docs `adr/0179-android-in-app-update-pins-the-apk-signing-certificate.md`

## What shipped
- `android/app/apk-signer-sha256.txt`: the release certificate's public SHA-256
  (`8bd8e604…0db4`, the value release run 40688332843 prints for all three flavors and the
  2026-07-26 signing review recorded). Gradle reads it into `BuildConfig.APK_SIGNER_SHA256S`
  (strict: 0–4 distinct 64-hex values; `-PutApkSignerPins=` overrides for test keys / dormant).
- `UpdateLogic`: `parsePinSet`, `sha256Hex`, `checkUpdateApk` (package → newer versionCode →
  dormant → unreadable/multiple signers → pin, or a pinned key in the API 28+ rotation lineage).
- `MainActivity.verifyThenInstall`: off the UI thread, on both the fresh-download and the reuse
  path, before `releaseKioskLock()` and the installer. It copies the APK into app-private
  `filesDir/updates/`, verifies the copy and installs only the copy (FileProvider now exposes only
  that `files-path`). A refusal deletes both files, removes the download, clears the saved id and
  shows the existing failed/retry state — no new string, nothing modal, selling unaffected.
- `scripts/ci/check-apk-signer-pin.sh` (+ sandboxed `_test.sh`, wired into `ci.yml`): `release.yml`
  fails if a built APK's signer is not the pin, or if the pin digest is not compiled into the
  APK's dex (an un-armed build).
- `RELEASING.md`, `android/README.md`: pin + rotation runbook (never advise an uninstall — it
  deletes the till's local data incl. unsynced offline sales).

## Findings
| # | Sev | Where | Finding | Outcome |
|---|---|---|---|---|
| M1 | medium (security) | `MainActivity` | TOCTOU: on API ≤ 29 the external files dir is writable by apps with storage permission, so the checked APK could be swapped before the installer read it | fixed: verify + install a private copy |
| M2 | medium | ADR-0179 / runbook | rotation steps wrong: removing the old digest strands API 24–27 tills; "reinstall" invites data loss | fixed: lineage accepted on API 28+, runbook reworded |
| L1 | low (security) | `release.yml` | nothing proved the APK was built armed | fixed: dex contains the digest, else fail |
| T1 | low | `verifyThenInstall` | refusal cleanup skipped when the Activity was destroyed mid-check | fixed: cleanup before the `isDestroyed` return |
| T2 | low | catch `Exception` not `Throwable` | rejected: an Error crashes the app, nothing stays stuck |
| T3 | low | `_test.sh` | cases asserted only `::error::` | fixed: each asserts its reason |
| T5 | info | same-versionCode download now shows "failed" | accepted, intended by design |
