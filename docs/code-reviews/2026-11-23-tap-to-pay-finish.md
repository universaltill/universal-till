# Code review: Tap to Pay settings panel, grant rule, offering gate (ut-docs#6458)

Reviewer: combined Reviewer (Sonnet 5.5, not the Dev, not the Tester), 2026-11-23. Diff read in full against
ADR-0198 (2, 3.1, 6) and ADR-0203; targeted tests re-run.
Pre-flight: plan/price n/a; platform claim: the panel only appears with a native bridge (iPhone); till behaviour:
main/standalone only; no secret in any answer; manual shipped (`web/help/en/tap-to-pay.md`).

## What shipped
Settings > Payments > Tap to Pay panel (4 steps: device, Apple, Stripe account read-only, explicit grant); native
Setup run detached with a timeout and single-flight; `installGrantsPermission` no longer auto-grants
`device:tap_to_pay` / `net:payment_broker` (ADR-0198 3.1); main-till offering and tender gate need a ready device or
a paired phone reader; declined / PIN fallback / not-ready panels; poll classified in `backgroundPollPaths`.

## Findings
- R1 (important, FIXED): the grant route gave both permissions to the first plugin whose tap entry names provider
  "stripe". Manifest validation has no provider-ownership check, so a marketplace plugin could declare
  `{tap:true,provider:"stripe"}` and receive the broker and device permissions on a manager's click. Now only
  `com.universaltill.payment-stripe` can receive the grant (`tapProviderPluginID`). Test
  `TestTapSettings_GrantRefusesForeignPlugin` added (409, nothing granted); the other tap-settings tests use the
  real plugin id. Follow-up card: enforce provider ownership at manifest/install level (the entry-offering path and
  the broker bind still trust the declared provider).
- Tester failure (auth `backgroundPollPaths`) is fixed and re-verified.
- Verified OK: grant form carries no permission name; grant needs `plugin_management`, is audited, bumps the plugin
  generation; Setup refused with no native call off the main till; demo mode denies all new routes; cloud read
  errors show "unknown", never "not set up"; bank decline code never reaches the cashier; i18n is English +
  `en.meta.json` only; panel text has no hardcoded strings; 56 px targets and logical CSS properties.
- Accepted: the grant route does not itself require the main till (a satellite manager can grant; the broker and
  tender gate still refuse taps there).
- Deferred: multi-leg tap refund unbound (see the Stripe plugin record); docs-shots image for `en/tap-to-pay` must be
  generated by CI (Linux fonts) before merge; the 4-step panel was not driven on a real iPhone (12+ handler tests).

## Verdict
GO after CI produces the docs-shots image and the suite is green.
