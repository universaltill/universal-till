# Review — cloud-terms accept step before a plugin-store Download registers the till (ut-docs#4791)

## Gap
ut-docs#4720 put the cloud-terms accept step on every operator-initiated
registration (Settings → Register now, the auto-register toggle, setup step 7).
The plugin store's **Download** still registered an unregistered till through
`enroll.EnsureRegistered` with no accept step, and so did
`POST /api/plugins/install-from-marketplace`. The cloud recorded those stores
as not accepted.

## Change
- `internal/pages/enrol_terms.go`: `termsGateLazyRegistration(ctx, d, ticked, locale)`.
  - Unregistered, with the current `TermsVersion` not accepted and no tick: refuse.
  - Ticked: `enroll.RecordTermsAcceptance`, so `register()` sends `terms_version` and `terms_locale`.
  - Already registered or already accepted: no change.
- `POST /api/plugins/store/download` (form `accept_terms`) and
  `POST /api/plugins/install-from-marketplace` (JSON bool `accept_terms`):
  - The gate runs before `EnsureRegistered`.
  - A refusal answers 428 `settings.enrol.terms_required` and registers or downloads nothing.
  - The marketplace handler gates before the "requested" status record, so a refusal leaves none behind.
  - A record failure answers 500 `settings.error.save_failed`.
- Store detail page (`plugins_store_detail.html`):
  - The existing `enrol_terms.html` partial sits above **Download** when the till is unregistered, not following a main till, and has not accepted.
  - An unticked box stops the click client-side, before the unverified-publisher prompt, focuses the box and shows the translated message. The server still enforces the gate.
  - Phone layout keeps the checkbox beside its wrapping label.
- Deliberately ungated: the wizard's base-plugin install (offline-first, must
  not block the wizard, and step 7 shows the step), cloud-directed installs,
  plugin update and TSE kickoff. These run on a till that already has an
  identity or as background work. A till registered that way is recorded
  not accepted, and Settings offers the box afterwards (ut-docs#4792). This is
  documented on the helper.
- No new `en.json` keys: the change reuses `settings.enrol.terms.*`,
  `settings.enrol.terms_required` and `settings.error.save_failed`, so no
  language-pack follow-ups.
- Help: `web/help/{en,de,tr,fa,ar}/plugins.md` step 2. `make docs-shots` was
  run; the manifest updated the surface hash and the plugins/ar topic hash.
  Unrelated PNG re-renders (catalog, categories, multitill) were reverted as
  environment noise.
