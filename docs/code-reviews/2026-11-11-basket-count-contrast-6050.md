# Review: basket count badge contrast in every theme (ut-docs#6050)

Date: 2026-11-11 · Lane: lane:cloud-41 · Branch: `fix/6050-basket-count-contrast`

## What shipped

- `web/public/app.css` `.basket-count` (the item-count pill next to the
  basket title): `--surface` text on `--text` instead of `--accent-contrast`
  on `--accent`. It is the same pair the phone tile in-basket badge uses
  (ut-docs#3241).
- `internal/pages/themes_test.go` `TestBasketCountBadgeContrast`: reads the
  colour/background tokens the rule really uses, resolves them per built-in
  theme (app.css `:root` + the theme's `:root`), and requires >= 4.5:1 (WCAG
  1.4.3). It also fails if any other selector in app.css or a theme file
  styles `.basket-count`, because that override would escape the check.
- `web/help/img/**`: regenerated by `make docs-shots` (the `web/public`
  change moves the surface hash; `sell.png` shows the new badge).

## Findings

Reviewer verdict: **Approve**. There were no high or medium findings.

1. Low, fixed: the rule regex matched only the bare top-level rule. A
   compound, descendant or `@media` override would have escaped the check.
   The test now fails on any other `.basket-count` selector in app.css or a
   theme file.
2. Low, no change: `decl()` requires a single `var(--token)` (an optional
   fallback is allowed), so a literal-colour edit fails loudly. That is
   intended.
