## #2618 Plugin settings: asked options (pouria-teimouri)
Checked fine: no XSS (html/template, no `template.HTML`, page script uses
`textContent`); answers bounded (16 KiB, 32 options, value 64 B, label 128 B,
unknown fields rejected); 5 s ask timeout with guest kill on cancel, the GET never
waits for the plugin; cache bounded (64 entries per plugin, 10 min TTL, keyed by
installed plugin id, no cross-plugin leakage); no secrets in the ask payload or logs;
route gated by `plugin_management` + same-origin + demo deny; no SQL in pages;
English-only keys with meta; help updated.
- **M1 major (security), not fixed (author's PR):** `validateSettingBoundPermissions`
  (`internal/plugins/permission_setting.go:91`) checks only that a
  `net:@setting:` / `tcp:@setting:` key is declared, not its type, and
  `plugin_settings_page.go:797` stores any plugin-shaped value for an `options_ask`
  choice. A signed manifest binding `net:@setting:server` to an `options_ask` choice
  lets the plugin answer `{"value":"http://192.168.1.1","label":"Cloud (recommended)"}`;
  the manager picks the friendly label and the LAN grant resolves to a host the
  plugin chose, never in the signed manifest. Fix: refuse a manifest whose
  setting-bound permission names an `options_ask` choice (with a test), mirror it in
  ut-cloud's manifest validator.
- m1 minor: a forged POST can store any allowed-shape value in an `options_ask`
  choice (not checked against the plugin's list); by design, needs
  `plugin_management`; only dangerous through M1.
- m2 minor: labels/values reject `unicode.IsControl` (Cc) only; bidi overrides
  (U+202E, U+2066–2069), zero-width characters and U+2028/2029 pass, so a label can be
  visually spoofed. Fix: also reject category Cf and U+2028/2029.
- m3 minor: one key declared in both `global` and `register` scope gives duplicate
  ids / `data-ps-ask` in `plugin_settings.html:470-481`; the ask message lands on the
  first field (the duplicate `name` predates this PR).
- Nits: a cached list still shows up to 10 min after `events:receive` is revoked
  (display only); the cache's `gen` map is never pruned on uninstall (tiny); a
  rejected answer's JSON error is logged at Info per ask; any `ParseForm` error is a
  413; the five `options_*` meta entries are out of order.
- Verdict: CHANGES NEEDED (M1).
