# Review — tree-pane zoom + shared origin recorder (ut-docs#2943, ADR-0122 §2/§4)

- **Date:** 2026-09-26
- **Branch:** `feat/2943-tree-pane-zoom`
- **Author lane:** `lane:cloud-54` (built on Opus 5.5)
- **Reviewer:** independent subagent on Fable (a different model), one round

## What shipped

- `web/ui/layouts/base.html` (first script): the ADR-0122 §2 origin
  recorder — `UT.motionOrigin` set on capture-phase `pointerdown` and
  Enter/Space `keydown` from the nearest
  `a, button, [hx-get], [hx-post], [role=treeitem], [data-zoom-origin]`;
  `UT.takeOrigin()` returns it once, 5 s expiry. A zoom registry
  (`UT.trackZoom` / `UT.finishZooms`). A tap finishes every running zoom and
  arms the existing 1 s click re-dispatch; for a finished zoom the click is
  re-dispatched whenever its target is not the element now under the
  pointer (§7). One `HTMLDialogElement.prototype.showModal/show` wrapper
  that finishes running zooms before the native call (§4/§5; #2944 extends
  it with the popup FLIP).
- `web/public/app.js`: `.ut-panel-fx` (#2338) replaced by `zoomPane()` —
  `el.animate()` from the tapped item's box to the pane box, uniform scale
  clamped 0.1–1 + translation, from opacity 0.4, `fill: 'none'`,
  `--ut-zoom-small-ms` (300 ms Full / 200 ms Balanced), bottom-centre
  fallback, skipped when the pane already shows `dialog[open]`; finished on
  `htmx:beforeSwap` into a pane. Only click/submit-triggered swaps zoom.
  `UT.motionOff()` (reduced motion / Light) still returns before any of it.
- `web/public/app.css`: `.ut-panel-fx` / `ut-panel-in` removed;
  `--ut-zoom-small-ms` on `:root` and in `html.fx-balanced`.
- Tests: Go static guards in `internal/pages/transitions_test.go` (two #2338
  pane-ease tests replaced); e2e `e2e/tests/tree-pane-zoom-2943.spec.ts`
  (Full geometry/transience, Balanced 200 ms, Light no animation, help
  search no zoom, mouse and touch tap mid-zoom, programmatic `show()`
  finishes the zoom); the pane half of `in-panel-dialog-transitions-2338`
  removed.
- `web/help/img/manifest.json`: surface hash only — no still pixel changes
  (motion only), per `guard-docs-shots.sh`.

Out of scope (their own cards): page zoom + `sessionStorage` back origin
(#2942), shared popup FLIP and removal of `.ut-dialog-fx` (#2944).

## Findings

| # | Sev | Finding | Outcome |
|---|---|---|---|
| 1 | major | `/help` search (`hx-trigger="input changed delay:200ms"` into `#manual-panel`) would zoom from the bottom centre on every debounced keystroke | **Fixed**: only `click`/`submit`-triggered swaps zoom; others keep `.ut-swap-fx`. e2e + static pin; e2e confirmed failing with the fix reverted (1 zoom recorded vs 0). |
| 2 | minor | Re-dispatch window never disarmed by a later press / `pointercancel` → possible click-through | **Fixed**: each `pointerdown` clears it first; `pointercancel` clears it. Static pin. |
| 3 | minor | After a re-dispatched mouse click, focus stayed on the control the moving mousedown hit | **Fixed**: `button, a[href]` added to the focus hand-over selector. |
| 4 | minor | Only a mouse tap during motion was tested (§8 asks touch too) | **Fixed**: `hasTouch` variant added. |
| 5 | nit | Mid-zoom mouse test could false-pass if the pane had nearly settled | **Fixed**: test slows the zoom to 3 s and asserts the button is not yet under the press point. |
| 6 | nit | Go tests could panic on a missing anchor | **Fixed**: indices guarded. |
| 7 | nit | `UT.motionOrigin.el` holds a node until the next press | Accepted — one entry, replaced on the next press. |

Reviewer confirmed OK: View Transition skip path unchanged; no recursion;
touch clicks re-hit-test so no double fire; keyboard clicks untouched; the
dialog wrapper keeps `this`, return value and native throws, cannot
double-wrap; zoom math correct around the default 50% 50% origin and
RTL-safe; every fixed descendant in a pane is a `<dialog>` opened via
`.show()`, so the wrapper covers the #2338 hazard.
