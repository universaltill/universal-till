# Sprachen & Anzeige

Die gesamte Kasse spricht Englisch, Türkçe, فارسی und العربية — einschließlich Rechts-nach-links-Layout — und passt sich mit einer Bildschirmtastatur und einstellbarer Textgröße an Touchscreens an.

## Verwendung

1. Ändern Sie die Sprache über das Menü; jede Person kann ihre eigene wählen — das ist eine Einstellung pro Browser und benötigt daher keine Manager-PIN.
2. Einstellungen → Sprache: legt die eigene Standardsprache dieser Kasse fest — verwendet für Benachrichtigungs-E-Mails und alles andere, das keinen eigenen Browser hat, den es fragen könnte (nicht nur diesen Bildschirm). Wird sofort angewendet, kein Neustart nötig. Dies ist getrennt vom Sprachwechsel pro Person oben im Menü: Der eigene Browser einer Kassiererin kann bei der von ihr gewählten Sprache bleiben, unabhängig davon, ob diese der Standardsprache dieser Kasse entspricht.
3. Einstellungen → Anzeige: passt die Oberflächenskalierung an Ihren Bildschirm an.
4. Einstellungen → Anzeige hat außerdem eine Auswahl für das **Geräteprofil**: **Kasse** (der Standard-Verkaufsbildschirm), **Backoffice** (eine Manager-Station für Berichte/Verwaltung — „/“ wird zur Berichtsseite statt zum Verkaufsbildschirm) oder **Selbstbedienungskiosk** (ein abgeschlossener, kundenseitiger Bestellbildschirm — anmeldefrei, sodass jedes Gerät im LAN des Geschäfts ihn erreichen kann). Es wird pro Kasse festgelegt, nicht geschäftsweit, sodass ein Geschäft eine beliebige Mischung aus Kassen, einem Backoffice-Gerät und einem oder mehreren Kiosken nebeneinander betreiben kann. Eine Änderung fragt immer nach einer Manager-PIN. Das Umschalten eines angemeldeten Bildschirms auf Selbstbedienungskiosk meldet die Sitzung dieses Bildschirms sofort ab, damit er nie einen Navigationsschritt von einer entsperrten Einstellungsseite entfernt ist, sobald er kundenseitig ist — Kasse und Backoffice melden Sie nie ab. Nur der umgeschaltete Bildschirm ist betroffen: Ein Manager, der auf einem anderen Gerät angemeldet bleibt, behält seine Sitzung.
5. Die Bildschirmtastatur öffnet sich automatisch auf Touchscreens (oder erzwingen Sie sie an/aus in den Anzeigeeinstellungen).
6. Einstellungen → Kassen: Geben Sie dieser Kasse einen eigenen Namen (z. B. „Vordere Theke“), damit sie leicht von anderen Kassen zu unterscheiden ist — angezeigt auf der Seite „Kassen“ und standardmäßig „Kasse 1“, bis Sie einen festlegen.
7. Einstellungen → Kassen: „Register dieser Kasse“ legt fest, welches Register diese Kasse ist. Bei nur einem Register wird es automatisch gewählt; bei einem Geschäft mit mehreren Registern wählen Sie es hier aus — Barauszahlungen (wie eine Pfandrückgabe) werden gegen die offene Schicht dieses Registers gebucht, und die Kasse verweigert eine Auszahlung, solange sie nicht weiß, welches Register sie ist.
8. Einstellungen → Geschäftsart: die Art des Geschäfts, die Sie im Einrichtungsassistenten gewählt haben (Café, Einzelhandel, Dienstleistung, Gastronomie, Marktstand oder Sonstiges) — hier jederzeit änderbar.
9. Einstellungen → Daten → Beispieldaten: Haben Sie beim Einrichten den Startkatalog geladen, entfernen Sie hier alles mit einem Tipp — Beispielartikel, die 3 Beispielkunden und die 3 Beispiel-Aktionscodes zusammen, damit ein Rabattcode aus den Demodaten nicht einlösbar bleibt, nachdem Sie darüber hinaus sind. Haben Sie noch keinen echten Verkauf getätigt, entfernt diese Schaltfläche alle Beispielzeilen bedingungslos — auch einen Artikel, den Sie beim Ausprobieren der Kasse umbenannt, im Preis geändert oder mit einer neuen SKU versehen haben —, damit ein versehentlich gesetztes Häkchen bei „Beispieldaten laden" nie einen dauerhaften Rest hinterlässt. Sobald die Kasse einen echten Verkauf verbucht hat, markiert das Bearbeiten eines Beispielartikels ihn als „Ihren eigenen"; die Schaltfläche listet ihn dann gesondert auf, mit dem tatsächlichen Grund, warum er behalten wurde, und was zu tun ist: Ein bearbeiteter Artikel bietet direkt in dieser Liste **Trotzdem entfernen** oder **Als eigenen Artikel behalten** an; ein Artikel, der wirklich verkauft oder im Bestand angepasst wurde (ob Beispiel oder echt), wird über diese Schaltfläche nie entfernt — diese Datensätze bleiben zum Schutz Ihrer Verkaufshistorie erhalten, und die Liste verweist Sie für den allgemeinen Weg „Deaktivieren, dann bereinigen" auf die Katalogbereinigung (ebenfalls auf dieser Seite, im Abschnitt nur für Manager weiter oben — Einstellungen → Daten → Katalogbereinigung). Befindet sich gerade ein Beispielartikel oder -kunde im Warenkorb der Kasse (Kassierer oder Selbstbedienung), wird die Entfernung blockiert, bis der Warenkorb geleert ist — leeren Sie ihn und versuchen Sie es erneut.
10. Einstellungen → Anzeige hat außerdem eine Fenstermodus-Auswahl (normal, maximiert, Vollbild, Kiosk), einen Schalter für „Beim Start starten“ und daneben eine Aktion „Zum Betriebssystem-Fenster verlassen“ (fragt nach einer Manager-PIN). „Zum Betriebssystem-Fenster verlassen“ verlässt Vollbild/Kiosk sofort und übergibt das Fenster der Kasse zurück an den Desktop des Betriebssystems — und die Kasse meldet erst „Zum Betriebssystem verlassen.“, wenn das Fenster wirklich zurückgekehrt ist; ist das Fenster nicht erreichbar, teilt sie dies mit, und nichts ändert sich. Auf dem Linux-Desktop gilt alles sofort, kein Neustart nötig — Vollbild/Kiosk verbergen die eigene Fensterdekoration des Betriebssystems — und es funktioniert gleichermaßen, ob die Universal-Till-Desktop-App die Kasse selbst gestartet hat oder einer bereits im Hintergrund laufenden Kasse beigetreten ist (eine reguläre .deb-Installation); „Beim Start starten“ gilt erst beim nächsten Start der Kasse (fügt einen echten Autostart-Eintrag hinzu oder entfernt ihn). Vollbild und Kiosk greifen nur, solange die Desktop-App läuft und das Fenster hält: Tut sie das nicht, zeigt der Anzeigebereich einen entsprechenden Hinweis, der Bildschirm bleibt ein normales Fenster, und Ihre gespeicherte Wahl wartet einfach auf den nächsten App-Start — eine Kasse kann sich also nie in einen Vollbildmodus einsperren, aus dem es keinen Ausweg gibt. Antwortet „Zum Betriebssystem-Fenster verlassen“, dass das Fenster nicht erreichbar ist, läuft die Desktop-App nicht (oder wurde gerade beendet): Starten Sie die Universal-Till-App, oder schließen Sie das Fenster einfach wie gewohnt über das Betriebssystem; antwortet sie, dass das Fenster zum Schließen aufgefordert wurde, dies aber noch nicht bestätigt hat, schauen Sie auf den Bildschirm der Kasse — das Fenster ist auf dem Rückweg, und das Verlassen wird dennoch aufgezeichnet. An einer Raspberry-Pi-Kiosk-Kasse ist die Fenstermodus-Auswahl ebenfalls echt und wirkt sofort, kein Neustart nötig: Schalten Sie auf „Kiosk“, aktiviert sich der dedizierte Kioskbildschirm sofort; schalten Sie auf etwas anderes, deaktiviert er sich (der „Beim Start starten“-Schalter des Pi bleibt Gerüst — das Gerät startet den Kioskbildschirm ohnehin von selbst beim Booten); „Zum Betriebssystem-Fenster verlassen“ teilt auf einer Pi-Appliance offen mit, dass es keinen Betriebssystem-Desktop zum Verlassen gibt — nichts ändert sich, und der Fenstermodus-Schalter ist Ihr Weg zurück; statt des Hinweises zur „Desktop-App“ nennt der Anzeigebereich auf einem Pi das Gerät eine dedizierte Kiosk-Appliance und verweist auf die Fenstermodus-Auswahl. Auf einer Pi-Appliance ist der Kioskbildschirm der einzige Bildschirm — das Umschalten weg von „Kiosk“ schließt ihn, und dahinter liegt keine Konsole, sodass Sie ein anderes Gerät im selben Netzwerk (oder SSH) brauchen, um ihn zurückzuschalten. Unter macOS und Windows speichert die Kasse Ihre Wahl für Fenstermodus und „Beim Start starten“, das Fenster bleibt jedoch ein normales Fenster, bis die Unterstützung für diese Plattform erscheint — es wird dort nie Vollbild, es gibt also nichts, worin man sich einsperren könnte. Auf einem Raspberry Pi mit Desktop (Raspberry Pi OS „mit Desktop“) richtet eine frische Installation dies alles für Sie ein: Die Kasse startet im Kioskmodus und öffnet sich beim Anmelden im Vollbild über dem Desktop. Bei einem Kaltstart kann es bis zu einer Minute dauern, bis das Fenster erscheint — der Bildschirm zeigt in der Zwischenzeit den nackten Desktop, was erwartungsgemäß ist und kein Einfrieren bedeutet; geben Sie ihm diese Minute, statt neu zu starten, denn ein Neustart beginnt dieselbe Wartezeit nur erneut. Sobald es erscheint, bleiben der Desktop und alles darauf direkt darunter, und „Zum Betriebssystem-Fenster verlassen“ (mit PIN) ist Ihr Weg dorthin zurück, um Updates zu installieren oder andere Programme zu nutzen. Diese Installationsentscheidung wird im Prüfprotokoll der Kasse festgehalten, sodass Sie immer sehen können, wann und warum sie getroffen wurde. Möchten Sie das nicht? Ändern Sie den Fenstermodus hier jederzeit, oder wählen Sie vor der Installation ab, indem Sie die Markierungsdatei `/etc/unitill/no-desktop-kiosk-overlay` anlegen (im Terminal: `sudo mkdir -p /etc/unitill && sudo touch /etc/unitill/no-desktop-kiosk-overlay`) — getrennt von der Markierung `/etc/unitill/no-kiosk` des kopflosen Kiosks, die verhindert, dass ein reiner Bildschirm-Pi zu einer dedizierten Kiosk-Appliance wird. Und sitzt die Kasse gerade am Anmeldebildschirm — Vollbild oder Kiosk, ohne dass jemand angemeldet ist —, hat der Anmeldebildschirm selbst einen eingeklappten Link „Ausgesperrt? Zurück zum Desktop“ mit derselben manager-PIN-geschützten Aktion, sodass das Anmelde-Tor niemals zur Falle wird. In der Android-App pinnt der gewöhnliche Kassenbetrieb (Verkaufsbildschirm, Einrichtung, Einstellungen, Anmeldebildschirm) den Bildschirm nie — die Status-/Navigationsleisten bleiben verborgen, aber Home, Zuletzt verwendet und die Benachrichtigungsleiste funktionieren normal, sodass Sie nie auf einem Bildschirm ohne Ausweg festsitzen. Nur das Umschalten des Geräteprofils auf **Selbstbedienungskiosk** bittet Android, den Bildschirm anzuheften (Home, Zuletzt verwendet und die Benachrichtigungsleiste sind dann alle blockiert, da dieser Bildschirm Kunden zugewandt ist) — dafür gibt es hier keinen separaten Fenstermodus-Schalter. Auf einem Tablet, das nicht als verwaltetes Gerät eingerichtet ist, zeigt Android beim ersten Mal eine eigene „Verstanden/Nein danke“-Abfrage an, und das Anheften greift erst, sobald Sie **Verstanden** antippen: Wird diese Abfrage abgelehnt oder einfach stehen gelassen, sieht der Bestellbildschirm genau gleich aus, aber Home und Zuletzt verwendet funktionieren weiterhin, sodass jeder die App verlassen kann. Die Kasse teilt mit, wenn dies passiert ist — ein roter Balken erscheint oben auf dem Kioskbildschirm mit dem Text „Kiosk-Sperre ist nicht aktiv — dieses Gerät ist nicht gesichert“. Das Bestellen unter dem Balken funktioniert weiterhin normal; tippen Sie auf Androids Abfrage auf **Verstanden** (schalten Sie das Profil weg und wieder zurück, falls die Abfrage verschwunden ist), und der Balken verschwindet von selbst innerhalb weniger Sekunden. Dieselbe PIN-geschützte Aktion „Zum Betriebssystem-Fenster verlassen“ (aus den Einstellungen oder über den Link „Ausgesperrt? Zurück zum Desktop“ am Anmeldebildschirm, der von einem angehefteten Selbstbedienungstablet aus erreicht wird) löst die Anheftung. Das Tippen auf das Schloss-Symbol am Selbstbedienungsbildschirm löst sie nicht von selbst: Der sich öffnende Anmeldebildschirm bleibt angeheftet — auch wenn der Bildschirm zwischenzeitlich in den Ruhezustand geht und wieder aufwacht —, bis eine Manager-PIN eingegeben wird, damit ein herumtippender Kunde nicht zum Home-Bildschirm des Tablets gelangen kann. Das Zurückschalten des Geräteprofils auf Kasse (oder Backoffice) löst die Anheftung, sobald die Kasse auf einem gewöhnlichen Bildschirm landet.
11. Die Wahl eines Landes im Einrichtungsassistenten ruft im Hintergrund automatisch dessen kostenlose Plugins ab (heute: das passende Sprachpaket) — keine Suche im Marktplatz nötig, und es funktioniert auch offline, mit automatischem erneutem Versuch, sobald das Netzwerk zurück ist. Solange eines noch installiert wird (oder auf den nächsten Versuch wartet), zeigt Einstellungen → Daten einen kleinen Hinweis mit einer Schaltfläche „Entfernen“, falls Sie es nicht möchten — nichts ist endgültig festgelegt.
12. Einstellungen → Daten → Transaktionshistorie löschen: löscht ALLE Verkäufe, Schichten und Rechnungen der laufenden Kasse auf einmal (nicht nur Testdaten) — gedacht als einmaliger Reset vor dem Livegang, nicht als Routineaufgabe. Katalog, Benutzer, Einstellungen und archivierte Berichte bleiben erhalten, nichts wird zerstört: Die gelöschten Datensätze wandern in ein datiertes Reset-Archiv (siehe nächster Schritt) und können wiederhergestellt werden, solange die Kasse seit dem Reset noch nicht gehandelt hat. Die Schaltfläche verlangt eine Manager-PIN, bevor sie etwas bewirkt — selbst wenn Sie bereits als Manager angemeldet sind, denn dies bestätigt im Moment einer so großen Aktion erneut, dass Sie es wirklich sind — und die Aktion selbst wird im Prüfprotokoll festgehalten.
13. Einstellungen → Daten → Archive zurücksetzen: Jedes Mal, wenn Sie die Transaktionshistorie löschen, landet dieser Stapel hier, statt zu verschwinden. **Wiederherstellen** bringt die Verkäufe, Schichten und Rechnungen eines Stapels vollständig und genau wie zuvor in die laufende Kasse zurück — jedoch nur, solange die Kasse seit dem Reset keine neuen Transaktionen hatte, und nur, wenn nichts, worauf der Stapel verweist (ein Produkt, ein Lagerort oder ein Kunde), danach selbst entfernt wurde, z. B. durch Entfernen von Beispieldaten, Katalogbereinigung oder eine DSGVO-Löschung. **Endgültig löschen** entfernt einen Stapel dauerhaft — ein Stapel mit echter Handelshistorie ist jedoch durch die Aufbewahrungsregeln Ihres Landes geschützt und kann vor seinem Aufbewahrungsdatum nicht gelöscht werden; dieses wird bis dahin anstelle der Löschen-Schaltfläche daneben angezeigt. Beide Aktionen verlangen vorher eine Manager-PIN.
14. Einstellungen → Daten → Katalogbereinigung: entfernt dauerhaft inaktive Produkte, die nie verkauft wurden und keine Bestandshistorie haben — alles, was jemals verkauft wurde, bleibt für Ihre Unterlagen erhalten. Erst eine Vorschau ansehen — die anschließende PIN-Abfrage nennt die Anzahl der zu entfernenden Produkte — dann mit einer Manager-PIN bestätigen.
15. Einstellungen → Daten → Kunde löschen (DSGVO): Suchen Sie einen Kunden nach Name, Telefon oder E-Mail und löschen Sie auf Anfrage dessen persönliche Daten. Vergangene Verkäufe bleiben für Ihre Unterlagen erhalten, zeigen aber nicht mehr, wem sie gehörten — der Verkauf selbst wird nicht gelöscht, nur die Verknüpfung zur Identität dieses Kunden.
16. Einstellungen → Barcode-Typen: welche Barcode-Arten dieses Geschäft scannt und eingibt — siehe [Katalog, Varianten & Barcodes](/help/catalog) für die Bedeutung jedes Typs und wann man ihn aktiviert.
17. Deutsche Geschäfte mit dem verwalteten TSE-Dienst (Beleg-Signierung): Solange die TSE-Einrichtung noch läuft oder fehlgeschlagen ist, zeigen die Einstellungen einen Statushinweis mit dem genauen Stand. Wurde die Einrichtung abgelehnt (zum Beispiel wegen eines noch fehlenden aktiven Abonnements), beheben Sie die Ursache und drücken Sie dort auf **Erneut versuchen** — die Kasse unternimmt den Versuch sofort erneut und zeigt das Ergebnis unmittelbar an. Direkt nach dem Einrichtungsassistenten erscheint derselbe Fehler zusätzlich oben auf dem Verkaufsbildschirm, damit er nicht übersehen werden kann. Ein Hinweis auf eine fehlgeschlagene Einrichtung kann nicht ausgeblendet werden, solange Ihr Geschäft ein funktionierendes TSE benötigt, um echte (systemrelevante) Verkäufe zu erfassen; ein Hinweis auf eine noch laufende Einrichtung lässt sich wie bisher ausblenden.
