# Languages & display

The whole till speaks English, Türkçe, فارسی and العربية — including right-to-left layout — and adapts to touch screens with an on-screen keyboard and adjustable text size.

## How to use it

1. Change the language from the menu; each user can pick their own — that's a per-browser choice, so it doesn't need a manager PIN.
2. Settings → Language: sets this till's own default language — used for notification email and anything else that has no browser of its own to ask (not just this screen). Applies immediately, no restart needed. This is separate from the menu's per-user language switch above: a cashier's own browser can stay on whatever language they picked, whether or not it matches this till's default.
3. Settings → Display: adjust the UI scale for your screen.
4. The on-screen keyboard pops up automatically on touch screens (or force it on/off in Display settings).
5. Settings → Tills: give this till its own name (e.g. "Front Counter") so it's easy to tell apart from other tills — shown on the Tills page and defaults to "Till 1" until you set one.
6. Settings → Tills: "This till's register" tells the till which register it is. With a single register it's picked automatically; on a shop with more than one register, choose it here — cash payouts (like a bottle-deposit refund) are recorded against this register's open shift, and the till will refuse to record a payout until it knows which register it is.
7. Settings → Shop type: the kind of business you picked in the setup wizard (café, retail, service trade, hospitality, market stall or other) — change it here any time.
8. Settings → Data → Sample data: if you loaded the starter catalogue during setup, remove it all here with one tap — sample items, the 3 sample customers, and the 3 sample promo codes together, so a discount code from the demo data doesn't stay redeemable after you've moved on. Anything already in real use is kept (your sales history stays intact, and a sample customer or promo you've actually started using survives) — the till tells you how many it removed and how many it kept. If a sample item or customer is currently in the till's basket (cashier or self-order), removal is blocked until the basket is cleared — clear it and try again.
9. Settings → Display also has a **Device profile** selector: **Register** (the default sell screen), **Back office** (the manager dashboard), or **Self-order kiosk** (the locked-down, customer-facing screen where shoppers browse the catalog and build their own order — see [Self-order](/help/self-order)). This is per-till, not shop-wide — it never syncs over the LAN — so one shop can mix ordinary registers, a back-office station, and one or more self-order kiosks at the same time. Switching this till to Self-order kiosk signs out the browser making the switch immediately, the same as tapping Log out: the self-order screen is reachable with no PIN by design, so nothing is left behind that could hand a customer a live staff session. Register and Back office never sign you out. Changing this setting needs a manager PIN, the same as the other Display settings here.
10. Settings → Display also has a window-mode selector (normal, maximized, fullscreen, kiosk), a launch-on-startup toggle, and an "Exit to OS window" action next to them (asks for a manager PIN). Exit to OS window leaves fullscreen/kiosk right away and hands the till's window back to the OS desktop — and the till only says "Exited to OS." once the window really came back; if the window can't be reached, it tells you so and nothing changes. On Linux desktop everything applies immediately, no restart needed — fullscreen/kiosk hide the OS's own window chrome — and it works the same whether the Universal Till desktop app started the till itself or joined a till already running in the background (a standard .deb install); launch-on-startup still applies the next time you start the till (adds or removes a real autostart entry). Fullscreen and kiosk only actually engage while the desktop app is running and holding the window: if it isn't, the Display section shows a note saying so, the screen stays a normal window, and your saved choice simply waits for the next time the app runs — so a till can never lock itself into a full screen it has no way out of. If Exit to OS window answers that the window can't be reached, the desktop app isn't running (or has just stopped): start the Universal Till app, or simply close the window from the OS as usual; if it answers that the window was asked to close but hasn't confirmed yet, look at the till's screen — the window is on its way back, and the exit is still recorded. On a Raspberry Pi kiosk till, the window-mode selector is real too and applies immediately, no restart needed: switch it to "kiosk" and the dedicated kiosk screen turns on right away; switch it to anything else and it turns off (the Pi's launch-on-startup toggle stays scaffolding — the box already starts the kiosk screen on its own from boot); Exit to OS window tells you plainly on a Pi appliance that there's no OS desktop to leave — nothing changes, and the window-mode toggle is your way back; instead of the "desktop app" note, the Display section on a Pi says it's a dedicated kiosk appliance and points you at the window-mode selector. On a Pi appliance the kiosk screen is the only screen — switching away from "kiosk" closes it and there's no console behind it, so you'll need another device on the same network (or SSH) to switch it back. On macOS and Windows, the till saves your window-mode and launch-on-startup choices, but the window stays a normal window until that platform's support ships — it will never go fullscreen there, so there's nothing to get stuck in. On a Raspberry Pi that runs a desktop (Raspberry Pi OS "with Desktop"), a fresh install sets all this up for you: the till starts in kiosk mode and opens fullscreen over the desktop at login. On a cold boot the window can take up to a minute to appear — the screen shows the bare desktop in the meantime, which is expected, not a freeze; give it that minute rather than restarting, since a restart just starts the same wait over again. Once it appears, the desktop and everything on it stay right underneath, and Exit to OS window (with the PIN) is your way back to it, to install updates or use other programs. That install-time decision is recorded in the till's audit trail, so you can always see when and why it happened. Don't want it? Switch the window mode here any time, or opt out before installing by creating the marker file `/etc/unitill/no-desktop-kiosk-overlay` (in a terminal: `sudo mkdir -p /etc/unitill && sudo touch /etc/unitill/no-desktop-kiosk-overlay`) — separate from the headless kiosk's `/etc/unitill/no-kiosk` marker, which keeps a screen-only Pi from becoming a dedicated kiosk appliance. And if the till is sitting at the sign-in screen — fullscreen or kiosk, with nobody signed in — the login screen itself has a collapsed "Locked out? Return to desktop" link carrying the very same manager-PIN-gated action, so the sign-in gate is never a trap. On the Android app, the till pins itself into place automatically (Home, Recents and the notification shade are all blocked) — there's no separate window-mode toggle to set here, and the same "Exit to OS window" PIN action (from Settings, or the same "Locked out? Return to desktop" link at the sign-in screen for a self-order tablet nobody's signed into) releases it; leaving Settings, or switching away from the till app and back, re-engages it automatically.
11. Picking a country in the setup wizard automatically fetches that country's free plugins (today: the matching language pack) in the background — no marketplace hunting required, and it works even if you're offline at the time, retrying on its own once the network's back. While one is still installing (or waiting to retry), Settings → Data shows a small note with a Remove button if you'd rather not have it — nothing is locked in.
12. Settings → Data → Clear transaction history: wipes ALL sales, shifts and invoices from the working till in one go (not just test ones) — meant as a one-time reset before going live, not something to do routinely. The catalog, users, settings and archived reports are kept, nothing is destroyed: the cleared records move into a dated reset archive (see the next step) and can be restored for as long as the till hasn't traded since. Typing "RESET" into the confirm field is required before the button does anything, and the action itself is recorded in the audit log.
13. Settings → Data → Reset archives: every time you clear transaction history, that batch lands here instead of vanishing. **Restore** (type "RESTORE" to confirm) brings a batch's sales, shifts and invoices back into the working till whole and exactly as they were — but only while the till has had no new transactions since the reset, and only if nothing the batch references (a product, stock location or customer) was itself removed afterwards, e.g. by sample-data removal, catalog cleanup or a GDPR erasure. **Delete permanently** (type "PURGE" to confirm) removes a batch for good — but a batch holding real trading history is protected by your country's retention rules and can't be deleted before its retention date, shown next to it instead of the delete button until then.
14. Settings → Data → Catalog cleanup: permanently removes inactive products that were never sold and have no stock history — anything ever sold stays, for your records. Preview first to see what would go, then type "CLEANUP" to confirm the removal.
15. Settings → Data → Erase a customer (GDPR): search for a customer by name, phone or email and erase their personal details on request. Their past sales are kept for your records, but no longer show who they belonged to — the sale itself isn't deleted, only the link to that customer's identity.
16. Settings → Barcode types: which kinds of barcode this shop scans and enters — see [Catalog, variants & barcodes](/help/catalog) for what each type means and when to turn one on.
