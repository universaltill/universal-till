# Multiple tills (one shop)

## Tills & devices

Everything about your tills is in one place: **Settings → Tills & devices**. It is one list of sections in the Settings tree, with no page or button in between (the old Tills page and its tabs, and the old Till registration and Subscription cards, all lead here):

- **This till**: one sentence saying what this till is ("This is the main till of …"), its role, a banner with one button if it was replaced or cannot reconnect to the shop by itself, and its name and register with **one Save** button. A till that is reconnecting by itself only says so (**Reconnecting…**): nothing to press. The device ID and the key fingerprint are under **Technical details**.
- **Shop and sync**: your shop account (claiming and registration), your plan, and **Reconnect this till to a shop** with the code field always visible. Underneath: who on the network may reach this till, the network security key, the copy of every sale and the quarantined entries.
- **Other tills**: the tills working on this shop network, live. A banner at the top says in plain words if something needs tidying and has the one button that fixes it, or says that nothing is needed. Phones used as card readers are listed in **Card readers**.
- **Old entries** (under Other tills, with a count): tills your shop account still lists that are not set up on this till, or that this till lists and your account no longer does. Each has a **Remove old entry** button. Removing asks for the manager PIN in a box right under the button: type it and press the button again (Escape closes the box). If a live till with another name was seen after the old entry, the entry offers **This is the same phone as …: replace**; that is only a hint, so check it is really the same phone. **Remove old entries** (several at once) asks for the PIN once. Its past sales stay. When your account cannot be read, nothing is called old and the section says it cannot check.
- **Add a till**: choose what you need (another till of this shop, join an existing shop, or replace this till), then the pairing code and QR, the join form, finding a main till on the network and pairing requests waiting for approval.
- **Card readers**: phones paired as card readers.
- **Kiosk** and **Notices**: the self-order kiosk's payment mode and idle reset, and the notice inbox.

Every address that used to open the Tills page (for example /tills or /tills?tab=add) now opens the matching section here.

If a device you paired before asks to join again with the same name (for example after it was reset), the request is marked **Already enrolled here**; approving it replaces the old entry, keeping the till's number and receipt prefix, so you do not need to rename it. A different device that is online right now and uses the same name is still refused.

Run several tills on the same shop network: one is the main till, the others join it and share the catalog, prices, settings and stock automatically. Photos you upload for items and categories on the main till follow within about half a minute, so every till shows the same pictures. A photo you remove on the main till disappears from the other tills too, about an hour later and never in the middle of a sale; a photo uploaded directly on a joined till is left alone. If the main till suddenly has no photos, or far fewer all at once (for example after its photo folder was lost or restored), the other tills keep theirs and a warning appears in the till's problems list instead.

## When you need a second till

- **A second counter, or busy periods.** Add an **additional till**. It rings up sales like any other till, keeps selling if the network drops, and shares the shop's catalog and settings.
- **A kiosk or order station.** Join it as a **satellite** (see "Additional tills and satellites" below). It needs the main till to work.
- **A standby that can take over.** Turn on the copy of every sale on each additional till (see "A copy of every sale on every till"). If the main till dies, you can promote one of them (see "When the main till was replaced").

## What is shared and what stays on each till

Shared across the shop (the main till decides, and every till follows):

- the catalog, prices, shop-wide settings, operators and customers;
- stock (a joined till's own number is only a copy);
- registers;
- plugins installed from the plugin store;
- photos uploaded on the main till;
- gift vouchers;
- sales, which flow from every till back to the main till.

Stays on one till only:

- photos uploaded directly on a joined till;
- plugins imported from a file;
- settings that belong to one till (its printer, its screen and display mode, its own register);
- a joining till's own sales from before it joined (they stay only in a copy in that till's backups folder).

## How to use it

1. On the **main till**, open **Settings → Tills & devices → Add a till**, then press **Show pairing code**. It shows a short code such as **K7P-4XQ**, the main till's address underneath it (for example 192.168.1.10:8080), and a QR code that the joining till can scan. The code works once and expires after 10 minutes. The full long code is still there too, under **Full code for copy & paste**, for when you'd rather copy and paste than type.
2. On the **second device**, install the till app. On its first setup screen choose **Join an existing shop**. There are two ways to join: find the main till on the network automatically, or enter the pairing code by hand.
3. Give this till a name once, above the two options — it's required, and the field turns red with a message if you try to search or enter a code before filling it in. Then pick an option: **Find on this network** (easiest): press **Find a main till on this network**, pick the main till from the list (to make sure it's the right device, compare the **Till ID** in the list with the **Till ID** under the main till's name on that till's own **This till** section — they're the same), and press **Request to pair**. Both screens now show the same 6-digit code — check they match, then approve the request on the main till (see "Approving a pairing request" below). The request usually shows up on the main till's **Add a till** section within a second or two; if it doesn't, it appears within 30 seconds, without reloading the page. A manager doesn't have to already be on Tills & devices to notice: on the main till, a request pending anywhere shows a dismissible notice at the top of the screen and a badge on the sync chip in the side rail (see step 11) — dismissing the notice doesn't approve or deny anything, it just hides it until a new request arrives or the till app is restarted. If pairing fails, the reason stays on screen until you try again — no need to reload the page. The request expires after 10 minutes if nobody approves it. Or **Enter a pairing code**: the quickest way is **Scan QR code** — point this device's camera at the QR code on the main till's pairing screen; the code field fills in and the main till's address is shown (nothing is sent yet). Add this till's name and press Join. If the camera is not allowed or there is none, or you would rather type, type the short code from step 1 into the Pairing code box (capitals or small letters, with or without the dash) and the main till's address, exactly as shown, into the Main till's address box, then press Join. If you paste the full long code instead, leave the address empty — the full code already contains it. The code is what authorises the enrolment — the main till's address on its own is not enough. For safety the main till accepts only a few wrong codes: after five tries within a minute from the same till it asks you to wait a minute, and after ten wrong codes in total it cancels the code it is showing — press **Show pairing code** again for a new one. The name must be unique on this shop's network: if the join is rejected because the name is already in use (by the main till or another joined till), pick a different name and try again. The one exception is a till that was replaced: if a till with that name was enrolled before and has not been seen for 24 hours, a manager can approve the pairing request on the main till (the request is flagged **Already enrolled**) and the new device takes over that till's place, with the same name, till ID and receipt numbering; the old device stops working. This only works when the request is approved for that exact name, never with a typed code alone. A till that is already running on its own (not joined to a main till, with no other tills joined to it, and not set up as a shop's main till from my.universaltill.com) also looks for a main till on the network by itself — shortly after it starts and then every few minutes. When it finds one, a manager sees a notice at the top of every screen naming that main till: type this till's name and press **Link this till** to send the same pairing request as **Request to pair** (the code check and the approval on the main till are exactly as above), or press ✕ to stop being asked on this till for good. If this till already has sales of its own, the notice also warns that linking replaces everything on it — sales, products and settings — with the main till's copy, and **Link this till** only works once you tick **Replace this till's sales and data**. In Add a till, the join section warns the same way above its two options, and **Request to pair** and Join only work once you tick the same box. If the first sale is rung up after the page opened, or while the till is joining, the join stops with the same warning and the tick box appears above the options — tick it and try again. If it stopped part-way through, this till takes itself off the main till's list again, so you can retry with the same name. Only if the main till could not be reached at that moment does it still list this till: then revoke that entry on the main till's **Other tills** section first (or, if it has not been seen for 24 hours, approve the pairing request to replace it), or use a different name. This till's own sales are not sent to the main till; they stay only in a copy in this till's backups folder. Close the day and print the Z report first if you need it.
4. Wait for it to finish. It copies the whole shop across — catalog, prices, settings, stock and operators — so on a busy shop network this can take up to a minute. Do not press Join twice: the token is single-use, and a second press fails with "code used or expired". When the screen says the till has joined, the screen shows **Restart now**. In Add a till, press it to finish: the till restarts and comes back after a few seconds. On the first setup screen the till restarts by itself, and the same button is there in case it doesn't. On Windows the till can't restart itself yet — close the window and reopen Universal Till instead.
5. If it fails, the reason appears under the button. The most common causes are the two tills not being on the same network, a mistyped address, and a code that has expired or was already used (show a new one on the main till). If **Scan QR code** says camera access was denied, allow the camera for Universal Till in the device's settings, or type the code instead; if it says the QR is not a Universal Till pairing code, scan the one on the main till's **Show pairing code** screen. Press **Clear scanned code** to scan again or to type a code instead. On an iPhone or iPad, the first search asks whether Universal Till may use the local network — allow it. If it was refused, the screen says so: turn on **Local Network** for Universal Till in the device's Settings (Privacy & Security → Local Network), or enter a pairing code instead. If it says the main till only accepts secure connections, update this till if it runs an older version than the main till, otherwise restart both tills, and try again; if it says the main till can't offer a secure connection, restart the main till and try again. To set up the **first till** of a shop you already created on my.universaltill.com, choose **Main till (first till of the shop)** under **Join as**: the main till's address box goes away and you type the pairing code from my.universaltill.com (your shop, then Tills, then Add a till). The till then shows your shop's name, country, currency and — when you chose one on my.universaltill.com — its shop type for you to confirm — **This is not my shop** drops the pairing — and asks only for the signing-device details in Germany and the admin PIN (plus the shop type, only for a shop that has none on my.universaltill.com yet). The type chosen on my.universaltill.com is the one the till saves. Nothing is saved until you press **Start selling**; the till then syncs in the background and a "Syncing your shop" page shows until your products have arrived, then the sale screen opens by itself (the import welcome appears only if your shop really has no products). The sale screen then shows a manager a **Next steps** card: set your staff PINs, set up the card terminal and printer, count your stock, and — on a plan that does not keep products in the cloud — add your products. Each line opens the page for it; ✕ closes the card for good on this till. If the code is wrong or expired, or you are offline, the screen says so under the button. If the shop already has a main till, the screen names it and when it was last seen: to replace it with this device, the shop owner chooses **Replace this till** for it on my.universaltill.com and you type that new code here, or join it with **Additional till**. With a replace code the till first asks **Replace "…"?**: it names the old main till, when it was last seen and that sales made on it after that are lost, says what this till gets from the cloud, and that sales history, customers and staff PINs come back only from a backup file of the old till (Settings → Backups, after setup). **Replace** makes this till the shop's main till and removes the old one for good; **Cancel** keeps the code for another try until it expires. After a replace, **Your shop** names the till it replaced and does not offer **This is not my shop**. If the old till is still connected, or the code was made for another till, the screen says so under the button.
6. Sales made on any till flow back to the main till, and catalog changes spread to all tills within about half a minute.
7. On a joined till, Catalog changes (items, prices, variants, barcodes, modifiers, categories and quick-sale buttons) are sent to the main till and saved there, so they reach every till and are not undone by the next sync — a banner at the top of Catalog and Inventory says so. The main till checks with its own staff list that you're allowed to make the change. While the main till can't be reached, the banner says so instead and a change is refused with a message, nothing saved: make it again when the main till is back. While it can't be reached, the fields and save buttons on Catalog, Categories and the category list on the Quick Buttons page are greyed out, so you see this before you start typing; they come back by themselves, together with the banner, once the main till answers again. If the item was changed on another till since you opened it, you're asked to reload the page rather than overwrite that change. Photos are not sent this way (see the photo note above). The banner also has a link to the same page on the main till: on Windows and Mac it's a clickable link; on the kiosk app it's plain text instead, since the kiosk has no way back if a link took it to another till's screen. The New buttons on those pages are greyed out too, their category lists can't be dragged into a new order, and on the sale screen holding a tile doesn't open the quick-button edit mode — a note says why instead.
8. Stock is decided by the main till only. A joined till never refuses a sale for being out of stock — its own stock number is just a copy that can lag a few seconds behind, so it always lets the sale through. If that means an item's stock genuinely goes below zero (two tills selling the last one at almost the same moment), it shows up as a problem on the main till's dashboard rather than blocking anyone's sale.
9. In **Other tills** on the **main till**, the list also shows the main till itself (labelled "this till") alongside any joined tills, using the name set in Settings — so a single-till shop still sees its till listed, not just an empty table. On the main till this list is live — it refreshes itself every 10 seconds — and each joined till shows whether it is **Linked** right now or **Not linked**, whether it is an additional till, its version compared with the main till's, any update it is waiting for or that failed, how many sales it still has waiting to send, and whether its secure connection (TLS) is pinned. When a linked till runs an older version than the main till, its row has an **Update now** button: it asks that till to install the main till's version now, even if automatic updates are switched off. The till downloads and checks the update itself and installs it as soon as no sale is open on it — the row then reads **Update waits for a quiet moment** or **Downloading update**, and **Update failed** with a short reason if it didn't work (press **Update now** again to retry). A till that can't update itself — a portable Windows zip, Android, or an install it isn't allowed to change — reads **Needs the installer on that till** instead: install the new version on that till by hand. If the till is **Not linked**, Update now says so and nothing is sent. You can also rename a till from the cloud: renaming a till in the online shop manager (my.universaltill.com) or the cloud portal changes that till's own name — main or joined, and only that till — at its next check-in: within a few minutes while it is online, or as soon as it reconnects if it was offline. The other way round, a name changed in Settings → Tills & devices → This till on the main till reaches the cloud at its next check-in too. A name changed in Settings → Tills & devices → This till on a joined till renames that joined till only — never the main till — and reaches the cloud at its next check-in the same way. A name must stay unique in the shop, as at pairing: renaming a till to a name the main till or another joined till already uses (capital or small letters make no difference) is refused — in Settings → Tills & devices → This till the reason shows next to the Save button, and the cloud refuses it before sending anything to the till. A till's name must also be a single line of at most 60 characters: line breaks, tabs and hidden formatting characters are refused, and the name box on the setup and pairing screens stops at 60 characters — in Settings → Tills & devices → This till, on the setup and pairing screens the reason shows under the button (a name that is too long says so), and a rename from the cloud with such a name is not applied. Either way, the main till's **Other tills** section shows a joined till's new name within about half a minute while that till is **Linked**, and the joined tills' own lists follow at their next sync. In **Shop and sync**, **Network security key** is the key your tills recognise each other by on the shop network. If it may have been copied — a till was lost, or its data was copied to another device — press **Change key**: the linked tills receive the new key at once, and the main till starts using it at its next restart once every linked till has it, or at the first restart 14 days later. A till that was switched off meanwhile reconnects by itself, and selling is never interrupted.
10. On a **joined till**, **Other tills** shows the same shop-wide list too — the main till (labelled "the main till") and every other joined till, including itself (labelled "this till"). It's read-only there: only the main till can remove ("revoke") a joined till. The main till's row also shows its **Till ID**, so you can check which main till this one is linked to; it shows **—** until this till has synced with its main till, usually within seconds of joining. On **every** till — main or joined — **Other tills** also shows a **Cloud link** row for that till's own connection to the cloud — Connecting, Live, Periodic, Reconnecting, Paused or Stopped — each with a short explanation. Only the main till holds a live link; a joined till checks in on its own every few minutes, so it reads Periodic. Background check-ins only run while the shop is on a paid plan (see [Store registration & claiming](/help/claim)). **Paused: needs its own credential** means the till still uses the shop's shared cloud key; its own credential normally arrives with the next check-in; if this stays, contact support.
11. The small sync chip near the bottom of the left-hand nav shows this till's own name. It's a plain rail icon like every other menu button — its sync state does NOT change the button's colour; instead a small dot appears on the icon when something needs attention. A manager (anyone allowed to manage tills) can tap the chip to open Tills & devices; for everyone else it is only a status display. A single-till shop with nothing joined yet doesn't show a chip at all — there's nothing to sync yet. The Tills page on my.universaltill.com lists a till's problems only while they are current: "main till unreachable" stays until the main till answers again and then clears, another warning that hasn't come back for 24 hours drops off, and routine self-repairs (a joined till fixing its own cloud identity, tidying rows on its first sync) are not listed as problems at all. If the dot and the queued count stay while this till is connected to the main till, the main till is refusing a sale as too large: that sale and the sales after it stay safely on this till and are sent automatically once the main till accepts them (update the main till); the Tills page on my.universaltill.com names the receipt.
   - On a **joined till**, pointing at the chip shows **Connected to the main till** when all is well, or **Main till unreachable — sales are queued and will sync when it is back**; **Join the main till again** means this till has to be paired again. The label adds how many sales are queued. The dot appears when the main till is unreachable, sales are queued or the till has to join again.
   - On the **main till**, the label adds counts such as the number of tills, how many are offline, how many entries are quarantined and how many pairing requests are waiting. The dot appears only for quarantined entries or waiting pairing requests: a joined till that is merely offline shows in the count, with no dot.
   - If a joined till ever sends a sale the main till can't apply (an extremely rare edge case — two tills issuing a gift voucher with the same code offline, for example), that one sale is held for review rather than silently lost. The chip then opens **Quarantined sync entries**, which lists the till, receipt number, reason and time; you can also open it from Settings → Tills & devices → Shop and sync with **View quarantined entries**. This never blocks any other sale from syncing normally.
   - A gift voucher works shop-wide: sell it on any till, and it can be looked up and redeemed on any other — while both are online, the redeeming till reserves the amount on the main till in real time before completing the sale, so it's no longer refused just because it was sold somewhere else — and two tills can't both spend the same balance at the same moment: whichever reaches the main till second is refused, instead of the voucher going overdrawn. If a joined till loses its connection to the main till, redeeming a voucher it has never itself seen still isn't possible until the connection is back (same as any other main-till-dependent action); a voucher that till already knows about keeps working offline as before.
   - The dot for a waiting pairing request clears itself the moment the request is approved, denied or expires — no need to refresh.
12. Plugins follow the main till too: install, remove, enable or disable a plugin on the **main till** and every joined till applies the same change automatically within about half a minute. A plugin you switch off on the main till is switched off on every joined till too, and stays installed there with its settings. Each till downloads the plugin from the plugin store itself and verifies it before it runs — plugins are never copied from till to till. Trying to install, remove, enable, disable or update a plugin directly on a joined till is refused with a message pointing you to the main till. The one exception is a plugin imported from a file: importing still works on any till, including a joined one, but the plugin stays only on that till and does not spread.
13. Shop-wide settings are decided by the main till too. On a joined till, a change in **Settings** that applies to the whole shop — the preferred payment method, payment fees, when to ask dine-in or takeaway, the order-number scheme, the shop type, the Store card (currency, tax, language), the lock timeout, the self-order kiosk options, selling without stock tracking, the sale-screen browsing mode, a value in the all-settings list, the barcode types, the receipt design, the business details for invoices, confirming or unpairing the fiscal device, the time the business day starts for reports, report retention, the automatic-update schedule, restoring or hiding again a tile under Settings → Hidden menu tiles and similar — is sent to the main till first and saved there, so it reaches every till and is not undone by the next sync. If the main till can't be reached, the change is refused with a message saying so and nothing changes on this till: try again when the main till is back, or make the change on the main till. While the main till can't be reached, the joined till's Settings page already shows these shop-wide settings read-only, with that same message: you see the current values but can't change them there; settings that belong to this till alone stay editable. The all-settings list stays editable, but a shop-wide value changed there is refused the same way. The main till also checks that the person making the change is allowed to (with its own staff list), and refuses it otherwise. A shop-type change also switches each joined till's screen layout (the salon layout, for example) without a restart, shortly after the change reaches it — but never in the middle of a sale: a till with items in a basket keeps its layout until that sale is finished or cleared. Settings that belong to one till only — its printer, its screen and display mode, its own register — are still saved on that till alone. The shop's country can be changed on a joined till too: the main till saves it, and while the shop's fiscal device is confirmed only the owner may change it. The joined till's own fiscal status catches up at the next sync.

## Approving a pairing request

Do this on the **main till**, as a manager.

1. Open Settings → Tills & devices → Add a till. Under **Pending pairing requests**, each device that asked to join is a row, with its **Device** name and a **Verification code**.
2. Compare the **Verification code** with the one on the joining till's **Waiting for approval…** screen. If they differ, don't approve: it is not the device you expect. Deny it instead (steps 4 and 5).
3. If you want, change the **Role** in the row (additional till or satellite) before you approve.
4. Type your **Manager PIN** in the row's box. A wrong PIN shows **Incorrect manager PIN.**
5. Press **Approve**, or **Deny** to refuse the request.

A joining till that asks again (for example after its app was restarted) replaces its own earlier request, so each device shows as one row. While you are typing a PIN, or for a short while after you touched the box, the list does not refresh itself, so the row you are working on stays where it is.

The joining till then finishes joining. If you deny the request, the joining till is not told: it keeps showing **Waiting for approval…** until the request expires, 10 minutes after it was sent. It then shows **No response — the request may have been declined or it expired. Try again.** and can send a new request. The same message appears if nobody answers within 10 minutes.

## Using a phone as a card reader

Where your shop has turned this on, a manager can pair a phone as a card reader for the main till. The phone only takes card taps: it gets no sales, items, customers or settings. A card reader pairs only to the main till (or a single standalone till), over the secure connection, never by QR code or short code. Once paired, the main till's own sales and the sales of its additional tills can all be paid on it.

On the main till open **Tills**. Under **Phone card readers** a manager turns the feature on or off for this till: enter your **Manager PIN** and tap **Turn on** or **Turn off**. This is a test feature: it works only for shops that have been enabled for phone readers, and for any other shop nothing is charged. The card also shows **This till's ID**; if a phone cannot find the till by itself, type this ID and the till's address on the phone.

1. On the main till open **Tills**. Under **Card reader requests** a phone that asked to connect shows its name and a **Verification code**. The card says "Card reader: takes card taps only, gets no shop data", so you can tell it apart from a till.
2. Check that the code matches the one on the phone, enter your **Manager PIN** and tap **Approve**. Tap **Deny** if you do not recognise the phone. A denied phone shows **A manager turned down this request. Ask a manager, then try again.** and can send a new request. The card has no role choice: a request for a card reader can only be approved as a card reader.
3. Approved readers appear under **Card readers**. To rename one, change its name and save. To remove one, enter your **Manager PIN** and tap **Remove reader**: the phone stops taking payments at once and must be paired again to come back.

If the main till is not serving a secure connection, the section says card readers need HTTPS first. A cashier cannot see or change any of this.

Each reader in the list shows what the phone last told the till: **Ready**, **Busy**, **Needs setup**, **Unavailable**, or **Not connected** when the phone is not linked to the till right now.

Taking a payment on the phone: the cashier chooses the card tender and the phone reader. An additional till lists the main till's phones too, with their **Ready** or **Busy** state; the phone used last on that till is chosen first, and a phone that is busy cannot be chosen. A phone takes one payment at a time: if it is already taking one (for the main till, another till, or its own screen), the second request is refused, nothing is started and nothing is charged, and the till says the reader is busy; try again when it is free. An additional till can pay on a phone only while it is linked to the main till over the secure connection; otherwise no phone is offered and cash and other tenders carry on as usual. A refund is always made on the main till. The till shows "Waiting for the customer to tap" with a countdown and a **Cancel** button, then "The phone is ready for the card" once the phone has the amount on screen. The customer taps their card on the phone. The till does not take the phone's word for the result: it asks the payment service itself and only records the sale when the payment is confirmed for exactly the sale amount. If the phone loses its connection to the till mid-tap, the till shows "Payment not confirmed" and says the customer may have been charged. It is never shown as declined; use **Check again** (or ask a manager) to find out what really happened.

## Additional tills and satellites

Every joined till has a role. An additional till works offline and rings up sales like any other till; it is the default. A satellite is a kiosk or order station that needs the main till to work.

- When a till joins (in Add a till or on the first setup screen), choose **Additional till** or **Satellite** under **What should this device be?**, below the till's name. Additional till is already selected.
- On the main till, each pairing request in **Add a till** shows the role the till asked for in its Role column. A manager can change it there before pressing Approve; the till joins with the role chosen at approval.
- Later, **Other tills** on the main till shows every joined till's role in the Role column, and a manager can press **Change role** to switch it. You are asked to confirm first, because that till may be in use right now. The change is recorded in the audit log, and the till picks it up at its next sync, within about half a minute.
- A satellite can only use the Self-order kiosk device profile: choosing Register or Back office under Settings → Device profile is refused with a message saying so. To use it as a normal till again, change its role on the main till's **Other tills** section first. On an additional till, choosing Self-order kiosk first asks whether to make it a satellite; confirming changes its role on the main till as well, so the main till must be reachable (otherwise nothing changes and a message says so). Apart from this, a satellite does not behave differently from an additional till yet. The Self-order kiosk user's PIN and a setting sent from the cloud follow the same rules: they can't make an additional till a kiosk or turn a satellite into a Register or Back office — the change is refused and nothing changes.

## Registers

A **register** is a till/checkout station — the thing a shift is opened on and a sale is rung up against. A shop can have more than one: a front counter and a back counter, for instance, each taking sales at the same time.

- Open **Registers** from the menu (manager only) to see every register. Tap the **+** button above the list to create one — give it a name and, optionally, the stock location it draws from, in the popup that opens. Tap an existing register's row (or Tab to its name and press Enter) to reopen the same popup prefilled, where a manager can rename it, change its stock location, or deactivate it (deactivating keeps its sales/shift history — it just stops offering it for a new shift). Changing the stock location doesn't touch its past sales or shifts — those stay tied to the register itself. A register that already has shift/sale history shows a "Has shift/sale history" hint on this page — informational only, it never blocks deactivation.
- Registers are shop-wide and always managed from the **main till**: on a joined till, creating, renaming or deactivating one shows a message pointing you back to the main till, rather than accepting a change that would only apply locally.
- Joining a second till (see above) assigns it a register **automatically**: enrolment creates a new register on the main till, named after the joining till (if that name is already taken, a numeric suffix is added, e.g. "Till 2 (2)"), and the joined till arrives already set to it — no manual step, and it can open its own shift straight away. The manual path still exists when you want more: create further registers from **Registers** (a shop can have more registers than tills), rename one there, or change which register a till is on that till under **Settings → Tills & devices** → **Cash register for payouts**.
- A register keeps its till's name. The first register is named after the main till (or after the shop, if the till has no name yet), not a stock name. Renaming a till — on that till under **Settings**, or from my.universaltill.com — renames its register on the main till too, as soon as the main till hears about it. If another register already has that name, the register keeps its old one; rename it here. Inactive registers (for example one you deactivated after unpairing its till) are listed in their own group under the active ones, with their count.
- If this shop had a register or stock location created directly on a joined till from before it started keeping both shop-wide, the next sync from the main till removes it (if it has no shift/sale or stock history yet) or deactivates it (if it does) — the same "main till wins" rule above, just catching up on that one leftover row. If a joined till's own register goes stale because of this, pick a working one again under **Settings → Tills & devices** → **Cash register for payouts**.


## Making a phone an additional till of your Mac or PC

On the new device (for example your phone), open Tills → Add a till and choose **Make this device an additional till of my shop**. Your other till, for example the computer on the counter, stays the main till and nothing on it changes. If the phone already has sales of its own (for example from trying it out), the join stops with **One more step**: tick **Yes, make this device an additional till and replace what is on this device**, then press **Join as an additional till** again. That tick box is the step that makes the phone an additional till: it replaces what is on the phone with the shop's copy from the main till. The phone's own earlier sales are not sent to the main till; they are kept in a copy in the phone's backups folder.

## When a till says it needs a person

A till that lost its connection to the shop reconnects by itself and says so in the status bar. When it cannot, it says why in one line with one button: for a replaced till or when another till is the main till, the button is **Join as an additional till**, and it opens the join form with the right choice already selected. For the other reasons, see Store registration & claiming.

## When the main till was replaced

If the main till died, the shop's owner can replace it on my.universaltill.com (Tills, the main till, **Replace this till**) with a new device, or with a till that already works in the shop once it is promoted (Settings → Tills & devices → Shop and sync → **Promote this till**). The promoted till gets its own new Till ID; the other tills join it again and see that ID. The new main till numbers its receipts with its own prefix (for example M3f2a9c01-000000001), so they never repeat the old till's receipt or invoice numbers. The same happens when the owner removed the main till on my.universaltill.com and a new device then joins as **Main till (only if the shop has no till yet, or this device takes over from the main till)** with an ordinary code.

- **The old till**, if it is ever switched on again, shows **Replaced by …** in the status bar and, in Settings → Tills & devices → This till, a banner with one button, **Join as an additional till**. It can still ring up sales, but they reach neither the cloud nor the main till: use the new main till instead. It no longer shows up as a main till on the shop network, shows no pairing code, and refuses the other tills' sales, so those stay on the tills that rang them.
- **The other tills** join the new main till: on each, open **Settings → Tills & devices → Add a till** and use **Join an existing shop** with a code from the new main till, as in step 3 of "How to use it". Before joining, close the day on that till and print the Z report. Make product, price and staff changes on the new main till: changes sent to the old one are lost when the tills join the new one.

## When a joined till was restored onto a new device

If a joined till's data is restored from a phone or iCloud backup, comes along in a phone-to-phone transfer that brings the till's data, or is copied onto another device, that device stops using the old till's connection to the main till, so two devices never sync as one till. It keeps selling, and the status bar shows **Join the main till again**. On the main till, create a join code; on the restored device, use **Join an existing shop** in Add a till and give it a new name. Its sales that have not reached the main till are sent first, under their own receipt numbers; after joining it numbers receipts as a new till. Don't revoke the till it was restored from if that till is still in use.

## When a joined till can't reach the main till

1. On a joined till, the status bar at the bottom of every screen — the sale screen included — has one light for the main till, and it always says in words what it means: **Main till linked** (green dot) means a live link: changes on the main till arrive within a second. **Main till: polling** (hollow dot) means there is no live link — usually the main till runs an older version — so changes still arrive, within about 30 seconds. **Main till not reachable since … — selling offline** (amber) means the main till has gone quiet: it appears within about 15 seconds of the link dropping — also when the main till was closed or restarted and hasn't come back by then — and after about a minute and a half when there was no live link. The joined till keeps selling either way — its sales wait on the joined till and sync as soon as the main till is back. When the versions differ, the linked light adds **Updating to v… soon** or **Update to v… needed** (this till is older than the main till; the version number follows) or **Waiting for the main till to update** (this till is newer). If plugin updates are waiting, the amber chip says so too: on a joined till, plugins follow the main till, so they can only be updated once it is reachable again. The browser's own **Online** light is not shown next to it on a joined till — it only knew that a network cable or Wi-Fi was connected — and appears as **No internet** only when the network is really down. Tap the main-till light to open Tills & devices, which explains the same state and shows, on the main till's row, when this till last reached it.
2. Usually nothing needs doing. If the main till only came back on a different address (for example, it restarted and got a new network address or port), the joined till finds it again by itself: every few minutes it looks for the main till on the shop network, and it reconnects only to the same main till it was paired with — that till has to prove it holds this till's pairing, so another device on the network can't take its place. If the shop network keeps the tills from seeing each other (some Wi-Fi networks do), the joined till also asks the shop's cloud account where the main till last said it was — the same proof applies, so a wrong answer changes nothing. This needs both tills connected to the cloud; without it, only the shop network is searched. The pairing is kept, nothing is copied again, and the light turns back to **Main till linked** (or **polling**) with the next successful contact.
3. A restarted main till normally comes back on the same port, so this should be rare — although the router can still give it a new network address, which the search in step 2 handles. If the chip stays, check that the main till is switched on and connected to the same network as this till.
4. Join again only if the main till was reinstalled or replaced. Joining copies the whole shop from the main till again and replaces what is on this till. Sales, no-sale opens and cleared baskets that have not reached a main till yet (the sync chip in the side rail shows a count of queued sales) are sent to the new main till first, under their own receipt numbers, and once more when the till restarts to finish the join; if they cannot be sent, the join stops and nothing on this till changes — back it up (Settings → Backups → Back up now) and try again. In cloud or both report retention, the join also waits until the cloud has every day close of this till. Then revoke this till on the main till's **Other tills** section, and on this till use **Join an existing shop** on the Tills page, as in step 3 of "How to use it".

## Removing a till

Remove ("revoke") a joined till when it was sold, broken or lost, or before you join it to the shop again.

1. If the till still works, let its queued sales reach the main till first, and close the day on it if you need its Z report.
2. On the **main till**, open Settings → Tills & devices → Other tills, find the till in the list and press **Revoke** on its row. A joined till can't revoke anything: the button is only on the main till, and only for a manager.
3. Confirm the question **Revoke this till? It will stop syncing until paired again.** by pressing **Revoke**.

The till leaves the list at once and its link to the main till is cut. The removal is recorded in the audit log. The revoked till is no longer connected to the main till: it can keep selling offline, but its sales that were not yet sent stay on it and don't reach the main till. Its own screen may keep showing it as connected (for example **Main till: polling**), so don't rely on it: check in the main till's **Other tills** section that the till is gone from the list. Its register is not removed: deactivate it under **Registers** if you no longer need it. To connect that device to the shop again, pair it again with a new pairing code (step 3 of "How to use it").

## A copy of every sale on every till

The main till can keep a **read-only copy of every sale and day close** of the shop on each additional till, so that any additional till can take over as the main till with nothing lost. It is **off** until a manager turns it on.

1. On the **main till**, go to Settings → Tills & devices. The card **Copy of every sale on each till** shows whether it is on. Press **Turn copying on** (or **Turn copying off**). Turning it off keeps the copies already made; turning it on again makes every additional till fetch its copy afresh.
2. While it is on, the card lists each additional till: **up to date**, **not copied yet**, or how many changes it still has to fetch. A till that was switched off or offline catches up by itself when it is back.
3. On an **additional till**, the same card shows the state of its own copy, how many sales it holds and since which day. Copies are kept for 400 days, and less if the disk is nearly full: below the low-disk limit the copy pauses and keeps only the last 31 days. Selling is never affected.
4. A copied sale is only a copy: it never counts in that till's totals, Z report, stock or receipt numbers, and it is never sent back. Satellites keep no copy.
5. The tills need a secure link to each other for this. If the card says **Needs a secure link**, pair that till again.
