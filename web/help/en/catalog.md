# Catalog, variants & barcodes

Your products: names, prices, departments, item variants (size, flavour…) and any number of barcodes per item or per variant. Managers and admins only: a cashier doesn't see Items in the menu at all, and creating, editing, deactivating or reorganising anything here — an item, a variant, a modifier group, an option set or a barcode — needs that same access, whichever screen the change is made from.

Open **Items** from the menu to get here — on a tablet-width screen or wider it opens as a two-pane screen: a compact list of sections (Catalog, Categories, Inventory, Modifiers, Option sets) down the left, and the selected section's own screen on the right, so switching between them never leaves the page. Catalog is selected by default. On a phone-width screen the two panes stack, and tapping a section opens its own full screen instead, the same as before. Each section is still its own page with its own address — /catalog, /categories, /inventory, /modifiers and /catalog/option-sets all work exactly as before if you go to one directly or bookmark it.

## How to use it

1. Open Catalog and tap the **+** button (Add item) to create a new item, or click an existing item's card to edit it — either opens a full-screen editor. Its top bar stays in place while you scroll: the item's name, **Save Changes**/**Create Item**, **Close**, **+ New** (start another item straight away) and — for an existing item — a small bin icon that removes the item from the catalog (it asks first; the item's sales history is kept, and its row can still come back if you save the item's own edit screen again before navigating away). On a narrower screen, Save Changes/Create Item and Close collapse to just their icon (a tick and a cross) to leave more room for the form below. Below the bar, tabs group everything about the item: **Details** (name, price, department, tax, tile colour and so on), **Variants** (sizes/flavours, barcodes, cost price, lead time and customisation options), **Item image**, **Print labels** and **Map a physical keypad**. A brand-new item has to be saved once before the Variants, image, labels and keypad tabs can be used — each tab says so until then. Items with a SAMPLE badge came from the optional starter catalogue (removable from Settings → Data).
   - **Item image:** open the **Item image** tab inside the editor to add or replace the item's own photo. Tap **Take a Photo** to open a live camera preview right on the page and capture a still without leaving it (falls back to your device's own camera app if a live preview isn't available), or **Choose File** to pick an existing image instead. Photos are resized automatically when they're stored, so there's no need to shrink one yourself first — but an extremely high-resolution photo (over about 6 megapixels, roughly 2800×2100 or larger) is too large to accept; resize or crop it to a smaller resolution and try again.
   - **No photo handy? Choose a built-in image instead.** The same **Item image** tab offers a small grid of built-in images (coffee, drink, sandwich, pastry, and a plain fallback) below the upload buttons — tap one to use it right away, no photo needed. The tile matching the item's name or department is highlighted with a dashed outline as a suggestion when the item has no image yet; tapping any tile (the suggested one or another) assigns it. Choosing a built-in image replaces any existing photo, and uploading a real photo later replaces a built-in image the same way — an item only ever shows one or the other. Tap **No image** to clear it back to blank. It shows on the sale screen, basket, search results and the Catalog list below the same as an uploaded photo, and the self-order screen shows a blank tile rather than the built-in image (it does not read this choice yet).
   - **Tile colour:** pick one of the small set of colours in the editor (near the department/brand fields) to give an item with no photo a solid coloured tile on both the sale screen and the Catalog list itself — a quick way to tell products apart before you've added real photos. It's a fixed palette, not a custom colour picker. Adding a photo later always wins — the tile shows the photo, not the colour — and picking **No colour** clears it back to plain.
2. On the **Variants** tab, edit variant names, SKUs, prices, cost prices and photos right in the grid; add or remove barcodes as chips; print labels per variant from the **Print labels** tab — see [Receipts & printing](/help/printing) for what that tab needs (a barcode or SKU on the item/variant, and a working printer) and what to do if nothing comes out. A variant with neither a barcode nor a SKU shows a "won't sell" flag right in the grid (this flag only appears for active variants), since a code is what the sale screen and self-order picker resolve it by — add either one to clear the flag and make the variant sellable.
   - **Plain code (ignore weight/price):** tick this when adding a barcode only if your shop uses weight- or price-embedded scale labels *and* you are entering an ordinary product barcode that happens to start with the same digits. It tells the till to store the code exactly as typed instead of reading part of it as a weight or price. Leave it unticked for everything else — it has no effect on a normal barcode.
3. Use Import to load items from a CSV file (a Loyverse, Square or SumUp catalog export is detected automatically) **or an Excel (`.xlsx`) workbook**, and Export to save your catalog — a speedy kasse / pepperm cashbox `.bkp` till backup is also accepted directly, detected automatically with no conversion needed. All three can also carry a `Tax rate` column (and a `Takeaway tax` column where it differs) — Universal Till creates the matching tax codes for you automatically.
   - **Excel workbooks:** only the first worksheet is read — the Preview tells you which one, so a workbook with several sheets never leaves you guessing. Prices and tax rates in German-formatted cells (decimal comma, e.g. `1.234,56`) are read correctly. A workbook is only rejected for merged cells when a merge sits in the header row or a column actually being imported — a decorative merge outside those columns (a logo cell to one side), or one on a trailing note or totals row that isn't itself a readable item, doesn't block the import; when it is rejected, the message asks you to remove the merges or export as CSV instead; a legacy `.xls` file (not `.xlsx`) isn't supported — save it as `.xlsx` or CSV first.
   - **Press Preview or Import once and wait.** A large file (hundreds of items, or a `.bkp` with lots of photos) can take a moment — an "Importing…" status appears and the button is disabled until the response comes back, so there's no need, and no benefit, to pressing it again. If you do somehow trigger it twice at once (a second device, a very fast double-tap), the second attempt is simply told the import is already running, or that the preview needs refreshing, rather than starting a second copy.
   - **Fixing problem rows before import:** the Preview lists every row that would be skipped and why. A row skipped only because its name is missing, its price could not be read, or both, can be fixed right there: tick *Import anyway* on that row and type the corrected name and/or price — a row missing both shows both fields, and both must be filled in before that row will import — then press Import: the corrections are applied and the row imports with the rest. All other skipped rows (for example a barcode or SKU that already exists in your catalog — or, for an item with neither, a name and category that already match one in your catalog) always stay skipped — that is what keeps importing twice safe. If you genuinely sell two different items that happen to share both a name and a category, give the second one its own barcode, SKU or category so it isn't mistaken for the same item.
   - **A `.bkp` till backup that reuses one item number across several different products** (common on older tills) no longer loses the extra items: the first one keeps the original number and every later one imports under a new, generated number instead of being dropped — the import summary tells you which rows this happened to, so you can give them a tidier number later if you want. This also covers a row you fix yourself in the problem grid above, once it shares its item number with a product elsewhere in the file that already imports cleanly: it too imports under its own generated number rather than being stuck. The only rows that still can't be rescued are two or more problem rows sharing a number that no already-importable row uses — the first one you correct takes the number and the rest stay skipped, because there's nothing to say which of them the number really belongs to.
   - **A source with no barcodes at all** — many `.bkp` till backups, and a CSV with no barcode column — shows a checkbox on the Preview: tick it and every item gets its own item number as its barcode; leave it unticked (the default) to import exactly as before, item numbers only. An item number reused by more than one item is left without a barcode either way, so no two different items ever share one.
   - **Already imported without barcodes?** The Catalog page's barcode-scan icon button (Backfill barcodes from SKU) is for exactly this — no need to re-import. It previews which items would get a barcode (and which can't, or already clash with one on another item) before anything is changed; confirm to apply it. Settings → Catalog import defaults has a matching toggle to have the import checkbox above start ticked by default for every future import — you still confirm or clear it on each one, this only changes where it starts.
   - On a long file the Preview list can run to hundreds of rows — an Import button is repeated at the bottom of the list so you don't have to scroll back to the top to continue. Once you press it, a green "Imported ✓" summary with a View catalog button confirms the import actually happened. From the Catalog page's own Import icon, it opens as a window over Catalog — pressing View catalog closes that window and refreshes the list behind it so your new items are there right away; if you went to /import directly or by bookmark instead, pressing it takes you to Catalog as its own page.
   - **A `.bkp` till backup that carries a product photo brings the real photo across** — it shows on the sale screen, basket and search results straight after import, the same as one you add by hand. If a referenced photo can't be found in the backup, that item is imported without it (never blocked) and the summary tells you which items this happened to.
   - **Items with no photo in the source file** get a generic icon automatically (a coffee cup, a pastry, a sandwich, a drink, or a plain fallback), picked from the item's name and category, so the sale screen, basket, search results and the Catalog list below all show something recognisable rather than a blank tile. Add a real photo any time from the catalog grid (step 2 above) to replace the icon everywhere at once.
4. A takeaway tax rate needs the German tax plugin enabled to save its override — if it's installed but switched off, the import still creates correct tax codes but the summary warns that the takeaway override wasn't applied; enable the plugin and re-run the import to fix it.
5. The first time you import priced items on a till whose currency you've never explicitly set, Import stops before writing anything and asks you to confirm which currency the file's prices are in — a fresh till defaults to GBP, so importing a foreign catalogue without checking this could otherwise price everything under the wrong currency. Confirm the currency shown if it's right, or pick the correct one; either way Import proceeds automatically and won't ask again once your till's currency has been set.
6. Which barcode types a scan or manual entry accepts is controlled per shop from Settings → Barcode types. Every common retail type (EAN-13, EAN-8, UPC-A, UPC-E, GTIN-14, Code 128, Code 39, internal/PLU codes) is on by default, so existing barcodes keep working exactly as before. The two scale-label types (weight-embedded and price-embedded EAN-13) are off by default — turn one on only once you're ready to use scale-printed labels, since it changes how a matching code is read.
7. To arrange which items appear as quick-sale buttons on the sale screen, use **Quick Buttons**.

## Good to know

- **Option sets** generate an item's variants for you: define a reusable list of values once (Size: S / M / L) via **Option sets** in the Items left rail, then in the item's editor panel tick up to two sets above the variants grid and press **Generate variants**. Each combination becomes an ordinary variant with its own SKU; running it again only adds combinations that are still missing. See the Option sets topic for the full walkthrough.
- **Modifiers** (modifier groups like "Toppings" or "Size") are defined once, in exactly one place: **Modifiers** in the Items left rail — a shop-wide screen with one card per group. Create a group there with just its name and rules (no item needed), add its options, then tick the **categories** it applies to and add the **items** that should offer it directly, all from the group's own card. A group not yet assigned to any category or item is kept, but isn't offered at checkout until it is. **Delete group** removes it everywhere (past sales keep the modifiers they recorded); unticking **Active** takes it off sale without deleting it. When cleaning up items (or groups) has left several unassigned, a count shows at the top of the screen with a **Show only unassigned** checkbox to filter down to just those, and a **Delete all unassigned groups** button to clear all of them in one confirmed action instead of one at a time. An item's own detail panel only shows a short summary of its group names, plus a **Manage Modifiers** button.
- That button opens a small window scoped to just this item, for **choosing which existing groups apply here** — not for creating or editing them. Tick any number of groups in the list and press **Attach existing group** to link them all to this item in one go (a group can be **shared across items** this way instead of recreated for each one). **Remove from this item** takes an already-linked group off just this one item, without deleting the group or affecting any other item using it — a group left with no item simply waits, unassigned, on the Modifiers screen. To rename a group, change its required/min/max settings, add/edit its options, or assign it to categories, go to **Modifiers** in the left rail — that's the only screen for it.
- **Inherited from the category:** groups linked to the item's category (set on the Categories page) are offered automatically, listed on the Variants tab as *from category* and shown in the same "Manage Modifiers" window under **From this item's category**. Tap **Skip for this item** to leave one out for just this item (the category keeps it; **Use again** brings it back) — skipping never removes a group the item is also attached to directly. The Variants tab's **Kitchen printer routing** section shows which stations the category sends the item to and lets you tick the item's own stations to override that for this item only (untick them all to follow the category again); an item's own stations always win outright over its category's.
- An item's own details (name, price, cost, lead time), its variants, its barcodes, and its Modifiers (modifier groups like "Toppings" or "Size", and their options like "Extra cheese") are all shop-wide and always managed from the **main till**: on a joined till, creating or editing any of these shows a message pointing you back to the main till, rather than accepting a change that would only apply locally.
- Importing a catalog is also shop-wide (it creates items, barcodes, categories and tax codes) and is only done from the **main till**: pressing Import on a joined till shows a message pointing you back to the main till instead of importing locally. Preview still works everywhere, since it doesn't save anything.
- **Filter by category:** tap the filter icon beside the search box to open the category list, then tap a category to narrow the list to items in it — tapping a category that has sub-categories includes their items too. It combines with the search box (both narrow the list together); tap **All categories** to clear it.
- **Clearing out old, removed items for good:** deleting an item (above) only deactivates it — it disappears from the sale screen and Quick Buttons immediately, but the record itself isn't gone: it can still come back (reopen and save the item's own edit screen before navigating away, step 1 above) and its sales history is kept. To permanently clear out items that are inactive, were never sold and have no stock history (anything ever sold, or currently sitting in a parked sale, is always kept, for your records), use **Settings → Data → Catalog cleanup**: Preview shows what would go before you remove anything (capped to the first 200 for a very long list — Remove itself always clears every matching item, not just the ones shown), and removing needs a manager PIN. Tick **Also include active products that were never sold** to widen this to items you haven't deactivated yet — useful for wiping a wrongly imported catalog clean before the shop goes live. The cleanup refuses while a product it would remove is still in the sale screen's basket (or the self-order kiosk's) — clear that basket first. A modifier group is never deleted by removing items — one left attached to nothing is kept, unassigned, on the **Modifiers** screen; delete it from there (one at a time, or all unassigned ones together) if you don't want it any more. See [Languages & display](/help/display) for the rest of the Settings → Data tools.
